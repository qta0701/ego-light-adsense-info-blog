## 원인 재현

1. 기존 글의 CTA td는 투명 배경, 글자 검정이었으며 H2 다음 일반 문장에 실제 b 태그가 있었다. span 계산 굵기만 보면 400이어도 내부 b는 700이므로 텍스트 노드 부모까지 검사해야 한다.
2. 같은 원고를 변환기에 넣었을 때 실제 URL을 유지하면 CTA가 `#fff8b2 / #1b1bf8 / 19px / bold`였다. URL을 미리 NAVEROG 표식으로 바꾼 원고는 동일 CTA가 `transparent / #000000`으로 나왔다. 네이버 색상 제거가 아니라 **변환 전 URL 치환으로 CTA 판정 조건을 없앤 것**이 주원인이었다.
3. 일반 본문에 400 span을 넣고 기존 분할 append + Ctrl+B를 사용해도 이미지 뒤 문장이 b로 저장됐다. 굵기 버튼 직접 해제와 상태 대기 후에는 개선됐지만, 이후 한 조각이 이미지 캡션으로 들어갔다. 캡션에서 본문으로 포커스가 이동했다고 추정한 것이 추가 결함이었다.
4. 최종 방식은 **실제 URL을 유지해 변환 → 텍스트 계산 스타일 명시 → 변환 뒤 표식 분리 → 전체 본문 1회 리치 붙여넣기 → 유일한 표식 문단 선택 → 이미지/OG 교체**다. 분할 append를 기본 경로에서 제외하자 두 새 원고와 기존 수정 글에서 일반 본문 굵기·누락 검사 모두 통과했다.
