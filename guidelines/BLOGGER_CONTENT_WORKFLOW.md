# HTML 콘텐츠 작성·Blogger 업로드 운영 가이드

2026-11-07. 기존 `웹자료수집.md` 6.4.1의 콘텐츠 작성·업로드 인계 기준을 이 파일로 분리했다. **A: 키워드마다 실제 독립 채팅**, **B: ego-browser Space 최대 3개 병렬**은 서로 다른 실행 방식이다. 수집은 [웹자료수집.md](웹자료수집.md), 글의 내용과 이미지 계약은 [html-content-guide.md](../블로그작성_가이드라인/html-content-guide.md), HTML 표현은 [html-style-guide.md](../블로그작성_가이드라인/html-style-guide.md), 복사용 요청문은 [blogger-content-request-prompt.md](../블로그작성_가이드라인/blogger-content-request-prompt.md)를 따른다. 실행·중복 방지·시트 상태는 이 문서를 우선한다.

## 1. 공통 대상과 인계 자료

- 시작 전에 현재 프로젝트 `guidelines/`의 `.md` 파일 존재를 확인한다. 없으면 경로 오류로 중단한다. `.antigravity/rules.md`, [Chrome 통합 가이드](CHROME_AGENTS_USAGE_GUIDE.md), [크롬 활용법](크롬에이전트_활용법.md), [데스크톱 가이드](AGENT_DESKTOP_GUIDE.md)를 먼저 읽는다.
- 대상 시트: [애드센스 콘텐츠표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit). `gid=2121839224`는 현재 앱사용 탭이며 모든 작업을 이 탭으로 고정한다는 뜻이 아니다. **사용자가 지정한 탭·실제 행 번호**와 메인 키워드를 확인한다. `No.` 열의 번호를 시트 행 번호로 대체하지 않는다.
- 각 작업은 `spreadsheetId + sheetId + 탭 + 행 + 메인 키워드 + 프로젝트 상대 키워드 폴더`로 식별한다. 탭명에 밑줄이 있을 수 있으므로 폴더를 첫 밑줄로 나누어 탭·키워드를 추측하지 않는다. A에서 행이 생략되면 같은 폴더의 `research.json`/manifest 또는 지정 탭의 키워드 검색으로 유일한 행을 확인한다. 여러 행이 일치하면 임의 쓰기하지 않는다.
- 입력은 `YY_MMDD/{탭}_{키워드}/웹조사/publish/*_웹조사결과.md`와 발행 이미지다. 없으면 동일 키워드 상위 `웹조사/`의 구형 Markdown·이미지를 확인한다. Markdown의 상대경로를 우선하고 `index.json`에 모든 이미지 메타데이터가 있다고 가정하지 않는다.
- 이미지별 원본·발행 파일명, 역할, 화면 종류, 단계·표식 번호 의미, 권장 순서, 설명·alt·캡션, 출처·실제 화면/원본 URL·확인일, 가림·재사용 조건·확인 한계를 인계한다. 검색 화면은 검색 URL과 실제 연 공식 URL을 구분한다. 원본·변환본·가림본은 같은 자료일 수 있다.
- 파일번호·이미지 내부 표식 번호·본문 절차 번호를 구분한다. 원래 파일명을 보존하고 `IMG_01` 같은 슬롯 ID로 HTML과 TXT의 파일·앞뒤 문단·소제목·URL을 연결한다. 수집에 사용한 이미지를 모두 본문에 삽입할 필요는 없다.
- 기본 출력은 `웹조사/publish/{탭}_{키워드}_html콘텐츠.html`과 `{탭}_{키워드}_제목메타디스크립션.txt`다. UTF-8로 저장하고 원본 조사 Markdown·이미지·수집 index/검증 기록은 보존한다.

## 2. 시트 열과 기록 원칙

2026-11-07 앱사용 탭의 헤더를 읽어 아래 위치를 확인했다. **실행 시 metadata와 헤더를 다시 읽고 헤더명으로 찾는다.** 줄바꿈·공백 차이는 정규화할 수 있지만 유사한 제목을 임의 매칭하지 않는다. 헤더 누락·중복은 확인 후 진행한다.

| 목적 | 실제 헤더명 | 현재 참고 열 | 쓰는 시점과 값 |
|---|---|---|---|
| 콘텐츠 작성 완료 | 애드센스 블로그 작성여부 | D | HTML/TXT 두 파일 생성·검수 완료 후 `ㅇ` |
| 초안 저장 확인 | 애드센스 임시저장 여부 | G | Blogger에 실제 초안이 저장됐음을 확인한 직후 `ㅇ`; 발행 후에도 유지 |
| 공개 글 주소 | 애드센스 포스팅 링크 | H | 실제 공개 발행을 확인한 게시글 URL |
| 행 식별 | 메인 키워드 | I | 읽기·대조만 수행 |
| 발행 시각 | 애드센스 포스팅 작성일 | L | H를 기록할 때 함께 실제 발행 시각을 날짜·시간 값으로 기록 |

- `ㅇ`는 한글 자음이다. 영문 `o`, 숫자 `0`, 불리언 체크박스로 바꾸지 않는다. 현재 행의 데이터 유효성 검사·수식·사용자 입력값도 확인한다. 화면상 공란인 수식, 공백 문자, FALSE, 0은 비어 있는 셀로 취급하지 않는다.
- 쓰기 직전에 **같은 행의 키워드와 대상 셀**을 다시 읽는다. 일치하는 완료값은 보존하고, 다른 값·다른 URL·수식이 있으면 덮어쓰지 않는다. 필요한 빈 셀만 정확히 수정하고 저장 후 재조회한다. 다른 열·전체 행·서식·시트 시간대를 변경하지 않는다.
- 시트 쓰기는 **한 조정자**가 담당한다. A의 독립 채팅/B의 Space 작업자는 완료 근거를 조정자에게 전달한다. 조정자는 중복되지 않는 행별로 결과를 반영한다. 로컬 잠금은 이 프로젝트 안의 동시 실행만 조정하며 외부 사용자·다른 PC와의 원자적 비교/쓰기 기능은 아니다. 따라서 live 재조회가 필요하다.
- H와 L은 같은 `batchUpdate` 요청 묶음에 포함한다. G가 비어 있으면 확인된 저장/발행 근거로 같은 묶음에서 보완할 수 있다. 이미 같은 H가 있으면 재발행하지 않고 기존 글 확인 후 누락 G/L만 복구한다. 다른 H면 충돌로 보고한다.
- 날짜는 문자열 `2026. 10. 18 오후 9:42:47`을 그대로 쓰는 대신 **한국 시각의 날짜 일련값 + DATE_TIME 표시 형식**으로 쓴다. 기본 패턴은 `yyyy. m. d AM/PM h:mm:ss`; 한국어 locale에서 요청한 오전/오후 표시인지 `formattedValue`로 확인한다. 현재 시트의 timezone은 `America/Los_Angeles`, locale은 `ko_KR`이었으므로 전체 설정을 바꾸지 않고 KST 벽시각으로 변환한 값을 넣는다.
- 발행 시각은 Blogger에서 확인한 실제 발행 시간 또는 이번 실행에서 실제 발행 완료를 관찰한 시각을 사용하고 근거를 기록한다. 재시도 시 현재 시각으로 바꾸지 않는다. 기존 글의 시각을 확인할 수 없으면 임의로 만들지 말고 보완 항목으로 남긴다. 예약 발행은 실제 공개되기 전까지 H/L 완료로 처리하지 않는다.
- 시트 업데이트 실패는 글 생성/발행 실패와 구분한다. 로컬 파일·실제 글 ID·URL·원래 발행 시각을 보존하고 **시트 반영만 재시도**한다. A/C의 수집 완료 표시는 D/G/H/L 작업을 대신하지 않는다.

## 3. A — 중복 검사 후 키워드별 독립 채팅

### 3.1 생성 전 중복 판정

`YY_MMDD/{탭}_{키워드}/` **전체 하위 경로**에서 정확한 두 결과물 파일명을 찾는다. 루트, `웹조사/`, `웹조사/publish/`, 구형 `outputs/` 등을 포함한다. 단지 기본 출력 위치에 없다는 이유로 새 파일을 만들지 않는다.

| 발견 상태 | 처리 |
|---|---|
| 두 파일 모두 없음 | 신규 생성 후보 |
| 같은 폴더에 정상 크기의 두 파일 각 1개 | 생성 건너뛰기; 경로와 상태 보고 |
| 한 파일만 있음, 빈 파일, 서로 다른 위치의 쌍 | 부분 결과 검토; 자동 재생성·덮어쓰기 금지 |
| 동일 파일명이 여러 곳에 존재 | 중복본 검토; 임의 선택·삭제·새 생성 금지 |

파일 존재만으로 내용 검수가 완료됐다고 판단하지 않는다. 기존 두 파일의 D만 누락됐다면 재생성 없이 실제 내용을 검수한 후 시트 반영을 복구할 수 있다. 부분 파일의 복구는 기존 작업 기록과 사용자 요청 범위를 확인해 누락 부분만 처리하며 기본 신규 생성 흐름에 섞지 않는다. 신규 생성은 D 상태도 대조한다. D가 `ㅇ`인데 파일이 없다면 유실/다른 경로 여부를 확인하고 즉시 재생성하지 않는다.

### 3.2 독립 채팅 배정·시작 장벽

1. 조정자가 대상 목록, 실제 행, 파일 상태와 시트 헤더를 확인해 **실제로 신규 생성할 n개 키워드**를 확정한다. 이미 존재하거나 부분 결과인 대상은 별도 보고하며 n에서 제외한다.
2. 같은 프로젝트에서 키워드별 **사용자에게 보이는 실제 독립 채팅 n개**를 만든다. Codex에서는 현재 제공되는 `list_projects`/`create_thread`/`wait_threads` 등을 사용한다. 하위 에이전트나 여러 Space를 독립 채팅이라고 부르지 않는다. 단일 키워드도 생성 대상이면 해당 키워드 채팅 1개를 배정한다. worktree는 별도 요청이 없으면 만들지 않는다.
3. 생성 전에 `YY_MMDD/_blogger_runs/{runId}/dispatch.json`을 `pending`으로 저장한다. 모든 최초 프롬프트에 배정 키워드·폴더·시트 행, 원래 조건, 이 가이드, 조정자와 dispatch 경로를 전달하고 **ready 전에는 사전 점검만** 하도록 한다. 모든 채팅 ID/준비 상태가 확인되면 `ready`, 생성 실패/병렬 불가이면 `blocked`로 남긴다. 일부만 몰래 실행하거나 한 채팅 순차 처리로 대체하지 않는다.
4. 조정자가 행·폴더 잠금을 확보한 뒤 각 채팅에 소유권을 배정한다. 작업자는 시작 직전에 결과물 부재를 재확인한다. 같은 키워드·행에 두 채팅을 배정하지 않는다. 공유 가이드·시트·dispatch 갱신은 조정자만 담당한다.
5. 각 채팅은 지정된 한 키워드의 자료만 사용해 글을 작성한다. 이미지별 HTML 슬롯·TXT 위치 매핑·파일 존재·사실·시각 검수를 마친 후 경로와 검수 기록을 전달한다. 원본 이미지나 조사 내용을 덮어쓰지 않는다.
6. 조정자가 실제 완료를 기다린 뒤 두 결과물과 행 키워드를 재확인하고 **D에 해당하는 헤더 열의 빈 셀에 `ㅇ`**를 기록·재조회한다. 파일 작성 완료와 시트 반영 완료를 따로 기록한다. 실패 시 완료한 파일을 보존하며 다시 새 채팅을 만들어 재생성하지 않는다.

TXT의 작업 정보에 `spreadsheetId, sheetId, 탭, 실제 행 번호, 메인 키워드, runId/threadId, D 반영 상태`를 추가한다. 기존 이미지 매핑 상세는 콘텐츠 가이드 0.6절을 유지한다.

## 4. B — ego-browser Space 3개 병렬 업로드

### 4.1 입력과 신규 발행 차단

사용자가 업로드할 **시트 탭과 실제 행 번호**, 대상 Blogger 블로그, 초안 저장/공개 발행 범위를 제공한다. 행 키워드로 정확한 로컬 결과물 쌍을 확인하고 대상이 유일하지 않으면 먼저 식별한다.

| live 시트 상태 | 신규 작업 처리 |
|---|---|
| G 공란, H 공란, L 공란 | 신규 업로드 후보. 로컬 기록과 Blogger의 기존 글도 조회 |
| G 값 있음, H 공란 | 이미 초안이 있을 수 있으므로 신규 생성 금지. 기존 글 ID를 확인하고 명시적 재개 요청일 때 그 글만 재개 |
| H 값 있음 (G와 무관) | 신규 생성·재발행 건너뛰기. 필요한 경우 그 URL의 실제 글 확인 후 누락 시트 정보만 복구 |
| G/H 공란인데 L 값 있음 | 상태 불일치 검토. 확인 전 신규 생성 금지 |

G가 `ㅇ` 이외의 값이어도 비어 있지 않으면 차단한다. H가 단순 텍스트·수식이어도 값이 있으면 차단한다. **G/H 공란만으로 기존 글이 없다고 단정하지 않는다.** 직전 실행이 Blogger 저장 후 시트 쓰기에 실패했을 수 있으므로 `blogger-state.json`의 blogId/postId/editorUrl/게시 URL과 해당 블로그의 기존 글을 대조한다. 모호하면 신규 생성하지 않는다.

### 4.2 Space 실행과 저장/발행

1. 설치된 `ego-browser` 스킬을 끝까지 읽고 **ego-browser로 업로드**한다. 시트 읽기·쓰기는 연결된 Google Drive/Sheets 도구를 사용한다. B의 브라우저를 다른 브라우저/Raw CDP로 임의 대체하지 않는다.
2. 조정자가 작업 행 잠금을 확보하고 `키워드/행 → blogId/postId → spaceId → 폴더`를 기록한다. 동시 활성 Space는 **최대 3개**, 키워드 하나당 고유 Space 하나다. 작업이 3개 이상이면 세 개씩 병렬로 처리하고 슬롯이 비면 다음 대상을 시작한다. 1~2개면 그 수만큼만 만든다. 채팅을 세 개 만드는 지시가 아니다.
3. 단일 글 안의 이미지 업로드 → URL 매핑 → 본문 적용 → 저장/발행은 순차 처리한다. 서로 다른 Space 작업만 병렬로 진행한다. 뷰포트 변경·캡처·네이티브 파일창 등 공유 자원 구간은 직렬화한다. 인증/사용자 제어로 대기하는 Space도 활성 슬롯에 포함하고 네 번째 Space를 만들지 않는다. 같은 Space/글 ID로 재개한다.
4. 새 글을 만들기 직전에 G/H와 키워드를 다시 읽는다. 값이 생겼으면 해당 신규 작업을 취소하고 기존 상태를 확인한다. Blogger에서 글 ID가 생기면 이미지 업로드 전에 로컬 상태에 즉시 저장한다. 생성/저장 응답이 불명확하면 목록·기존 ID를 먼저 조회하고 새 글 버튼을 반복하지 않는다.
5. TXT의 이미지 순서·파일명·상대경로·IMG ID를 대조해 업로드한다. 실제 URL을 HTML 토큰에 치환하고 TXT에 반영한다. 여러 파일의 업로드 결과 순서를 가정하지 않는다. 기존 업로드 URL과 원격 이미지는 재사용한다.
6. 이미지·본문·제목·메타·퍼머링크·라벨을 적용하고 실제 **초안 저장 완료**를 확인한다. 로컬 `blogger-state.json`에 `draft_saved`, blogId/postId/editorUrl, 저장 확인 시각과 검수 결과를 먼저 남긴다. 조정자가 G를 `ㅇ`로 갱신·재조회한다. 이미지 몇 장이 업로드됐거나 빈 자동저장 글이 생긴 것만으로 G를 완료 처리하지 않는다.
7. 초안 저장 요청이면 여기서 완료한다. H/L은 비워 둔다. 공개 발행 요청이면 모바일/PC 미리보기, 이미지 토큰 제거·로딩·순서·캡션·링크 등을 검수하고 **같은 글**을 발행한다. 발행 클릭 직전 H가 여전히 공란인지 재확인한다. 이미 같은 글이 발행된 상태면 재발행하지 않고 상태만 복구한다.
8. 실제 공개 상태와 게시글 URL(편집기·미리보기·예약 URL 제외)을 확인한다. 로컬 상태를 먼저 `published`로 기록하고 원래 발행 시각을 고정한다. 조정자가 H에 URL, L에 날짜·시간 값을 함께 쓰고, G가 누락됐으면 보완한 뒤 재조회한다.
9. 시트 오류가 나더라도 성공한 게시물을 새로 만들거나 재발행하지 않는다. 로컬 상태를 `sheet_pending`으로 기록하고 시트 기록만 재시도한다. 요청된 브라우저 작업·검수·근거 저장을 마쳤으면 해당 Space를 한 번 종료한다. 인증/사용자 조작 대기는 기존 Space를 보존한다.

`blogger-state.json`은 해당 키워드의 `웹조사/evidence/`에 에이전트가 관리한다. 최소 필드: 작업 식별 정보, runId, spaceId, blogId/postId/editorUrl, 이미지 ID별 파일/URL, 단계, savedAt, publishedAt(UTC offset 포함), publishedAt의 근거, 공개 URL, D/G/H/L별 반영·재조회 상태, 오류·재개 지점. 인증 쿠키·토큰은 저장하지 않는다. TXT에도 사람이 읽을 수 있는 상태와 URL을 동기화한다. 이 파일은 아래 보조 도구가 자동으로 Blogger에서 수집하는 파일이 아니다.

## 5. 코드로 처리하는 범위

[tools/blogger_workflow.py](../tools/blogger_workflow.py)는 Python 3.14 표준 라이브러리만 사용한다. **파일 중복 검사, 로컬 동시 실행 잠금, 헤더 기반 열 찾기, 시트 신규 업로드 판정, KST 날짜 변환과 정밀 batchUpdate 요청 생성**을 수행한다. 실제 채팅 생성·ego Space 조작·글 작성·업로드·시트 전송은 에이전트와 연결 도구가 수행한다. 도구 출력의 `plan_only`를 시트 업데이트 성공으로 보고하지 않는다.

### 5.1 파일 검사와 잠금

```powershell
python3.14-64.exe tools/blogger_workflow.py --no-notify scan '26_1107/앱사용_당근마켓 전국검색'
python3.14-64.exe tools/blogger_workflow.py --no-notify claim 'YY_MMDD/_blogger_runs/RUN_ID/job.json' > 'YY_MMDD/_blogger_runs/RUN_ID/claim.json'
python3.14-64.exe tools/blogger_workflow.py --no-notify release 'YY_MMDD/_blogger_runs/RUN_ID/claim.json'
```

`job.json` 형식 예시(실제 배정으로 바꾸며 그대로 실행하지 않는다):

```json
{"spreadsheetId":"1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s","tab":"앱사용","row":50,"folder":"26_1107/앱사용_당근마켓 전국검색","stage":"A","owner":"실제-채팅-또는-실행-ID"}
```

`scan`은 `create/skip_existing/review_partial/review_duplicates`를 반환한다. A의 `claim`은 두 파일이 없는 경우에만 성공하고 폴더·행 두 잠금을 배타적으로 만든다. B는 `stage: B`로 잠근 후 live 시트와 원격 글을 별도 확인한다. `claim` 성공 여부/종료 코드를 확인하고 영수증을 보존한다. 기존 영수증 파일을 덮어쓰지 않도록 실행마다 고유 경로를 쓴다. 에러 출력은 성공 영수증이 아니다. 잠금은 자동 만료되지 않는다. 중단 시 실행이 끝났는지 확인한 후 소유 토큰으로만 해제한다. `.session/blogger-workflow/locks/`의 잠금을 통째로 지우지 않는다.

### 5.2 시트 snapshot과 요청 계획

연결 도구에서 메타데이터·헤더·정확한 대상 행의 CellData(`userEnteredValue/effectiveValue/formattedValue/dataValidation`)를 읽어 다음 구조로 정리한다. `cells`는 **A열부터 마지막 대상 열까지**, 빈 셀은 `{}`로 채운다. 도구가 중간 빈 셀을 생략하지 않았는지 범위 위치를 확인한다. 실제 읽은 시각만 `readAt`에 기록한다. `get_spreadsheet_range`의 표시 문자열만으로 수식 유무를 판단하지 않는다.

```json
{
  "spreadsheetId":"1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s",
  "sheetId":2121839224,"tab":"앱사용","row":50,"headerRow":1,
  "keyword":"당근마켓 전국검색","readAt":"2026-11-07T21:42:47+09:00",
  "headers":["블로그 업로드 날짜","No.","상위노출 블로그 수집여부","애드센스 블로그 작성여부","네이버 블로그 작성 갯수","외부유입 작성갯수","애드센스 임시저장 여부","애드센스 포스팅 링크","메인 키워드","PC 검색량","모바일 검색량","애드센스 포스팅 작성일"],
  "cells":[{},{},{},{},{},{},{},{},{"userEnteredValue":{"stringValue":"당근마켓 전국검색"}},{},{},{}]
}
```

```powershell
python3.14-64.exe tools/blogger_workflow.py --no-notify preflight 'snapshot.json'
python3.14-64.exe tools/blogger_workflow.py --no-notify sheet-plan 'snapshot.json' 'event.json' > 'sheet-plan.json'
```

`preflight`는 `eligible_new/skip_existing_link/resume_existing_only/review_inconsistent_date`를 반환한다. snapshot은 5분 이내만 허용하지만, 이것이 쓰기 직전 재조회를 대신하지 않는다. `event.json`은 **에이전트가 실제 검수한 후에만** 다음 중 하나로 작성한다:

```json
{"type":"content","verified":true,"folder":"26_1107/앱사용_당근마켓 전국검색"}
```

```json
{"type":"draft","verified":true,"blogId":"실제ID","postId":"실제ID","savedAt":"2026-11-07T21:42:47+09:00"}
```

```json
{"type":"published","verified":true,"blogId":"실제ID","postId":"실제ID","url":"https://실제블로그/실제게시글.html","publishedAt":"2026-11-07T21:42:47+09:00"}
```

`verified`는 검수자의 진술이며 코드가 사실·이미지·원격 발행을 검증했다는 뜻이 아니다. 코드의 파일 검사는 경로·개수·빈 파일·UTF-8만 검사한다. `sheet-plan`은 키워드 불일치·헤더 중복·기존 값 충돌·수식·엄격한 유효성 조건을 확인한다. 동일 값은 재작성하지 않고, 발행 이벤트는 G/H/L의 필요한 변경을 한 `requests` 배열로 만든다. 실제 URL의 글 소유권과 공개 상태는 에이전트가 확인한다.

조정자는 잠금을 유지한 채 다시 읽은 값으로 계획을 생성하고, 반환 `spreadsheetId`와 `requests`를 연결 도구 `batch_update_spreadsheet`의 현재 스키마에 맞춰 전달한다. 결과를 재조회해 D/G는 정확한 `ㅇ`, H는 실제 URL, L은 숫자형 날짜와 KST 표시 시각인지 확인한다. 성공 근거를 저장한 뒤 잠금을 해제한다. CLI는 기본적으로 완료/오류 Windows 알림과 Speech Off.wav를 제공하며 배치 내부 호출·테스트는 `--no-notify`, 전체 작업 종료 알림은 조정자가 한 번 수행한다.

검증 명령:

```powershell
python3.14-64.exe -m unittest discover -s tools -p test_blogger_workflow.py -v
```

테스트는 임시 폴더와 모의 CellData를 사용한다. 실블로그 업로드, 실제 독립 채팅/ego 동시 Space, 시트 쓰기·날짜 렌더링은 사용자 대상 실행 때 별도로 확인한다.
