2026-11-12 갱신. 이 문서는 구글시트의 HTML 미작성 목록이나 사용자가 지정한 행에서 대상을 확정하고, 로컬 웹조사 자료로 Blogger 게시용 HTML과 제목·메타디스크립션 TXT를 작성한 뒤 작성 완료(D열)를 기록하는 **A 프로세스 전용 가이드라인**이다. 작성 결과물의 Blogger 업로드 및 발행 인계는 [BLOGGER_UPLOAD_WORKFLOW.md](BLOGGER_UPLOAD_WORKFLOW.md)를 참조한다.
실행 원칙은 **키워드마다 실제 독립 채팅 배정(단일 세션인 경우 고품질 순차 작성)**이다.

## 1. 대상과 인계 자료

### 1.1 시작 전 확인 및 시트 팝업 조회

1. 현재 프로젝트 `guidelines/`에 `.md` 파일이 있는지 확인한다. 없으면 경로 오류로 중단한다. [.antigravity/rules.md](../.antigravity/rules.md)와 [데스크톱 가이드](AGENT_DESKTOP_GUIDE.md)를 먼저 읽는다.
2. 시트 조회형 요청은 설치된 `ego-browser skill`의 안내에 따라 공개 SDK와 조회용 TaskSpace에서 [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)를 연다. URL의 문서 ID로 확인하고 탭은 팝업에 표시된 이름을 사용한다.
3. 메뉴가 좁은 창에 가려지면 [웹자료수집.md 8.1절](웹자료수집.md#81-팝업-조회-및-목록-저장)의 `ensureSheetsMenuWidth(page)`를 호출해 2,150px 폭 요청과 실제 적용 방식을 확인한다. 에뮬레이션이면 조작할 SDK 라운드마다 재호출하고 새 snapshot에서 메뉴 상태를 확인한다. 현재 UI에서 `🔍 키워드 조회` → `3️⃣ html 글 미작성 전체 시트 조회 (팝업)`를 선택한다. 스크립트 실행이 끝나고 `전체 시트 html 글 미작성 목록` 대화상자가 열릴 때까지 기다린다. 결과 없음, 스크립트 오류, 로그인·권한 요구를 구분한다. 로그인이나 권한 조작이 필요하면 같은 TaskSpace에서 사용자에게 제어를 넘기고 확인 후 재개한다.
4. 전체 목록은 `📋 전체 기본 복사`로 가져온다. 섹션으로 가져올 때는 대상 탭마다 분할 크기(예: `3개씩`)를 정하고 그 탭의 `📑 연달아 분리된 섹션 전체 복사`를 사용한다. 중첩 iframe에서 버튼을 찾지 못하면 현재 화면에서 버튼 위치를 확인한 뒤 클릭한다. 실제 복사 텍스트를 확인할 수 없으면 대화상자 snapshot 또는 iframe subtree의 요약 텍스트박스와 필요한 섹션 텍스트박스를 읽는다. 시트 셀에 붙여넣어 확인하지 않는다.
5. 팝업의 탭·행 순서와 섹션 경계를 유지해 `{tab, row, keyword}`로 정리한다. `No.` 열 대신 실제 시트 행 번호를 사용한다. 전체 행 수·탭 수를 대조하고, 섹션으로 가져왔다면 섹션별 행 수와 누락 여부도 확인한다. 같은 탭·행의 중복이나 키워드 충돌, 탭 누락, 건수 불일치는 해당 범위를 다시 확인한 뒤 배정한다. 조회 결과가 0개면 결과만 보고한다. [웹자료수집.md 8절](웹자료수집.md#8-google-sheets-스크립트-메뉴로-미작성-키워드-추출)의 조회·복사 복구 방식을 참고한다.

ego-browser 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용한다. 최소화된 같은 창은 함수가 자동으로 복원한다. 직접 CDP 복원은 `capture()`를 사용할 수 없을 때만 [웹자료수집.md 7절](웹자료수집.md#ego-taskspace-창-복원과-google-검색-결과-캡처-2026-11-12)에 따른다.

### 1.2 시트 행 검증과 로컬 경로 확정

1. 팝업에서 가져온 행과 직접 지정받은 행 모두 Sheets 연결 도구/API로 문서 메타데이터, 탭의 `sheetId`, 헤더와 대상 행을 확인한다. `블로그 업로드 날짜`, `애드센스 블로그 작성여부`, `메인 키워드`는 헤더명으로 찾는다(현재 참고 A·D·I열). 사전 점검은 탭별로 필요한 열과 대상 행 범위를 묶어서 읽는다. 팝업의 탭·실제 행 번호·메인 키워드를 시트의 현재 행과 대조한다. 행이 바뀌었거나 키워드가 다르면 다시 조회하고, 불일치가 남은 행은 검토 상태로 기록한다. 직접 지정형에서 행 번호가 생략된 경우 같은 폴더의 `research.json`/manifest 또는 지정 탭의 키워드 검색으로 유일한 실제 행을 확인한다.
2. 검증된 행의 `블로그 업로드 날짜`를 `YY_MMDD`로 바꿔 `YY_MMDD/{탭}_{메인 키워드}/`를 먼저 확인한다. A열이 공란이거나 날짜를 해석할 수 없거나 해당 폴더가 없거나 조사 메타데이터가 다른 행을 가리키면 프로젝트의 날짜 폴더에서 같은 이름을 찾는다. `웹조사/research.json` 또는 조사 manifest의 탭·행·키워드와 경로를 대조한다. 구형 폴더는 폴더명과 조사 문서의 주제로 대응을 확인한다. 예를 들어 A열이 `2026-11-12`여도 메타데이터가 `26_1111`의 기존 폴더와 일치하면 그 폴더를 사용한다. 후보가 없거나 일치 여부를 확정할 수 없으면 해당 행의 경로와 사유를 기록하고, 확인된 다른 행은 계속 처리한다.
3. 작업 식별자는 `spreadsheetId + sheetId + 탭 + 실제 행 번호 + 메인 키워드 + 키워드 폴더`다. 조회 시각, 원본 목록 순서·섹션(있을 경우), 확인한 시트 값, 실제 조사 폴더의 프로젝트 상대경로와 선택 근거, 제외·보류 사유를 배정 기록에 남긴다. 조회와 경로 대조는 읽기 단계다. 재개 요청은 기존 배정과 실제 결과물 상태를 대조하고 새로 조회된 행은 신규 실행 대상으로 남긴다.

### 1.3 입력 자료와 결과물

- `웹조사/publish/{탭}_{키워드}_웹조사결과.md`를 먼저 읽는다. 없으면 같은 키워드의 `웹조사/publish/*_웹조사결과.md`, `웹조사/*_웹조사결과.md`, `웹조사/웹조사결과.md` 순으로 확인한다. 조사 Markdown이나 핵심 질문에 필요한 근거를 확보하지 못한 행은 자료 보완 항목과 재개 지점을 기록한다.
- 이미지 링크는 선택한 Markdown 파일 기준 상대경로로 해석한다. 같은 키워드의 `publish/`, 구형 `웹조사/`와 문서에 명시된 하위 경로에서 발행 후보를 확인한다. `publish/`에서 사용할 수 있는 이미지가 4장 이하이거나 필요한 장면이 빠졌으면 1.4절에 따라 보완한다.
- 이미지별 원본·발행 파일명, 역할, 화면 종류, 권장 순서, 설명·alt·캡션, 출처·실제 화면 URL·확인일을 인계한다. 파일번호, 이미지 내부 표식 번호, 본문 절차 번호를 구분한다. 원래 파일명을 보존하고 채택한 이미지를 `IMG_01` 같은 슬롯 ID로 HTML과 TXT에 연결한다.
- 기본 출력은 `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_html콘텐츠.html`과 `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_제목메타디스크립션.txt`다. 두 파일을 UTF-8로 저장하고 원본 조사 Markdown·이미지·수집 기록을 보존한다.

### 1.4 발행용 이미지가 부족할 때

1. 같은 키워드의 `웹조사/publish/`에서 본문에 사용할 수 있는 이미지를 센다. 같은 화면의 원본과 편집본은 한 장으로 센다. 4장 이하이거나 필요한 장면이 빠졌으면 `research.json`, `publish/index.json`, `evidence/review.json`, 캡처·출처 기록을 대조해 같은 키워드의 `웹조사/raw/`에서 보완 후보를 찾아 직접 연다. `publish/`의 제외·보류 사유도 확인하고 다른 날짜나 키워드의 동명 파일은 제외한다.
2. 원본과 발행본의 실제 화면, 앱·웹 구분과 버전, 버튼·표식, 출처 URL·확인일, 가독성, 개인정보 노출을 대조한다. 캡처 및 가림·자르기·표식 편집본을 활용하고, 화면이 현재 설명과 다르면 예시의 시점과 차이를 명확히 밝힌다. 예를 들어 일반택배 화면을 반값택배 전용 접수 화면으로 설명하지 않는다.
3. `raw/`를 확인한 뒤에도 사용할 이미지가 4장 이하이거나 필요한 장면을 확보하지 못했으면 ego-browser에서 해당 메인 키워드를 Google로 검색한다. 광고를 제외하고 실제로 연 공식 페이지에서 빠진 단계의 화면을 `tools/research_browser.mjs`의 `capture()`로 수집한다. 검색 화면을 사용할 때는 실제로 연 공식 결과 제목에, 단계 화면은 설명 대상 버튼이나 메뉴에 빨간 테두리·화살표 등 필요한 표식을 붙인다. 원본과 URL·확인일·캡처 근거는 `raw/`와 `evidence/` 또는 키워드별 작업 기록 폴더에 보관하고, 캡처와 표식 검수는 [웹자료수집.md 6~7절](웹자료수집.md)을 따른다.
4. `raw/`에서 채택한 이미지와 새 캡처의 복사본 또는 편집본을 `웹조사/publish/blogger-images/`에 저장한다. 수정이 없으면 원래 이름을 유지하고, 같은 이름의 파일은 내용이 같을 때 재사용하며 내용이 다르면 구분되는 이름으로 저장한다. 가림·자르기·표식은 작업 사본에 적용하고 편집 후 다시 열어 검수한다. 원본, 기존 발행 이미지, 조사 Markdown, `research.json`, 수집 도구의 `index.json`과 검증 기록을 보존한다.
5. 보완 이미지마다 HTML에 슬롯과 치환 토큰을 만들고 TXT의 `[Blogger 이미지 업로드 추천 순서와 삽입 위치]`에서 같은 슬롯 ID의 상세 블록을 작성한다. 기존 이미지와 합쳐 실제 절차 순서에 배치하고 원본과 업로드 파일의 상대경로를 각각 적는다. 실제 H2/H3 문구와 ID, 직전 문단 ID와 마지막 문장, 직후 문단 ID와 첫 문장, 화면 설명·alt·캡션·픽셀 크기, 출처 URL·확인일, 채택 사유·편집·가림 내역을 기록한다. 화면에 표식이 없으면 `해당 없음`으로 쓰고, 본문과 캡션은 실제 보이는 버튼과 상태를 기준으로 작성한다.
   - 콘텐츠와 이미지 배치 TXT에는 이미지 이용 제한에 관한 문구를 넣지 않는다. 화면의 시점과 실제 설명에 필요한 차이는 그대로 기재한다.
6. 채택하지 않은 후보의 경로와 사유는 TXT의 `[제외·보류 이미지]`에 기록한다. 추가 조사 후에도 적합한 이미지가 부족하면 시도한 경로, 최종 채택 수, 필요한 장면과 재개 지점도 그 항목에 남긴다. 공식 근거로 핵심 절차를 설명할 수 있으면 단계 안내·표·공식 링크로 본문을 완성한다. 이미지 수만으로 D열 완료 여부를 결정하지 않으며 핵심 안내를 검증할 근거가 부족하면 검토 상태로 둔다.

## 2. 시트 열과 기록 원칙 (A 콘텐츠 작성 관련)

A 단계는 콘텐츠 생성 및 검수 완료 후 **'애드센스 블로그 작성여부'(D열)**에 완료 표식을 기록한다.

| 목적 | 실제 헤더명 | 현재 참고 열 | 쓰는 시점과 값 |
|---|---|---|---|
| 로컬 경로 탐색(날짜) | 블로그 업로드 날짜 | A | 해당 행의 날짜(예: 2026-11-06)를 읽어 로컬 날짜 폴더(`YY_MMDD`, 예: `26_1106`) 및 키워드 경로(`{탭}_{키워드}`) 탐색에 사용; 읽기만 수행 |
| 콘텐츠 작성 완료 | 애드센스 블로그 작성여부 | D | HTML/TXT 두 파일 생성 및 검수 완료 후 `ㅇ` |
| 행 식별 | 메인 키워드 | I | 대상 행 대조 및 읽기만 수행 |

1. **셀 값 및 서식 원칙**:
   - `ㅇ`는 한글 자음이다. 영문 `o`, 숫자 `0`, 불리언 등으로 바꾸지 않는다.
   - 공백 문자, 수식 결과 공란, FALSE, 0은 빈 셀로 취급하지 않는다.
   - 쓰기 직전에 **같은 행의 키워드와 대상 셀**을 다시 읽는다. 일치하는 완료값(`ㅇ`)은 보존하고, 다른 값이나 수식이 있으면 덮어쓰지 않는다.
   - 필요한 빈 셀만 정확히 수정하고 저장 후 재조회한다. 다른 열, 전체 행, 서식, 시트 시간대를 변경하지 않는다.
2. **조정자 역할**:
   - 시트 쓰기는 **한 조정자**가 전담한다. 개별 작업 채팅은 완료 근거를 조정자에게 전달하고, 조정자가 시트에 결과를 반영한다.
3. **오류 격리**:
   - 시트 업데이트 실패는 글 생성 실패와 구분한다. 로컬 파일과 작업 기록을 보존하고 **시트 반영만 재시도**한다.

## 3. A — 중복 검사 및 독립 채팅 배정 (순차 작성 대응)

### 3.1 생성 전 중복 판정

`YY_MMDD/{탭}_{키워드}/` **전체 하위 경로**에서 정확한 두 결과물 파일명을 찾는다. 루트, `웹조사/`, `웹조사/publish/`, 구형 `outputs/` 등을 모두 포함한다.

| 발견 상태 | 처리 방침 |
|---|---|
| 두 파일 모두 없음 | 신규 생성 후보 |
| 같은 폴더에 정상 크기의 두 파일 각 1개 | 생성 건너뛰기; 경로와 상태 보고 |
| 한 파일만 있음, 빈 파일, 서로 다른 위치의 쌍 | 부분 결과 검토; 자동 재생성·덮어쓰기 금지 |
| 동일 파일명이 여러 곳에 존재 | 중복본 검토; 임의 선택·삭제·새 생성 금지 |

- 파일 존재만으로 내용 검수가 완료됐다고 판단하지 않는다. 기존 두 파일이 있으나 D가 누락됐다면 재생성 없이 실제 내용을 검수한 후 시트 기록을 복구한다. 신규 생성은 작성여부 셀이 비어 있고 사용할 조사 근거가 확보된 행으로 확정한다. 다른 값이나 수식이 있는 행은 검토 상태로 기록한다.
- D가 이미 `ㅇ`인데 파일이 없다면 유실/다른 경로 여부를 확인하고 즉시 재생성하지 않는다.
- 2026-11-08 앱사용 46행 사전 점검 사례: D=`ㅇ`지만 해당 HTML/TXT 쌍이 프로젝트에 없고 조사 자료만 있었다. B 업로드에서도 이 불일치를 확인해야 한다. 경로 확인 또는 명시적 재작성 의사 확인 전에는 새 Blogger 글을 생성하지 않는다. 확인한 범위·시트 값·재개 지점을 로컬 상태에 남긴다.

### 3.2 독립 채팅 배정 및 실행 장벽

1. **신규 생성 대상 확정**:
   - 조정자가 대상 목록, 실제 행, 로컬 경로, 파일 상태와 시트 헤더를 확인해 **실제 신규 생성할 n개 키워드**를 확정한다. 팝업 섹션은 배정·보고에 사용하며 실행 장벽은 이 절을 따른다.
2. **독립 채팅 배정 (Codex/다중 에이전트 환경)**:
   - 키워드별 **실제 독립 채팅 n개**를 생성하여 병렬 처리한다. 단일 키워드도 생성 대상이면 독립 채팅 1개를 배정한다.
   - 생성 전 `YY_MMDD/_blogger_runs/{runId}/dispatch.json`을 `pending`으로 저장한다. 배정 폴더의 날짜가 여러 개면 이번 실행의 한국 날짜 폴더에 배정 기록을 두고 각 행의 실제 키워드 폴더를 별도로 기록한다. 최초 프롬프트에 배정 키워드·폴더·시트 행, 원래 조건, 가이드라인, dispatch 경로를 전달한다.
   - 섹션으로 배정하면 해당 섹션의 채팅 ID가 모두 기록된 시점에 그 섹션과 소속 행을 `ready`로 바꾼다. 섹션을 나누지 않았으면 전체 배정에 같은 기준을 적용한다. `ready` 전에는 사전 점검만 수행한다. 채팅 생성이 막힌 섹션과 사유는 `blocked`로 기록하고, 준비된 다른 섹션은 진행한다. 사용자가 동시 작업 수를 지정했으면 그 범위에서 시작한다.
3. **구글시트 행 잠금 금지 (행 락 배제 원칙)**:
   - **앞으로는 구글시트에서 잠그지 않는다.** A 단계(콘텐츠 작성) 진행 시 구글시트 행에 대한 배타 잠금(`row:...`)을 생성하지 않으며, 작업 충돌 방지 및 중복 확인은 **오직 로컬 키워드 폴더(`folder:`) 및 `scan`을 통한 파일 존재 여부**로만 관리한다.
   - 불필요한 시트 행 잠금으로 인한 타 세션·에이전트의 작업 차단이나 후속 B 프로세스(Blogger 업로드)와의 잠금 충돌을 원천 방지한다.
4. **Antigravity 단일 세션 환경 대응**:
   - 만약 독립 채팅 자동 생성이 지원되지 않는 Antigravity 환경이라면, **"순차 작성 금지" 제약을 해제하고 현재 조정자 세션에서 키워드의 HTML/TXT를 차례대로 고품질 작성 및 검수**한다. (해당 섹션에서 일괄 순차 진행)
5. **작업 수행 및 검수**:
   - 각 작업은 지정된 한 키워드의 자료만 사용한다.
   - 결과물 검수 때 파일 쌍·UTF-8, H2 전체 링크와 인트로 CTA, 사실 근거를 확인한다. 보완 이미지를 포함해 HTML 슬롯(`IMG_01`)과 TXT 상세 블록을 1:1로 대조하고, 토큰·실제 업로드 파일·삽입 위치·픽셀·앞뒤 문장·alt·캡션을 검수한다. 작업 채팅은 파일 경로, 채택·보류 이미지와 검수 결과를 함께 보고한다.
   - 로컬 미리보기에서는 임시 사본의 토큰에 실제 이미지를 연결해 모바일·PC 폭에서 표시, 비율, 가로 넘침을 확인한다. 작업 채팅에서 브라우저 연결·렌더 오류가 나면 조정자가 접근 가능한 환경에서 해당 원고를 모아 확인한다. 렌더에 성공한 범위와 실제 Blogger 테마 미리보기 여부를 각각 TXT에 기록한다.
6. **D열 시트 반영 및 TXT 작업 정보 기록**:
   - 조정자가 검수가 끝난 행을 묶어 두 결과물과 대상 키워드·작성여부 셀을 다시 확인한다. 준비된 행의 **'애드센스 블로그 작성여부'(D열) 빈 셀에만 `ㅇ`**를 기록한 뒤 같은 범위를 재조회한다. 다른 행의 검수가 진행 중이어도 확인된 행은 먼저 반영할 수 있다.
   - TXT 작업 정보에 `spreadsheetId, sheetId, 탭, 실제 행 번호, 메인 키워드, runId/threadId`와 `D열 반영 상태` 한 줄을 둔다. 조정자가 실제 반영·재조회 결과로 그 줄을 갱신한다. 인계 메모에서 D열을 언급할 때는 작업 정보의 상태 줄을 참조한다. 전체 처리 후 대상 행을 묶어서 마지막으로 대조한다.
7. **결과 보고**:
   - 조회형 요청은 팝업 전체 행 수·탭 수와 섹션별 배정 결과를 보고한다. 행별로 HTML/TXT 경로, HTML 줄 수·H2 개수, 채택 이미지 수, 검수 및 D열 재조회 상태를 기록한다. 이미지 보류·보완, 기존 결과 사용, 자료 누락, 경로 불일치, 부분 파일·중복, 시트 쓰기 실패는 각 행의 사유와 재개 지점을 함께 남긴다.

## 4. 코드로 처리하는 범위 (`tools/blogger_workflow.py`)

[tools/blogger_workflow.py](../tools/blogger_workflow.py)는 Python 3.14 표준 라이브러리만 사용한다. **파일 중복 검사, 로컬 동시 실행 잠금, 헤더 기반 열 찾기, 시트 batchUpdate 요청 생성**을 지원한다.

```powershell
# 1. 대상 폴더 파일 스캔 (create / skip_existing / review_partial / review_duplicates 반환)
python3.14-64.exe tools/blogger_workflow.py --no-notify scan 'YY_MMDD/{탭}_{키워드}'

# 2. A 단계 로컬 폴더 잠금 확보 (구글시트 행 잠금 제외 정책)
# 앞으로는 구글시트에서 잠그지 않으며, stage A claim은 행 락을 제외하고 로컬 폴더만 잠금하여 타 세션/B단계 충돌을 방지합니다.
python3.14-64.exe tools/blogger_workflow.py --no-notify claim 'YY_MMDD/_blogger_runs/RUN_ID/job.json' > 'YY_MMDD/_blogger_runs/RUN_ID/claim.json'

# 3. 작성 검수 완료 후 시트 D열 업데이트 계획 생성
python3.14-64.exe tools/blogger_workflow.py --no-notify sheet-plan 'snapshot.json' 'event.json' > 'sheet-plan.json'

# 4. 작업 완료 후 잠금 해제
python3.14-64.exe tools/blogger_workflow.py --no-notify release 'YY_MMDD/_blogger_runs/RUN_ID/claim.json'
```

- `job.json` 형식 예시 (`stage: A`):
  ```json
  {"spreadsheetId":"1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s","tab":"앱사용","row":50,"folder":"26_1107/앱사용_당근마켓 전국검색","stage":"A","owner":"실제-채팅-또는-실행-ID"}
  ```
- `event.json` 형식 예시 (`type: content`):
  ```json
  {"type":"content","verified":true,"folder":"26_1107/앱사용_당근마켓 전국검색"}
  ```
