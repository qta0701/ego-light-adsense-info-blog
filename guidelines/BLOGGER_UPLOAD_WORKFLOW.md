## 0. 기본 실행 모드 — 최소 왕복 (2026-11-08 사용자 확인 반영)

사용자가 앱사용 49행의 공개 글과 H열 실제 URL을 정상 완료로 확인했다. 다음 실행은 이 절의 간소화 기준을 기본 적용한다. 아래 과거 기록이나 관련 가이드에 일률적인 PC·모바일 미리보기 요구가 있더라도 **이 업로드 작업에서는 현재 절의 조건부 검수 기준을 우선**한다.

**기본 흐름:** 시트 팝업 또는 직접 지정으로 대상 확보 → 실제 행·파일·중복 확인 → stage B 예약 → 같은 글에 이미지 순차 업로드 → 완성 본문·메타 입력 → 저장 및 통합 확인 1회 → G 반영 → 공개 발행 → 실제 공개 페이지 확인 1회 → H/L 반영·재조회 → 종료.

**2026-11-12 이미지 우선 기준:** 채택 이미지와 그 역할을 유지하고 업로드까지 완료하는 것을 기본으로 한다. 설명이 충분하다는 이유만으로 이미지 없는 글을 기본 발행하지 않는다. 이미지 파일이 없거나 화면이 맞지 않으면 1.2절의 확인·대체 절차를 먼저 수행하고, 해결하지 못한 행은 그 상태와 재개 지점을 남겨 보류한다. 이미지 없는 발행은 사용자가 그 범위와 영향을 확인하고 명시적으로 요청하거나 허용한 경우에만 가능하다.

| 기본으로 수행 | 기본으로 생략 |
|---|---|
| 실제 행·키워드·헤더, G/H/L, 로컬 상태·Blogger 중복 대조 | 이미 작성·검수된 원고를 다시 조사하거나 전면 재작성 |
| 이미지 파일↔IMG ID↔업로드 URL 매핑, 본문 구조·토큰 검사 1회 | 이미지마다 snapshot·screenshot·별도 검사 스크립트 작성 |
| 저장 후 같은 편집기 재진입 1회로 본문·메타 묶음 확인 | 필드마다 저장·재진입, 같은 저장본 반복 비교 |
| 실제 공개 URL·제목·게시 상태·발행 시각·이미지 로딩 묶음 확인 | PC/모바일 미리보기 탭, iframe 분리 탭, 뷰포트 변경, 전체 화면 캡처 |
| 생성/발행/시트 쓰기 직전 live 확인, 쓰기 후 재조회 | 동일 시점의 같은 셀 중복 요청, Sheets 연결 도구로 전체 탭의 셀 읽기 |
| 실패·불일치가 있는 부분만 추가 확인 | 테마 SEO·광고·사이트 전체 품질까지 검사 범위 확대 |

**미리보기·시각 검수는 조건부:** 사용자가 별도로 요청하거나, 새 CSS/레이아웃·이미지 편집을 했거나, 가독성/잘림/로딩 문제가 관찰될 때만 해당 부분을 확인한다. 필요한 화면 한 곳부터 확인하고, 반응형 문제이면 해당 뷰포트만 추가한다. 초안만 요청한 경우 저장본 확인으로 종료한다. 생략한 검수를 실시했다고 기록하지 않는다.

ego-browser 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용한다. 최소화된 같은 창은 함수가 자동으로 복원한다. 직접 CDP 복원은 `capture()`를 사용할 수 없을 때만 [웹자료수집.md 7절](웹자료수집.md#ego-taskspace-창-복원과-google-검색-결과-캡처-2026-11-12)에 따른다. 업로드 검증용 캡처는 B 실행 디렉터리의 별도 폴더에 보관한다.

구조 검사는 완성 HTML의 이미지 개수·순서·alt/캡션·실제 URL, 남은 토큰·빈 src·로컬 경로·예시 URL을 한 번에 확인한다. 공개 확인 때 lazy-load 이미지는 순차 스크롤하여 로딩을 확인하되 이미지마다 캡처하지 않는다. 중복·누락·저장 실패는 해결 후 진행한다.

## 1. 대상과 인계 자료

1. **대상 구글시트**:
   - [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)
   - 작업 식별자: `spreadsheetId + sheetId + 탭 + 실제 행 번호 + 메인 키워드 + 키워드 폴더`
   - 팝업에서 추출하거나 사용자가 지정한 탭·실제 시트 행 번호·메인 키워드를 사용한다. `No.` 열의 번호를 실제 시트 행 번호로 사용하지 않는다.
2. **로컬 작업 경로 탐색 규칙 (구글시트 A열 '블로그 업로드 날짜' 기반 동적 탐색)**:
   - 1.1절의 팝업 추출 또는 직접 지정으로 확보한 탭·행·메인 키워드를 live 시트와 대조한 뒤 로컬 경로를 찾는다.
     1) **시트 날짜 확인**: 해당 행에서 `블로그 업로드 날짜` 헤더의 값(현재 A열)을 읽는다.
     2) **날짜 폴더명(`YY_MMDD`) 도출**: A열의 날짜 데이터(예: `2026-11-06`, `2026. 11. 6` 등)에서 연도 끝 2자리와 월/일을 추출하여 `YY_MMDD` 형식(예: `26_1106`)으로 변환한다.
     3) **키워드 폴더 탐색**: 프로젝트 루트에서 `YY_MMDD/{탭}_{메인 키워드}/`(예: `26_1106/앱사용_당근마켓 채팅 걸기/`)를 먼저 확인한다. 파일명에 사용할 수 없는 문자가 있는 탭·키워드는 기존 조사 도구의 폴더명 정규화 규칙을 적용하고, 시트 대조에는 원래 이름을 사용한다.
     4) **경로 예외 처리**: 날짜가 비었거나 해석할 수 없거나, 예상 폴더가 없거나 조사 기록이 다른 행을 가리키면 프로젝트의 `YY_MMDD` 폴더에서 같은 이름을 찾는다. `웹조사/research.json`, 기존 배정 기록·manifest 또는 `blogger-state.json`이 있으면 탭·행·키워드·경로를 대조한다. 구형 폴더는 폴더명과 조사 문서의 주제를 확인한다. 경로가 여러 후보로 남으면 해당 행의 경로와 사유를 기록하고, 확인된 다른 행을 계속 처리한다.
     5) **결과물 파일 확보**: `웹조사/publish/`에서 실제 폴더명을 접두사로 쓰는 `_html콘텐츠.html`, `_제목메타디스크립션.txt` 및 관련 `_웹조사결과.md`를 확인한다. `tools/blogger_workflow.py scan`으로 키워드 폴더 전체의 HTML/TXT 사본을 대조한다. 구형 경로에서는 같은 디렉터리의 유일한 정상 쌍을 확인해 사용한다. 이미지는 TXT에 기록된 파일명·상대경로·슬롯을 대조해 가져온다.
3. **입력 자료**:
   - 위 탐색 규칙으로 확보한 `_html콘텐츠.html`과 `_제목메타디스크립션.txt` 쌍. 기본 위치는 `YY_MMDD/{탭}_{키워드}/웹조사/publish/`다.
   - 발행 대상 이미지 파일들 (TXT의 `[Blogger 이미지 업로드 추천 순서와 삽입 위치]` 섹션 매핑 준수)
   - UTF-8 인코딩 확인 및 원본 조사 Markdown·이미지·수집 기록 보존
4. **업로드 인계 기준**:
   - HTML/TXT 누락, 빈 파일, 서로 다른 위치의 쌍, 중복 사본은 글 생성 전에 해소한다. 채택 이미지의 누락·매핑 불일치는 1.2절에 따라 이미지별로 처리한다.
   - 이미지별 원래 파일명, 슬롯 ID(`IMG_01`, `IMG_02` 등), 본문 순서, 치환 토큰(`{{BLOGGER_IMAGE_URL_IMG_01}}`), 권장 alt·캡션을 확인한다.
   - 단일 글 내의 업로드는 순차 처리하며, 업로드된 실제 URL로 HTML 토큰을 치환한다.

### 1.1 시트 스크립트 메뉴에서 Blogger 미작성 후보 가져오기

1. 설치된 `ego-browser skill`을 끝까지 읽고 공개 SDK로 `순분` 프로필(4.2절)의 조회용 TaskSpace에서 1.애드센스 키워드표를 연다. 시트 제목이 바뀌어도 URL의 문서 ID로 확인한다. 메뉴가 좁은 창에 가려지면 [웹자료수집.md 8.1절](웹자료수집.md#81-팝업-조회-및-목록-저장)의 `ensureSheetsMenuWidth(page)`를 사용하고 실제 창과 뷰포트 적용 방식을 확인한다. 에뮬레이션이면 조작할 SDK 라운드마다 재호출하고 새 snapshot에서 메뉴 상태를 확인한다. 상단 `🔍 키워드 조회` → `5️⃣ blogger 미작성 전체 시트 조회 (팝업)`을 실행한다.
2. 스크립트 실행이 끝나고 `전체 시트 blogger 미작성 목록` 팝업이 나타날 때까지 기다린다. 결과 0건, 실행 오류, 로그인·권한 요구를 구분한다. 인증이나 사용자 조작이 필요하면 같은 Space에서 제어를 넘긴 뒤 재개한다.
3. `📋 전체 기본 복사`를 눌러 가져온 모든 탭·실제 행 번호·메인 키워드를 작업 목록으로 삼는다. 분할 복사를 별도로 요청한 경우에는 해당 탭의 분할 수를 정한 뒤 `📑 연달아 분리된 섹션 전체 복사`를 사용한다. 복사 텍스트를 확인하고, 중첩 iframe에서 복사 버튼 조작이 실패하거나 클립보드를 읽을 수 없으면 팝업 snapshot 또는 해당 iframe subtree의 요약과 섹션 텍스트박스를 읽는다. 복사 확인을 위해 시트에 붙여넣지 않는다. 메뉴 클릭이 다른 요소에 가려진 경우와 복사 복구는 [웹자료수집.md 8절](웹자료수집.md#8-google-sheets-스크립트-메뉴로-미작성-키워드-추출)의 방식을 참고한다.
4. 목록을 `{tab, row, keyword}`로 정리하면서 팝업의 탭·행 순서와 선택한 섹션 경계를 유지한다. 팝업의 전체 행 수·탭 수와 실제 확보 목록을 대조하고, 섹션으로 가져왔다면 대상 탭의 섹션별 건수도 확인한다. 같은 탭·행 중복, 키워드 충돌, 탭 누락, 건수 불일치는 해당 목록을 다시 확인한 후 배정한다. 팝업에 0건으로 표시되면 조회 결과를 보고하고 종료한다.
5. 조정자는 Sheets 연결 도구로 문서 메타데이터, 해당 탭의 `sheetId`, 헤더와 후보 행을 좁은 범위로 읽는다. `블로그 업로드 날짜`, `메인 키워드`, `애드센스 임시저장 여부`, `애드센스 포스팅 링크`, `애드센스 포스팅 작성일`(현재 A·I·G·H·L)을 헤더로 찾는다. 실제 행·키워드가 달라졌으면 다시 조회하고, 불일치가 남으면 해당 행을 보류한다. 일치한 행의 HTML/TXT 쌍과 G/H/L 실제 공란을 확인해 4.2절의 신규 배정 후보를 만든다. 배정받은 작업은 이미지 문제 복구와 Blogger 중복 검사를 글 생성 전에 수행한다. 조회·대조 중에는 시트를 수정하지 않는다.
6. 기존 B 실행 기록에 조회 시각, 문서·탭 ID, 탭·실제 행·키워드, 팝업 순서와 섹션, 확인한 시트 값, 로컬 상대경로, 배정·보류 사유를 남긴다. 목록 확보 후 조회용 Space를 정리하고 확인된 행을 4.2절의 병렬 배정으로 넘긴다. 팝업 섹션은 원본 순서와 보고에 사용한다. 기존 실행 재개 시에는 원래 배정과 `blogger-state.json`의 Space·글 ID를 대조해 남은 단계부터 이어간다. 새로 조회된 행은 신규 실행 대상으로 남긴다.

### 1.2 이미지 우선 인계·복구와 행 보류 기준

1. **원래 목표 고정:** B 단계에서 원본 TXT의 채택 이미지 수 `N`과 순서·IMG ID·경로·역할·alt·캡션, HTML 슬롯·토큰을 읽고 B 실행 기록에 먼저 고정한다. `N`개 모두를 원본 또는 의미가 맞는 대체 이미지로 업로드하는 것이 목표다. TXT가 이미 0개라면 조사 기록을 확인하고 관련 있는 발행용 이미지 1개 이상을 준비한다. 사용자가 이미지 없는 글을 명시적으로 허용한 경우는 그 범위를 기록한다. 이미지 수를 줄여 검사를 통과시키거나 일괄 삭제 스크립트를 적용하지 않는다.
2. **이미지별 파일 확인:** 실제 파일과 `research.json`, 조사 Markdown, `publish/index.json`, `evidence/review.json`, TXT에 기재된 원본·출처·가림 내역을 대조하고 각 IMG ID의 파일·매핑·내용을 확인한다. 직접 캡처한 화면과 가림·자르기·표식 편집본을 활용한다. 파일 누락이나 경로 오류는 같은 키워드의 기록과 실제 파일로 복구한다.
3. **파일·화면 문제 시 대체 확보:** 이미지가 누락되거나 설명할 단계와 맞지 않으면 같은 키워드의 기존 이미지, 공식 화면 캡처 또는 적합한 자체 제작 설명 이미지를 찾아 검수한다. 직접 만든 도식·일러스트는 실제 앱 화면이나 확인하지 않은 절차처럼 표현하지 않는다. AI 생성 이미지가 적합하면 설치된 이미지 생성 스킬을 따른다. 시도한 후보와 출처·확인일을 IMG ID별로 기록한다.
4. **슬롯별 완료 조건:** 대체물은 원본 슬롯이 설명하던 내용과 본문 단계에 맞아야 한다. 원본과 발행용 파일을 보존하고 같은 IMG ID와 위치를 유지하되 필요하면 alt·캡션·본문을 실제 대체 이미지에 맞게 수정한다. TXT와 B 기록에 원본 경로·대체 경로·출처·상태·사유를 갱신한다. 원본 `N`과 최종 업로드해야 할 슬롯을 대조하고, 각 슬롯의 실제 Blogger URL을 순서대로 보존한다.
5. **미해결 시:** 파일이나 정확한 대체물을 확보하지 못하면 관련 IMG ID와 시도 내역, 필요한 자료 및 재개 지점을 기록하고 그 행을 보류한다. 명시적으로 이미지 일부/전체 없는 발행을 허용받지 않았다면 슬롯·토큰을 지워 발행하지 않는다. 이미 Blogger 글이 생겼다면 같은 postId와 업로드된 URL을 보존해 재개한다. 미완성 초안을 기술적으로 저장할 수는 있지만 G 완료 표시나 공개 발행, H/L 기록은 하지 않는다. 다른 준비된 행은 계속 처리한다.
6. **전달·검증:** 변경할 때 원본 HTML/TXT와 이미지 파일을 B 실행 디렉터리에 보존하고 발행용 사본을 만든다. `N > 0`이면 업로드 전 `원래 N = 원본 사용 예정 슬롯 + 대체 예정 슬롯 + 명시적으로 제외 허용된 슬롯`을 대조하고, 완료 시 각 예정 슬롯이 실제 업로드 또는 확인된 기존 URL로 연결됐는지 다시 확인한다. 보고의 전체 업로드 수에는 대체 이미지 업로드도 포함하고 대체 수를 별도로 표시해 중복 합산하지 않는다. 원래 `N = 0`이면 새로 확보한 이미지의 슬롯 수를 별도로 기록·검증한다. 저장 후와 공개 페이지에서 각 IMG ID의 실제 URL, 이미지 수·순서·alt·캡션·로딩, 잔여 토큰을 확인한다. 업로드 실패를 기록하고 해당 이미지부터 재개한다.

**2026-11-12 재발 방지:** 당시 13건의 채택 이미지 40개가 실제 Blogger 이미지 업로드 시도 전에 일괄 제거됐다. 이미지 슬롯은 파일과 본문 단계별로 대조하고, 준비된 이미지를 업로드해 확인한다. 기록: `26_1111/_blogger_runs/20261112-codex-2048/completion.md`.

## 3. 시트 열과 기록 원칙 (B 업로드 관련)

B 단계는 **'애드센스 임시저장 여부'(G), '애드센스 포스팅 링크'(H), '애드센스 포스팅 작성일'(L)**을 다룬다.

| 목적 | 실제 헤더명 | 현재 참고 열 | 쓰는 시점과 값 |
|---|---|---|---|
| 로컬 경로 탐색(날짜) | 블로그 업로드 날짜 | A | 해당 행의 업로드 날짜(예: 2026-11-06)를 읽어 로컬 날짜 폴더(`YY_MMDD`, 예: `26_1106`) 및 키워드 경로(`{탭}_{키워드}`) 탐색에 사용; 읽기만 수행 |
| 초안 저장 확인 | 애드센스 임시저장 여부 | G | Blogger에 실제 초안 저장이 완료됐음을 확인한 직후 `ㅇ` 기록; 발행 후에도 유지 |
| 공개 글 주소 | 애드센스 포스팅 링크 | H | 실제 공개 발행을 확인한 게시글 URL (`https://...`) |
| 행 식별 | 메인 키워드 | I | 대상 행 대조 및 읽기만 수행 |
| 발행 시각 | 애드센스 포스팅 작성일 | L | H를 기록할 때 함께 실제 발행 시각을 날짜·시간 값으로 기록 |

1. **셀 기록 기준**:
   - `ㅇ`는 한글 자음이다. 영문 `o`, 숫자 `0`, 불리언 등으로 바꾸지 않는다. 수식 결과 공란, 공백 문자, FALSE, 0은 빈 셀로 취급하지 않는다.
   - 쓰기 직전에 대상 행의 키워드와 셀 값을 다시 읽는다. 일치하는 완료값은 보존하고, 다른 값이나 수식이 있으면 덮어쓰지 않는다.
   - 시트 쓰기는 한 조정자가 담당한다. Space 작업자는 완료 근거를 전달하고 조정자가 반영한다.
2. **발행 링크(H)와 발행 시각(L) 동시 쓰기**:
   - H와 L은 같은 `batchUpdate` 요청 묶음에 포함한다. G가 비어 있으면 확인된 저장 근거로 함께 보완한다.
   - 이미 같은 H가 있으면 재발행하지 않고 기존 글 확인 후 누락된 G/L만 복구한다.
   - **날짜 형식**: 문자열 그대로 쓰지 않고 **한국 시각의 날짜 일련값 + DATE_TIME 표시 형식**(`yyyy. m. d AM/PM h:mm:ss`)으로 쓴다. KST 벽시각으로 변환한 일련값을 넣고 `formattedValue`로 오전/오후 표시를 확인한다.
   - 발행 시각은 Blogger에서 확인한 실제 발행 시간 또는 이번 실행에서 실제 발행 완료를 관찰한 시각을 사용한다. 재시도 시 현재 시각으로 바꾸지 않는다.
3. **오류 격리**:
   - 시트 업데이트 실패는 글 저장/발행 실패와 구분한다. 로컬 파일, 실제 글 ID, URL, 원래 발행 시각을 보존하고 시트 반영만 재시도한다.

## 4. B — 독립 작업 채팅과 ego-browser Space 3개 병렬 업로드


### 4.1 입력과 신규 발행 차단

시트 팝업 조회형은 1.1절에서 확보한 후보를 사용한다. 직접 지정형과 동일하게 시트 탭과 실제 행 번호, 대상 Blogger 블로그, 초안 저장/공개 발행 범위를 확인한다. 1절 2항에 따라 시트의 `블로그 업로드 날짜`와 로컬 기록을 대조한다. 신규 생성은 로컬 업로드 파일을 확보하고 기존 초안은 Blogger에 저장된 본문을 확인한다.

| live 시트 상태 | 신규 작업 처리 |
|---|---|
| G 공란, H 공란, L 공란 | 신규 업로드 후보. 로컬 기록과 Blogger 기존 글도 조회 |
| G 값 있음, H·L 공란 | 직접 지정한 재개 요청에서 기존 초안 ID를 확인해 같은 글로 진행 |
| G 값 있음, H 공란, L 값 있음 | 상태 불일치 검토. 같은 공개 글을 확인하면 누락 시트 값만 복구 |
| H 값 있음 (G와 무관) | 신규 생성·재발행 건너뛰기. 필요한 경우 URL의 실제 글 확인 후 누락 시트 정보만 복구 |
| G/H 공란인데 L 값 있음 | 상태 불일치 검토. 확인 전 신규 생성 금지 |

> **주의**: G/H 공란만으로 기존 글이 없다고 단정하지 않는다. 직전 실행이 Blogger 저장 후 시트 쓰기에 실패했을 수 있으므로 `blogger-state.json`의 blogId/postId/editorUrl/게시 URL과 해당 블로그의 기존 글을 대조한다.

### 4.2 Space 실행과 저장/발행

1. **ego-browser 프로필 전환 ('순분' 프로필 사용)**:
   - Blogger 업로드 및 발행 작업 시 기본 브라우저 프로필이 아닌 **'순분' 프로필(`name: "순분"`, `profileId: "Profile 2"`, 계정 `soonboon3265@gmail.com`)** 세션을 사용하도록 TaskSpace를 생성한다.
   - ego-browser SDK 실행 시 `await profiles()` 목록에서 `name === "순분"`인 프로필 ID를 동적으로 탐색하고, 신규 TaskSpace 생성 시 `{ profileId: targetProfile.id }` 옵션을 전달한다:
     ```javascript
     const profileList = await profiles();
     const soonboonProfile = profileList.find(p => p.name === '순분' && p.id === 'Profile 2');
     if (!soonboonProfile) throw new Error('요청한 순분 / Profile 2 프로필을 확인하지 못함');
     const task = await taskSpace(spaceName, { profileId: soonboonProfile.id });
     ```
   - '순분' 프로필에 유지된 Google/Blogger 로그인 세션을 사용한다. 미등록·로그아웃·추가 인증이면 사용자 확인을 요청하고 기존 Space를 보존한다. 이름/ID 불일치를 기본 프로필이나 임의 임포트로 우회하지 않는다.
2. **독립 작업 채팅 및 Space 배정**
   - 조정자가 B 실행 기록에 후보 순서·행·키워드·폴더를 저장한다. 행·시트 상태와 신규 HTML/TXT 쌍을 대조하고 1.2절의 이미지 준비 상태를 확인한다. 기본은 키워드별 채팅 1개이되, 사용자가 채팅당 키워드 수를 지정하면 그 묶음대로 실제 채팅을 생성한다. 해당 행마다 stage B claim을 확보하고 각 채팅에 대상과 기록 경로, claim, Blogger URL, 원래 이미지 수와 슬롯별 상태·대체 방침을 넘긴다. 채팅에 근거 확인 없이 이미지 전체를 제외하라고 일괄 지시하지 않는다.
   - 각 키워드는 전용 TaskSpace 1개를 열거나 재개한다. 한 채팅에 여러 키워드를 배정한 경우에도 Space는 키워드마다 별개이며 사용자가 요청한 범위에서 병렬 진행한다. B 실행 기록에 실제 채팅 ID, `spaceId`, 시작·종료 시각, `blogId/postId`와 현재 단계를 기록한다. 채팅과 Space의 실제 동시 실행 수를 각각 확인한다.
   - **접속 Blogger URL 식별**: 시트 탭 이름(카테고리)에 대응하여 [2절 카테고리 매핑표]의 URL(`https://www.blogger.com/blog/posts/<blogId>?hl=ko`)로 이동(`await page.goto(bloggerUrl)`)한다. 사용자가 특정 URL/ID를 직접 지정한 경우 해당 주소를 우선한다.
   - 준비된 행이 3개 이상이면 환경과 사용자 지정 묶음이 허용하는 최대 3개 Space를 함께 시작한다. 인증·시트 확인 등으로 대기 중인 채팅과 Space도 해당 슬롯을 점유한다. 작업이 종료되어 슬롯이 비면 남은 활성 Space를 포함해 한도를 확인하고 다른 행을 시작한다. 한 행의 오류가 독립적인 다른 행 전체를 불필요하게 중단시키지 않도록 한다. 팝업을 기본 목록으로 복사했거나 섹션을 나눠 가져온 경우에도 같은 방식으로 배정한다.
   - 실행 환경에서 독립 채팅이나 Space 수가 제한되면 실제 오류와 가능한 슬롯 수를 기록한다. 독립 채팅 생성이 지원되지 않으면 조정자 채팅에서 지원되는 독립 Space를 최대 3개까지 사용한다. Space도 제한되면 가능한 수만큼 실행하고 빈 슬롯을 채우며 처리한다. 실제 배정 수와 사용한 실행 방식을 결과에 남긴다.
3. **단일 글 순차 처리와 공유 자원 직렬화**:
   - 글 안의 이미지 업로드 → URL 매핑 → 본문 적용 → 저장/발행은 순차 처리한다.
   - 뷰포트 변경, 스크린샷 캡처, 네이티브 파일창 등 공유 자원 구간은 직렬화한다.
   - 같은 `blogId`의 **공개 게시 요청과 실제 주소 확인은 전역으로 직렬화**한다. 조정자만 게시 순서를 승인하고 작업 채팅을 가로질러 소유자·대상 postId와 상태를 공유 실행 기록에 남긴다. 한 글의 목록 보기 URL·실제 페이지 제목/canonical 및 발행 시각을 검증하고 소유권을 반환받은 후 다음 글의 게시를 허용한다. 확인이 불명확하거나 채팅이 중단되면 기록과 Blogger의 현재 상태를 먼저 확인한다. `tools/blogger_workflow.py`의 행·폴더 claim이 블로그 전체 게시 잠금까지 자동 제공한다고 가정하지 않는다. 각 글의 조사·이미지 업로드·초안은 병렬로 계속할 수 있다. 2026-11-12에는 두 글이 같은 자동 주소를 표시하고 한 주소에서 다른 글이 열렸으므로 게시됨 표시만으로 성공 처리하지 않는다.
   - 작업 채팅은 생성·발행 직전 시트 확인을 조정자에게 요청하고 결과를 받은 뒤 실행한다. 저장·발행 확인 근거를 조정자에게 전달하면 조정자가 G/H/L 쓰기와 재조회를 담당한다. 다른 키워드 작업은 각자의 단계에서 계속 진행한다.
4. **새 글 생성 및 ID 확보**:
   - 새 글 만들기 직전 G/H/L과 키워드를 재확인한다.
   - 새 글 생성 후 글 ID가 생기면 이미지 업로드 전에 `blogger-state.json`에 즉시 기록한다. 생성 응답이 불명확하면 목록을 먼저 조회하고 새 글 버튼을 연타하지 않는다.
5. **이미지 업로드와 토큰 치환**:
   - 1.2절에서 확정한 모든 슬롯의 이미지 순서·파일명·경로·IMG ID와 실제 파일을 대조해 같은 글에 하나씩 업로드한다. 첫 업로드 성공을 확인하고 IMG ID와 실제 URL을 저장한 후 다음 파일을 처리한다.
   - 실제 URL을 HTML의 `{{BLOGGER_IMAGE_URL_IMG_01}}` 토큰에 치환하고 TXT에 반영한다. 기존 업로드 URL은 같은 글·슬롯·이미지에 해당하고 여전히 로드되는 경우에만 재사용한다. 채택 수가 양수인데 실제 업로드·검증 수가 0이거나 슬롯이 누락되면, 사용자가 해당 슬롯의 제외 또는 이미지 없는 발행을 명시적으로 허용한 경우 외에는 완료로 처리하지 않는다.
6. **초안 저장 및 G열 반영**:
   - 본문과 4.3절의 최종 메타데이터를 한 번에 적용한다. 실제 저장 표시 후 같은 편집기에 한 번 재진입하여 본문·제목·검색 설명·라벨·적용 가능한 주소, 슬롯별 이미지 URL·개수·순서·alt·캡션을 묶어서 확인한다. 이미지 목표가 미충족이면 1.2절의 미완성 처리로 남기고 G를 쓰지 않는다.
   - 로컬 `blogger-state.json`에 `draft_saved`, blogId/postId/editorUrl, 저장 확인 시각을 먼저 기록한다.
   - 조정자가 G를 `ㅇ`로 갱신하고 재조회한다. (초안 저장 요청은 여기서 완료, H/L은 비워 둠)
7. **공개 발행**:
   - 0절의 구조 검사와 저장본 확인을 마치면 같은 글을 발행한다. 미리보기는 0절의 조건에 해당할 때만 사용한다.
   - 발행 직전 H가 여전히 공란인지 재확인한다.
8. **공개 글 URL 및 H/L열 반영**:
   - 목록의 동일 postId 행에서 게시됨과 보기 링크를 확인하고, 그 공개 페이지에서 제목·canonical·이미지 로딩·메타·발행 시각을 한 번에 읽는다. 편집기/미리보기/예약 URL을 완료 주소로 쓰지 않는다.
   - 목록 URL이 다른 postId의 URL과 같거나 공개 제목·canonical이 대상 글과 다르면 충돌로 기록하고 잘못된 URL을 H/L에 쓰지 않는다. 같은 postId와 관찰된 URL·원래 시각을 보존하고, 4.3절에 따라 해당 글의 복구 범위를 확인한다. 다른 행의 가능한 작업은 계속한다.
   - 로컬 상태를 `published`로 기록하고 원래 발행 시각을 고정한다.
   - 조정자가 H에 URL, L에 날짜·시간 일련값을 함께 쓰고, G가 누락되었으면 보완한 뒤 재조회한다.
9. **종료 및 상태 기록**:
   - 요청된 브라우저 작업·검수·근거 저장을 마쳤으면 해당 Space를 종료한다.
   - `blogger-state.json` 경로: `YY_MMDD/{탭}_{키워드}/웹조사/evidence/blogger-state.json`

### 4.3 메타데이터 자율 완성 및 주소 처리

- 제목·검색 설명·사용 가능한 맞춤 퍼머링크·라벨은 **TXT의 최종 추천값 우선**이다. 최종값이 없거나 해당 항목이 비어 있으면 본문·메인 키워드·탭을 근거로 에이전트가 그 항목만 직접 작성해 입력한다. 사용자에게 후보 선택이나 작성 허락을 다시 묻지 않는다.
- 제목은 본문 범위를 정확히 요약하고, 검색 설명은 실제 입력란 길이 제한 안에서 핵심 내용을 간결하게 작성한다. 본문에 없는 사실·효과·최신 날짜를 만들어 넣지 않는다. slug는 간결한 영문 소문자·숫자·하이픈, 라벨은 주제와 일치하는 3~5개를 기본으로 한다. 후보 목록 7개 등을 새로 만들 필요는 없다.
- 입력란이 제한하는 길이·문법에 맞춰 자율 조정하고, 채택한 최종값과 `source: txt | generated | adjusted`를 TXT 및 상태에 남긴다. **TXT 파일 자체나 HTML 본문이 없는 경우**까지 새 원고 작성으로 확장하는 규칙은 아니다.
- 라벨은 현재 입력란에 값을 넣고 끝에 실제 키보드 쉼표 입력→Tab으로 확정한다. 저장 전 활성화된 버튼, 저장 후 실제 유지값을 확인한다.
- 맞춤 주소가 사용 가능하면 추천값/자율 작성값으로 설정하되 **한 번의 입력·저장과 통합 재진입 확인**으로 끝낸다. DOM fill만으로 유지되지 않았던 경로를 반복하지 않는다. 현재 UI의 입력 확정 방식을 사용하고, 저장 유지가 확인되지 않거나 기능이 없으면 Blogger 자동 주소로 진행하여 결과에 기록한다. 확인되지 않은 방법을 성공한 방식이라고 문서화하지 않는다.
- 자동 주소가 정상 공개되면 발행 성공으로 처리하고 추천값과의 차이만 비고로 남긴다. 이미 공개된 주소를 바꾸려고 초안으로 되돌리거나 재발행하지 않는다. 사용자 지정 주소가 절대 조건으로 명시된 경우에는 발행 전에 그 조건 충족 여부를 확인한다.
- 실제 주소 충돌처럼 공개 페이지가 다른 글을 여는 경우에는 게시 상태·postId·각 글의 보기 URL·제목·canonical·발행 시각을 대조한다. 기존 공개 글을 초안으로 되돌리거나 재발행하는 복구가 필요하면 그 영향과 시각 변경 가능성을 알려 사용자 승인을 받은 뒤 같은 postId로 처리한다. 새 주소의 실제 페이지와 충돌했던 다른 글을 함께 재검증하고, 새 글을 중복 생성하지 않는다. 2026-11-12 앱사용 51·52행에서 확인한 사례다.
- 요청한 글 설명이 공개 head에 있으면 완료한다. 테마 공통 설명 중복·미리보기 가젯 오류 등 글과 무관한 현상은 작업을 확장하거나 재발행할 이유가 아니다.

## 5. 코드로 처리하는 범위 (`tools/blogger_workflow.py`)

[tools/blogger_workflow.py](../tools/blogger_workflow.py)는 파일 검사, 로컬 동시 실행 잠금, 헤더 기반 열 찾기, 신규 업로드 사전 검사(`preflight`), KST 날짜 변환 및 batchUpdate 계획 작성을 지원한다.

```powershell
# 1. B 단계 작업 잠금 확보
python3.14-64.exe tools/blogger_workflow.py --no-notify claim 'YY_MMDD/_blogger_runs/RUN_ID/job.json'
# 반환된 JSON을 UTF-8 파일 도구로 claim.json에 저장한다. PowerShell 5.1의 >는 사용하지 않는다.

# 2. 시트 snapshot 사전 점검 (G/H/L 상태 판정)
python3.14-64.exe tools/blogger_workflow.py --no-notify preflight 'snapshot.json'

# 3. 초안 저장 또는 발행 이벤트 계획 생성
python3.14-64.exe tools/blogger_workflow.py --no-notify sheet-plan 'snapshot.json' 'event.json'
# 계획은 연결 Sheets 도구로 적용한다. 필요할 때만 반환 JSON을 UTF-8로 저장한다.

# 4. 작업 완료 후 잠금 해제
python3.14-64.exe tools/blogger_workflow.py --no-notify release 'YY_MMDD/_blogger_runs/RUN_ID/claim.json'
```

- `job.json` 예시 (`stage: B`):
  ```json
  {"spreadsheetId":"1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s","tab":"앱사용","row":50,"folder":"26_1107/앱사용_당근마켓 전국검색","stage":"B","owner":"실제-실행-ID"}
  ```
- `event.json` 예시:
  - 초안 저장 완료 시:
    ```json
    {"type":"draft","verified":true,"blogId":"실제ID","postId":"실제ID","savedAt":"2026-11-08T20:00:00+09:00"}
    ```
  - 공개 발행 완료 시:
    ```json
    {"type":"published","verified":true,"blogId":"실제ID","postId":"실제ID","url":"https://app.supportimes.com/entry/실제글.html","publishedAt":"2026-11-08T20:00:00+09:00"}
    ```

### 5.1 새 코드 작성 최소화

- 파일 검사·잠금·열 매핑·공란 판정·KST 변환·시트 계획은 기존 `tools/blogger_workflow.py`의 `scan/claim/preflight/sheet-plan/release`를 우선 재사용한다. 같은 로직의 임시 Python 프로그램을 매번 만들지 않는다. 실제 시트 쓰기는 연결 도구로만 수행한다.
- 브라우저는 7절의 검증된 조작을 사용한다. 업로드 반복은 파일별 스크립트 대신 하나의 순차 루프로 묶고 각 이미지 완료마다 상태를 저장한다. 코드가 길다는 이유로 안전한 중간 상태 기록을 없애지 않는다.
- 설치된 ego 스킬이 요구하는 **라운드별 UTF-8 `.mjs`**는 유지하되 한 파일에는 의미 있는 단계와 그 결과 대기를 묶는다. 단계 예: 접속·중복 확인 / 생성·ID 기록 / 이미지 업로드 루프 / 본문·메타·저장 / 재진입 통합 확인 / 발행 / 공개 확인·종료. 고정 호출 횟수를 맞추려고 중간 오류를 무시하지 않는다.
- `.session`의 과거 mutation 스크립트를 다시 실행하거나 옛 postId/Space/ref를 복사하지 않는다. 현재 상태와 새 입력으로 최소 실행 코드를 구성하고, 이미 존재하는 일반 함수만 가져다 쓴다. 이 문서는 모든 단계를 무인 실행하는 새 프로그램이 설치됐다는 뜻이 아니다.
- 일반 업로드 중에 새로운 프레임워크·래퍼·테스트·진단 스크립트를 만들지 않는다. 기존 도구의 실제 결함이 있을 때만 해당 부분을 수정한다. 단순 로컬 치환·상태 기록은 기존 실행 단계에 포함한다.

## 7. 검증된 ego-browser 조작 경로

현재 페이지에서 관찰한 요소만 사용한다. 아래 이름과 selector는 2026-11-08 성공 기록이며 UI가 다르면 해당 패널만 다시 관찰한다. 저장된 숫자 ref는 재사용하지 않는다.

| 작업 | 성공 경로·결과 조건 |
|---|---|
| 검색·대상 확인 | `input[aria-label="검색"]` 입력→Enter. URL의 q 및 갱신된 목록을 확인하고 같은 blogId/postId 대조. |
| 생성 | `새 글 작성`→편집 URL과 제목 입력란 대기→postId 로컬 기록. |
| 이미지 | `이미지 삽입`→`컴퓨터에서 업로드`→`찾아보기` 표시 대기→`setInputFiles('input[type=file]',[절대경로])`→`레이아웃 선택` 대기→`원본 크기`→`확인`. CodeMirror의 해당 파일명/실제 URL 확인, 상태 저장 후 다음 파일. |
| HTML | 가시적인 `.CodeMirror`의 `CodeMirror.getValue()` / `setValue(html); save()`. 임시 업로드 이미지 목록은 완성 HTML로 교체하여 중복 방지. |
| 제목·설명 | `input[aria-label="제목"]`, 펼친 `검색 설명 입력` 필드. 현재 입력란 제한 준수. |
| 라벨 | 펼친 `쉼표로 라벨을 구분하세요.` textbox의 현재 ref로 입력→끝에 `keyboard.type(',')`→Tab. 문자열 표시만으로 완료 판정 금지. |
| 저장 | `옵션 더보기`→`저장`→가시적인 `변경사항이 저장되었습니다.` 확인. `goto(editorUrl,{waitUntil:'domcontentloaded',timeout:30000})` 재진입 1회 후 본문·메타 통합 비교. 본문은 CRLF/LF만 정규화. |
| 발행 | H 공란 live 확인→`게시`→게시 확인 대화상자의 `확인`→같은 postId 목록 행의 `게시됨` 대기. |
| 실제 URL | 해당 목록 행의 편집 링크 hover→`보기` href를 읽어 공개 페이지 이동. slug로 URL을 추정하지 않음. |
| 완료 | 공개 제목·canonical·이미지/메타·발행 시각 묶음 확인→로컬→시트→재조회. claim 해제와 `finish({keep:[]})` 각 1회. |

퍼머링크는 4.3절의 조건부 처리다. 2026-11-08 앱사용 50행에서는 패널을 펼친 뒤 실제 `div[role="radio"][aria-label^="맞춤 퍼머링크"]`에 포커스를 주고 `Space`로 선택하여 `aria-checked="true"`를 확인한 후 활성 입력란에 슬러그를 입력했다. 저장 후 같은 편집기 재진입과 공개 주소에서 유지가 확인됐다. 입력값만 확인하지 말고 저장 후 라디오 선택과 값도 함께 확인한다. 같은 실행의 51행은 유지되지 않아 자동 주소로 진행했으므로 모든 글에서 성공한다고 가정하지 않는다. 이미지 확대 링크가 필요한 경우 실제 업로드 href를 사용한다. 기존 원고의 이미지·캡션을 이유 없이 다시 편집하지 않는다.

## 9. 토큰·코드·브라우저 왕복 절감

1. **읽기 범위:** 현재 운영은 0~5절·7~9절, 관련 가이드의 필요한 절과 설치된 ego 스킬을 읽는다. 스킬은 끝까지 읽는다. 같은 실행에서 읽은 문서·헤더 매핑은 변경이 없으면 재사용하고 archive·과거 라운드 전체를 기본 입력으로 넣지 않는다.
2. **상태 중심 재개:** tab/실제 행/keyword/폴더/헤더 매핑/Space/글 ID/이미지 URL/완료 단계/다음 단계는 `blogger-state.json` 한 곳에서 찾는다. 완료된 업로드·본문 적용은 되풀이하지 않는다. 저장 기록을 live 상태의 대체물로 쓰지는 않는다.
3. **출력 제한:** HTML·URL 전체는 파일에 보존한다. 기본 반환은 단계·ID·본문 hash/길이·이미지/alt/캡션 개수·저장 여부·불일치 목록으로 제한한다. snapshot은 새로운 UI 판단이나 오류 때만 해당 패널을 읽고, screenshot은 0절의 조건일 때만 사용한다.
4. **한 번에 확인:** 본문/메타 저장 확인은 한 번의 재진입에서, 공개 확인은 한 번 연 공개 탭에서, 시트 확인은 대상 행의 좁은 범위 한 요청에서 처리한다. 기본 미리보기·뷰포트 변경·필드별 재로드·같은 화면 반복 확인은 없다.
5. **최신성 유지:** 생성 직전, 발행 직전, 시트 쓰기 직전, 쓰기 후의 필요한 live 검사는 유지한다. 같은 시점에 쓰는 대상 셀과 키워드·수식·유효성 정보는 한 요청으로 묶는다. 이전 단계의 조회를 나중 쓰기의 직전 조회로 간주하지 않는다.
6. **실패 시 국소 복구:** 실패한 단계의 현재 상태를 한 번 관찰하고 검증된 대안으로 진행한다. 성공한 mutation을 맹목적으로 재실행하지 않는다. 인증/사용자 제어 대기는 같은 Space·글을 유지한다.
7. **기록·보고:** 성공 결과는 기존 상태를 갱신하고 새로운 발견이 있을 때만 가이드를 수정한다. 조회형은 팝업 전체 행 수·탭 수와 섹션별 배정 건수를 보고한다. 실제 시작한 채팅·Space 수와 각각의 최대 동시 실행 수, 제한으로 실행 방식이 바뀐 사유를 남긴다. 행별로 탭·행·키워드, 초안/공개 상태, 실제 URL, 원래 채택 이미지 수와 실제 업로드·제외·대체 수, IMG ID별 근거·실패 사유, G/H/L 재조회 결과와 재개 지점을 보고한다. 수치와 URL은 최종 재조회 결과와 표를 대조하고 미리보기 실시 여부도 사실대로 기록한다.

이 최적화는 불필요한 작업을 생략하는 운영 기준이다. 실행 시간·토큰 절감률은 측정 전 수치로 단정하지 않는다. 시트에서 대상을 직접 추출할 때는 [시트 팝업 조회형](../블로그작성_가이드라인/blogger-upload-request-prompt-sheet-menu.md), 대상 행이나 기존 글을 지정할 때는 [대상 직접 지정형](../블로그작성_가이드라인/blogger-upload-request-prompt.md)을 사용한다.
