# 네이버 블로그 콘텐츠 작성 가이드 (Naver Blog Content Creation Workflow)

2026-11-10 제정. 이 문서는 수집된 웹조사 결과 및 캡처 이미지를 바탕으로, 네이버 블로그 생태계에 최적화된 고전환 바이럴 마크다운(.md) 원고(본문 및 최하단 해시태그 포함)와 제목 및 이미지 배치 가이드(.txt)를 작성하고, 구글시트에 네이버 블로그 md 생성 여부(E열)를 기록하는 **네이버 블로그 콘텐츠 작성 전용 가이드라인**이다. (Blogger HTML 작성 가이드는 [BLOGGER_CONTENT_WORKFLOW.md](BLOGGER_CONTENT_WORKFLOW.md)를 참조한다.)

- 수집 기준: [웹자료수집.md](웹자료수집.md)
- 네이버 블로그 행동과학 가이드: [naver-blog-promo-guide.md](../블로그작성_가이드라인/naver-blog-promo-guide.md)
- 복사용 프롬프트: [naver-blog-content-create-prompt.md](../블로그작성_가이드라인/naver-blog-content-create-prompt.md)
- 시스템 코딩 지침: [.antigravity/rules.md](../.antigravity/rules.md), [데스크톱 가이드](AGENT_DESKTOP_GUIDE.md)

## 1. 대상과 인계 자료

1. **시작 전 확인**:
   - 현재 프로젝트 `guidelines/` 내에 `.md` 파일들이 존재하는지 확인한다. 만약 없거나 비어 있다면 잘못된 프로젝트 경로이므로 작업을 즉시 중단하고 사용자에게 알린다.
   - [.antigravity/rules.md](../.antigravity/rules.md), [데스크톱 가이드](AGENT_DESKTOP_GUIDE.md)를 먼저 확인한다.
2. **대상 구글시트**:
   - [애드센스 콘텐츠표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit)
   - 작업 식별자: `spreadsheetId + sheetId + 탭 + 실제 행 번호 + 메인 키워드 + 키워드 폴더`
   - `No.` 열의 번호를 실제 시트 행 번호로 대체하지 않는다. **사용자가 지정한 탭과 실제 행 번호**, 메인 키워드를 확인한다.
   - 행 번호가 생략된 경우 같은 폴더의 `research.json`/manifest 또는 지정 탭의 키워드 검색으로 유일한 행을 확인하며, 여러 행이 일치하면 임의 쓰기하지 않는다.
3. **로컬 작업 경로 동적 탐색 규칙 (구글시트 A열 '블로그 업로드 날짜' 기반)**:
   - 사용자 요청(예: `naver-blog-content-create-prompt.md`)에서 `[구글시트 탭 이름: {탭}]`, `[{행 번호}행: {메인 키워드}]` 형태로 대상이 주어졌을 때 다음과 같이 탐색한다:
     1) **시트 A열 조회**: 지정된 탭의 해당 행 번호에서 **A열 (`블로그 업로드 날짜` 헤더열)** 값을 확인한다.
     2) **날짜 폴더명(`YY_MMDD`) 도출**: A열의 날짜 데이터(예: `2026-11-06`, `2026. 11. 6` 등)에서 연도 끝 2자리와 월/일을 추출하여 `YY_MMDD` 형식(예: `26_1106`)으로 변환한다.
     3) **키워드 폴더 탐색**: 프로젝트 루트에서 해당 날짜 경로(`YY_MMDD\`)를 찾고, 그 하위에서 `{탭}_{메인 키워드}` 형식의 폴더(예: `26_1106\앱사용_당근마켓 채팅 걸기\`)를 찾는다.
     4) **조사 자료 및 제목·이미지 참조**: 해당 폴더 내 `웹조사\publish\*_웹조사결과.md` 및 `웹조사\` 하위의 조사 자료와 캡처 이미지들, 그리고 `웹조사\publish\{탭}_{키워드}_제목메타디스크립션.txt`를 인계받는다. `제목메타디스크립션.txt`의 [제목 후보]를 적극 참고하여 본문 제목, 제목 후보 3개 및 홈판형 제목 후보 3개를 도출하며, 캡처 이미지들을 바탕으로 본문 이미지 배치 지시 및 이미지 배치 가이드를 작성하여 `웹조사\publish\` 하위에 저장한다.
     5) **예외 처리**: 만약 A열이 공란이거나 날짜 형식이 아니어서 폴더를 특정할 수 없는 경우, 프로젝트 내의 날짜 폴더들을 탐색하되 불명확하거나 여러 개가 존재하면 임의 선택하지 않고 사용자에게 확인을 요청한다.
4. **홍보 URL (`{promotion_url}`) 참조 규칙**:
   - 네이버 블로그 .md 본문에 들어갈 전환 유도 링크는 **사용자가 프롬프트에서 직접 제공한 URL** 또는 **지정된 구글시트 행 번호의 H열(`애드센스 포스팅 링크` 헤더열)** 값을 참조한다.
   - 사용자가 직접 URL을 명시한 경우 해당 URL을 우선 적용하고, 명시하지 않은 경우 구글시트 해당 행의 H열 값을 읽어와 `{promotion_url}` 자리에 적용한다.
   - H열이 비어있거나 올바른 URL이 아닌 경우 임의의 더미 링크를 넣지 말고 사용자에게 확인을 요청한다.
5. **기본 출력물 및 저장 규칙 (토큰 절약 원칙)**:
   - **로컬 저장 파일 2종**:
     1) 본문 원고(최하단 해시태그 포함): `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_네이버블로그.md`
     2) 제목 및 이미지 배치 가이드: `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt`
   - 반드시 **UTF-8**로 저장하며, 원본 조사 Markdown·이미지·수집 기록은 원본 그대로 보존한다.
   - **채팅 응답 출력 시 토큰 절감 규칙**:
     - 원고 본문 및 제목/이미지 배치 전문을 채팅창에 일체 출력하지 않는다. (대량의 불필요한 토큰 낭비 방지)
     - 결과 보고는 최종 작업 결과 요약 테이블만 간결하게 출력한다.

## 2. 구글시트 열 구조와 기록 원칙

네이버 블로그 원고 작성이 검수 완료되면 **'네이버 블로그 md 생성 여부'(E열)**에 완료 표식(`ㅇ`)을 기록한다.

| 목적 | 실제 헤더명 | 참조 열 | 작업 시점과 동작 |
|---|---|---|---|
| 로컬 경로 탐색(날짜) | 블로그 업로드 날짜 | A | 해당 행의 날짜를 읽어 로컬 날짜 폴더(`YY_MMDD`, 예: `26_1106`) 및 키워드 폴더(`{탭}_{키워드}`) 탐색; 읽기만 수행 |
| 애드센스 HTML 작성여부 | 애드센스 블로그 작성여부 | D | Blogger HTML/TXT 생성 상태 (참고용, 네이버 블로그 작업 시 수정하지 않음) |
| **네이버 블로그 작성 완료** | **네이버 블로그 md 생성 여부** | **E** | **네이버 블로그 .md 파일 생성 및 검수 완료 후 한글 자음 `ㅇ` 기록** |
| **홍보 링크 참조** | **애드센스 포스팅 링크** | **H** | **본문 CTA에 삽입할 홍보 URL을 참조 (사용자가 직접 URL을 제공하지 않은 경우 읽어와 사용)** |
| 행 식별 | 메인 키워드 | I | 대상 행 대조 및 키워드 일치 확인; 읽기만 수행 |

1. **셀 값 및 서식 원칙**:
   - 완료 표식은 한글 자음 `ㅇ`이다. 영문 `o`, 숫자 `0`, 불리언 등으로 변경하지 않는다.
   - 공백 문자, 수식 결과 공란, FALSE, 0은 빈 셀로 취급하지 않는다.
   - 쓰기 직전에 **같은 행의 메인 키워드(I열)와 대상 셀(E열)**을 다시 읽는다. 이미 완료값(`ㅇ`)이 적혀 있다면 보존하고, 다른 값이나 수식이 있으면 덮어쓰지 않는다.
   - 필요한 빈 셀(E열)만 정확히 수정하고 저장 후 재조회한다. 다른 열, 전체 행, 서식, 시트 시간대를 변경하지 않는다.
2. **구글시트 행 잠금 정책 (행 락 배제 원칙)**:
   - 네이버 블로그 콘텐츠 작성 단계 진행 시 구글시트 행에 대한 배타 잠금(`row:...`)을 생성하지 않으며, 작업 충돌 방지 및 중복 확인은 **오직 로컬 키워드 폴더 및 파일 존재 여부**로만 관리한다.
3. **오류 격리**:
   - 시트 업데이트 실패는 글 생성 실패와 구분한다. 로컬 파일과 작업 기록을 보존하고 **시트 반영만 재시도**한다.

## 3. 중복 검사 및 순차 작성 대응

### 3.1 생성 전 중복 판정

`YY_MMDD/{탭}_{키워드}/` 하위 경로에서 `{탭}_{키워드}_네이버블로그.md` 파일이 존재하는지 확인한다.

| 발견 상태 | 처리 방침 |
|---|---|
| 파일 없음 | 신규 생성 후보 |
| 정상 크기의 결과 파일 1개 존재 | 생성 건너뛰기; 기존 경로와 상태 보고 |
| 빈 파일 또는 손상된 파일 | 내용 검토; 사용자 확인 전 자동 덮어쓰기 금지 |
| 동일 파일명이 여러 위치에 존재 | 중복본 검토; 임의 선택·삭제·새 생성 금지 |

- 파일이 이미 존재하지만 시트 E열이 누락된 경우, 재생성 없이 실제 내용을 검수한 후 시트 E열에 `ㅇ`를 기록하여 복구한다.
- 시트 E열이 이미 `ㅇ`인데 로컬 파일이 없다면 유실 또는 경로 불일치 여부를 확인하고 즉시 재생성하지 않는다.

### 3.2 단일 세션 순차 작성 및 독립 채팅 대응

- 독립 채팅 자동 생성이 지원되지 않는 단일 세션 환경(Antigravity 등)에서는 키워드별로 로컬 원고를 차례대로 고품질 작성 및 검수하고 구글시트 E열을 갱신한다.
- 각 키워드 작업 시 배정된 해당 키워드의 웹조사 자료와 이미지만 독립적으로 사용한다.

## 4. 네이버 블로그 콘텐츠 구성 및 작성 세부 지침

### 4.1 전반적인 톤앤매너 및 어조

1. **친근하고 부드러운 대화체**:
   - 독자에게 정보를 알기 쉽게 설명해주는 친근하게 대화하는 톤과 말투를 사용한다.
   - `~합니다`, `~입니다`와 같은 딱딱하고 기계적인 어조를 배제하고, `~해요`, `~어요`, `~했는데요`, `~더라구요` 등 부드럽게 공감하는 어투를 구사한다.
   - 독자의 고민, 불안, 귀찮음에 깊이 공감하며 쉽고 간결하게 작성한다.
2. **경험담 중심 서술**:
   - 해당 글에서 제공하는 정보를 직접 알아내기 위해 창작자가 겪었던 경험담 형식으로 스토리를 자연스럽게 풀어낸다.
   - 전문적인 주제를 다룰 때는 신뢰도를 높이기 위해 구체적인 통계, 연구 결과, 공식 기관의 발표 자료(보도자료, 고시 등)를 인용하여 인간만의 맥락과 경험이 돋보이게 한다.
   - 정보의 구체적인 출처와 사회적 증거를 본문에 자연스럽게 녹여낸다.
   - 지나치게 장황한 서술은 지양하고, 핵심 인사이트 위주로 간결하게 작성하여 정보 밀도를 극대화한다.

---

### 4.2 인트로 (도입부) 작성 규칙

1. **인사말 및 안부 전면 배제**:
   - "안녕하세요, 반갑습니다", "오늘 날씨가 춥네요" 등 상투적인 인사말은 완전히 건너뛴다.
2. **직접적 답 제공 및 문제/이득/손실 후킹**:
   - 시작하자마자 사람들이 이 주제에서 가장 알고 싶어 하는 핵심 질문에 대해 직접적인 답을 제공한다.
   - 해결할 수 있는 문제, 얻을 수 있는 이득, 놓쳤을 때 발생하는 손실 상황, 핵심 요약 등을 선택적으로 후킹하여 스크롤을 유도한다.
   - 특히 홍보 링크를 통해 얻을 수 있는 결정적 이득과 해결 가능한 고민을 언급하여 클릭 욕구를 자극한다.
3. **분량 엄격 준수**:
   - **첫 번째 소주제(##) 전까지의 인트로는 반드시 2개 문단으로 작성한다.**
   - **공백 제외 (순수 텍스트) 160자 이내, 공백 포함 210자 이내**의 매우 간결하고 밀도 높은 분량으로 작성한다.

---

### 4.3 CTA 링크 배치 및 빌드업 카피라이팅 규칙 (총 2회)

포스팅 전체에서 홍보 URL(`{promotion_url}`)은 **정확히 2회** 배치한다. (홍보 URL 이외의 다른 외부 URL 링크는 일체 삽입 금지)

#### 1) 1차 CTA (인트로 직후, 첫 번째 소주제 시작 전)
- 인트로 직후 해당 링크와 직접적으로 관련된 이득 및 신청/확인하지 않았을 때의 손실을 언급하는 **짧은 빌드업 문구(1~2줄)**를 작성한다.
- CTA 문구는 **단일 셀(1개) 마크다운 테이블**로 감싸서 작성한다.
- 테이블 종료 후 **반드시 빈 줄(줄바꿈 1회)을 적용한 뒤 홍보 URL(`{promotion_url}`)**을 노출한다. 앞의 이모지는 주제에 어울리는 것으로 변경한다.

```markdown
| 🚌 인천교통연수원 신규교육 일정 및 빠른 예약 바로가기👇 |
 :---: 

{promotion_url}
```

#### 2) 2차 CTA (첫 번째 ## 소주제 이후, 두 번째 소주제 시작 전)
- 첫 번째 소주제 내용이 끝난 뒤, 독자의 상황에 맞는 직접적인 문제 해결책과 즉시 얻을 수 있는 혜택을 강조하는 **차별화된 짧은 빌드업 문구(1~2줄)**를 작성한다.
- 1차 CTA와 카피라이팅 및 이모지를 다르게 구성하여 동일한 단일 셀 테이블 형식으로 배치한다.

```markdown
| 📋 2026 운수종사자 교육 대상자 확인 및 신청 페이지 바로가기👇 |
 :---: 

{promotion_url}
```

### 4.4 소주제(H2) 및 유사 헤더(Pseudo-header) 작성 규칙

1. **소주제는 오직 `##`(H2)만 사용**:
   - 모든 공식 소주제는 반드시 `##`(H2 태그)로만 작성한다.
   - **`###`, `####` 등 H3 이하 태그의 사용을 엄격히 금지한다.**
   - 각 H2에는 번호를 붙여 직관적 순서를 안내한다 (예: `## 1. 인천교통연수원 신규교육 신청 자격 및 필수 조건`).
   - 소주제명에 `how to`, `step by step` 같은 불필요한 영문 표기를 금지한다.
2. **유사 헤더(Pseudo-header)의 단일 셀 테이블화 (필수 규칙)**:
   - `#` 태그가 없는 소제목(예: `**신청 진행 순서** 📱`, `**직접 겪으며 느낀 주의사항** ✍️` 등 본문 내 볼드 텍스트로 된 중간 소제목)은 **반드시 단일 셀(1행 1열) 마크다운 테이블**로 작성한다.

```markdown
| **신청 전 꼭 챙겨야 할 필수 서류** 📑 |
| :--- |
```

### 4.5 테이블 및 불릿(Bullet) 구성 규칙

1. **본문 내 테이블 3~4개 필수 포함**:
   - 전체 본문에 **3~4개의 마크다운 테이블**이 적절한 위치에 분산 삽입되었는지 점검한다. (CTA 테이블, FAQ 테이블과 별도로 데이터/정보 전달용 본문 테이블 3~4개 포함)
   - 테이블의 각 컬럼명과 주요 항목에는 내용과 어울리는 **직관적인 이모지**를 필수 포함한다.
   - 테이블 내부 문장은 누구나 한눈에 파악할 수 있도록 간결한 요약 문장으로 작성한다.
2. **불릿과 넘버링의 적극 활용**:
   - 핵심 절차나 정보를 나열할 때는 넘버링(1., 2., 3.)과 불릿(-), 이모지를 적극적으로 활용한다.
   - 독자의 예상 질문을 파악하여 한눈에 들어오는 정보성 불릿으로 추가 제공한다.
   - 각 불릿 문장은 모바일 가독성을 위해 간결하게 작성한다 (최대 150자 이내 권장).

### 4.6 네이버 공식 스팸 기준 준수 및 진정성 있는 콘텐츠 작성 지침

네이버의 Search AI 및 C-Rank/DIA 로직은 기계적인 단순 요약 글과 스팸성 패턴을 저품질로 분류하므로, 네이버 공식 스팸 안내 기준을 철저히 준수하고 진정성 있는 경험 위주로 작성해야 한다.

1. **네이버 공식 스팸 기준 준수 (스팸성 배제 및 신뢰성 확보)**:
   - **키워드 반복·남용(어뷰징) 절대 금지**: 검색 상위 노출만을 목적으로 동일 키워드를 의도적으로 반복하거나, 부자연스럽게 키워드를 끼워 넣는 행위를 엄격히 금지한다. 자연스러운 한국어 문맥과 문장 흐름을 최우선으로 작성한다.
   - **낚시성 제목 및 허위 정보 배제**: 제목과 본문 내용이 반드시 일치해야 하며, 실제 제공하지 않는 혜택이나 자극적인 문구로 독자를 기만하는 낚시성 작성을 배제한다.
   - **기계적 스크래핑 및 저품질 템플릿 탈피**: 타 사이트 콘텐츠를 기계적으로 변형·짜깁기하거나 천편일률적인 AI 템플릿 문체를 배제하고, 독자에게 실질적인 도움을 주는 고유한 정보와 진정성을 담는다.
   - **숨겨진 텍스트 및 과도한 링크 삽입 금지**: 글자색 은닉 등 비정상적 기법은 일체 금지하며, 본문 내 외부 링크는 지정된 공식 홍보 링크({promotion_url}) 정확히 2회 외에는 절대 삽입하지 않는다.
2. **진정성 있는 경험담 및 시행착오 팁 필수 포함 (본문 내 2회 이상)**:
   - 정보를 단순히 나열하는 요약 톤을 완전히 배제하고, 창작자(나)가 공식 누리집/앱에 직접 들어가 신청·확인하는 과정에서 겪은 실제 행동 양식과 생생한 팁을 본문 내에 자연스럽게 **2회 이상** 포함한다.
   - *예시*:
     - `"제가 직접 누리집에 접속해 신청 메뉴를 눌러보니, 본인인증 팝업이 차단되어 한참을 헤맸는데요. 미리 브라우저 팝업 허용 설정을 켜두시는 것이 훨씬 수월해요."`
     - `"공식 공고문과 고시 원문을 꼼꼼히 대조해보니 놓치기 쉬운 필수 서류가 하나 더 있더라구요."`
3. **미디어(이미지) 정보의 텍스트화**:
   - 이미지는 각 `##` 소주제 직후에 배치 지시가 들어간다.
   - 첨부된 이미지에 담긴 중요한 핵심 정보(접수 일정, 지원 금액, 신청 대상 자격, 수수료, 마감일 등)는 이미지 위나 아래의 본문 텍스트 내에서 명확하게 다시 기재한다. (AI가 이미지 내용을 텍스트 형태로 쉽게 인용 및 색인할 수 있도록 구조화)
4. **독창적 맥락과 생생한 사례/시행착오**:
   - 정보 수집 수준을 넘어 본인이 직접 겪은 구체적 사례, 문제 해결 과정, 실수하기 쉬운 실패 경험(시행착오를 통해 얻은 팁), 상세한 사용 후기를 생생하게 작성한다.
   - 누구나 아는 뻔한 상식 대신 창작자만의 관점, 감정, 실질적 팁을 담아 기계적 AI 생성 글로 오인되지 않도록 한다.
5. **공식 통계 및 사회적 증거 인용**:
   - 신뢰도를 높이기 위해 구체적인 통계 수치, 공식 기관의 발표 자료, 공신력 있는 연구 결과를 인용하여 인간 창작자만의 신뢰성을 부여한다.
6. **정보 밀도 유지**:
   - 장황하고 불필요한 사설은 지양하고 핵심 인사이트 위주로 간결하게 서술한다.

### 4.7 본문 내 이미지 배치 지시 작성 규칙

- 웹조사 자료(`YY_MMDD/{탭}_{키워드}/웹조사/publish/*_웹조사결과.md` 및 이미지 파일들)에서 확인된 실제 이미지들을 바탕으로 작성한다.
- 각 `##` 소주제 직후에 해당 단계와 연관된 이미지가 삽입될 위치를 명확히 지시한다.
- 이미지 파일명만 적지 않고, **실제 화면 설명, 캡션, 그리고 이미지의 핵심 정보**를 본문 텍스트와 유기적으로 연결하여 지시한다.

```markdown
[이미지 배치 지시: `IMG_01_신규교육_접수화면.png` - 인천교통연수원 공식 접수 시스템 메인 화면 캡처 삽입. 캡션: "인천교통연수원 운수종사자 교육 신청 메뉴 화면"]
```

### 4.8 자주 묻는 질문(FAQ) 및 마무리(결론 생략) 규칙

1. **마무리(결론) 단락 전면 생략**:
   - 포스팅 본문은 **자주 묻는 질문(FAQ)까지만 작성하고 즉시 종료**한다.
   - "지금까지 ~에 대해 알아보았습니다", "도움이 되셨기를 바랍니다" 같은 상투적인 마무리/결론 문단은 절대 작성하지 않는다.
2. **FAQ 테이블 작성 규격 (단일 컬럼 테이블)**:
   - FAQ 섹션은 마지막 `##` 소주제로 구성하며, 독자가 본문 외에 추가로 가장 궁금해할 실질적인 질문 3개를 선정한다.
   - 각 질문-답변 세트는 **단일 컬럼(1열) 마크다운 테이블**로 분리하여 작성한다.
   - 질문은 첫 번째 행(볼드체), 답변은 두 번째 행에 배치하고, 세트 사이에 줄바꿈을 둔다.
3. **본문 최하단 해시태그 배치**:
   - FAQ 테이블 바로 아래에 줄바꿈 후, 본문의 최종 마무리 요소로 **해시태그(8~10개)**를 직접 기재한다.

```markdown
## 자주 묻는 질문 (FAQ) ❓

| **Q1. 교육 신청 후 일정 변경이나 취소가 당일에도 가능한가요?** |
| :--- |
| A1: 교육 당일에는 원칙적으로 변경이나 취소가 불가능해요. 일정 변경이 필요하시다면 교육 시작 최소 3일 전까지 홈페이지 마이페이지에서 취소 후 다시 원하시는 날짜로 재신청하셔야 불이익이 없어요. |

| **Q2. 모바일 스마트폰으로도 교육 신청과 수강이 가능한가요?** |
| :--- |
| A2: 네, 가능해요! 모바일 브라우저에서도 동일하게 접속하여 본인인증 후 신청하실 수 있어요. 다만 원활한 영상 시청을 위해 안정적인 Wi-Fi 환경에서 진행하시는 것을 추천해 드려요. |

| **Q3. 신규 교육 이수증은 교육 완료 즉시 바로 발급받을 수 있나요?** |
| :--- |
| A3: 교육 과정을 100% 수강하고 최종 평가를 완료하시면 즉시 시스템에서 이수증 PDF를 출력하거나 다운로드하실 수 있어요. 관할 구청이나 회사 제출용으로 바로 활용하시면 돼요. |
```

### 4.9 제목 및 이미지 배치 가이드(.txt) 작성 및 본문 최하단 해시태그 규칙

1. **제목 및 이미지 배치 텍스트 파일 생성 (필수)**:
   - 파일 경로: `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt` (UTF-8 인코딩)
   - **[절대 금지] 텍스트 파일 결과물 안에는 어떠한 볼드 표시(`**`) 특수문자도 사용하면 안 된다.**
   - **1) 제목 후보 3개**:
     - 검색 노출 및 클릭에 최적화된 자연스러운 제목 3개 (키워드 단순 나열형 스팸 절대 금지, `제목메타디스크립션.txt` 제목 후보 적극 참조).
   - **2) 홈판형 제목 후보 3개**:
     - 네이버 모바일 MY/홈판/피드형 노출에 최적화된 주목도 높은 제목 3개.
     - 독자의 호기심, 공감, 긴급성, 손실 회피 심리를 자극하는 매력적이고 직관적인 카피라이팅.
   - **3) 사용 이미지 정보 및 본문 내 추천 배치 위치**:
     - 사용할 각 캡처 이미지별 상세 정보(이미지 파일명, 화면 설명 및 주요 내용, 권장 캡션, 본문 내 추천 배치 위치(어느 ## 소주제 직후인지), 배치 이유 및 독자 가이드 설명)를 구조화하여 기록.
   - **저장 양식 예시**:
     ```text
     [네이버 블로그 제목 후보 3개]
     1. 자연스러운 검색 최적화 제목 1
     2. 자연스러운 검색 최적화 제목 2
     3. 자연스러운 검색 최적화 제목 3

     [네이버 모바일 홈판형 제목 후보 3개]
     1. 모바일 홈판 피드용 후킹형 제목 1
     2. 모바일 홈판 피드용 후킹형 제목 2
     3. 모바일 홈판 피드용 후킹형 제목 3

     [사용 이미지 정보 및 본문 내 추천 배치 위치]

        - 화면 설명: 인천교통연수원 접수 시스템 메인 화면 및 신규교육 예약 메뉴
        - 권장 캡션: 인천교통연수원 운수종사자 교육 신청 메뉴 화면
        - 본문 추천 배치 위치: ## 1. 소주제 직후 삽입
        - 배치 이유 및 설명: 사용자가 사이트 접속 후 가장 먼저 마주하는 화면으로, 예약 메뉴 위치를 시각적으로 확인시켜 진행 혼란을 방지함.

     2. 이미지 파일명: IMG_02_교육대상_확인화면.png
        - 화면 설명: 교육 대상자 자격 요건 조회 및 본인인증 팝업 화면
        - 권장 캡션: 2026 운수종사자 신규교육 대상자 확인 화면
        - 본문 추천 배치 위치: ## 2. 소주제 직후 삽입
        - 배치 이유 및 설명: 본인인증 및 대상 자격 확인 단계를 안내하여 헛걸음이나 잘못된 접수를 사전 차단함.
     ```
2. **해시태그 본문 최하단 작성 (8~10개)**:
   - 해시태그는 `{탭}_{키워드}_네이버블로그.md` 파일의 **맨 마지막 줄(FAQ 섹션 테이블 바로 다음)**에 직접 작성한다.

   - **[절대 금지] 해시태그 안에는 어떠한 볼드 표시(`**`)나 특수문자 서식도 사용하면 안 된다.**
   - **본문 최하단 해시태그 작성 양식**:
     ```markdown
     #메인키워드 #서브키워드1 #서브키워드2 #서브키워드3 #서브키워드4 #서브키워드5 #서브키워드6 #서브키워드7 #서브키워드8
     ```
