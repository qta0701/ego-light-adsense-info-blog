# 네이버 블로그 콘텐츠 작성 가이드 (Naver Blog Content Creation Workflow)

2026-11-10 제정. 이 문서는 수집된 웹조사 결과 및 캡처 이미지를 바탕으로, 네이버 블로그 생태계에 최적화된 고전환 바이럴 마크다운(.md) 원고(본문 및 최하단 해시태그 포함)와 제목 및 이미지 배치 가이드(.txt)를 작성하고, 구글시트에 네이버 블로그 md 생성 여부(E열)를 기록하는 **네이버 블로그 콘텐츠 작성 전용 가이드라인**이다. (Blogger HTML 작성 가이드는 [BLOGGER_CONTENT_WORKFLOW.md](BLOGGER_CONTENT_WORKFLOW.md)를 참조한다.)

- 수집 기준: [웹자료수집.md](웹자료수집.md)
- 네이버 블로그 행동과학 가이드: [naver-blog-promo-guide.md](../블로그작성_가이드라인/naver-blog-promo-guide.md)
- 복사용 프롬프트: [시트 팝업 조회형](../블로그작성_가이드라인/naver-blog-content-create-prompt-sheet-menu.md), [대상 직접 지정형](../블로그작성_가이드라인/naver-blog-content-create-prompt.md)
- 시스템 코딩 지침: [.antigravity/rules.md](../.antigravity/rules.md), [데스크톱 가이드](AGENT_DESKTOP_GUIDE.md)

## 1. 대상과 인계 자료

### 1.1 시작 전 확인과 시트 팝업 조회

1. 프로젝트의 `guidelines/`에 `.md` 파일이 있는지 확인한다. 없다면 프로젝트 경로 확인을 요청한다. [.antigravity/rules.md](../.antigravity/rules.md)와 [데스크톱 가이드](AGENT_DESKTOP_GUIDE.md)를 읽는다.
2. 시트 조회형에서는 설치된 `ego-browser skill`을 끝까지 읽고 공개 SDK를 사용해 조회용 TaskSpace에서 [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)를 연다. 문서 ID로 대상을 확인하고 작업 탭은 팝업에서 가져온다.
3. 상단 메뉴가 가려지지 않도록 [웹자료수집.md 8.1절](웹자료수집.md#81-팝업-조회-및-목록-저장)의 `ensureSheetsMenuWidth(page)`로 2,150px 폭을 요청하고 실제 적용 방식과 메뉴 상태를 확인한다. 상단 `🔍 키워드 조회` → `9️⃣ 네이버 블로그 md 미작성 전체 시트 조회 (팝업)`을 실행한다. 스크립트 실행이 끝나고 `전체 시트 네이버 블로그 md 미작성 목록`이 열릴 때까지 기다린다. 결과 없음, 실행 오류, 로그인·권한 요구를 구분한다. 사용자 조작이 필요하면 같은 TaskSpace에서 제어를 넘기고 확인 후 재개한다.
4. 전체 목록은 `📋 전체 기본 복사`로 가져온다. 섹션이 필요하면 대상 탭마다 분할 크기(예: `3개씩`)를 정하고 그 탭의 `📑 연달아 분리된 섹션 전체 복사`를 사용한다. 중첩 iframe에서 버튼을 찾기 어려우면 실제 화면에서 위치를 확인해 클릭한다. 복사 텍스트를 확인할 수 없으면 대화상자 snapshot 또는 iframe subtree에 표시되는 요약·섹션 텍스트박스를 읽는다. 복사 검증에 시트 셀 붙여넣기를 사용하지 않는다. 조회·복사 복구 방식은 [웹자료수집.md 8절](웹자료수집.md#8-google-sheets-스크립트-메뉴로-미작성-키워드-추출)을 참고한다.
5. 복사 결과를 `{tab, row, keyword}`로 정리하고 팝업의 탭·행 순서와 섹션 경계를 유지한다. `No.` 열과 별개인 실제 시트 행 번호를 사용한다. 전체 행·탭 수와 분할 시 섹션별 건수를 대조하고, 탭 누락·동일 탭/행 중복·키워드 충돌·건수 불일치는 다시 확인한다. 결과가 0개면 결과만 보고한다.

ego-browser 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용한다. 최소화된 같은 창은 함수가 자동으로 복원한다. 직접 CDP 복원은 `capture()`를 사용할 수 없을 때만 [웹자료수집.md 7절](웹자료수집.md#ego-taskspace-창-복원과-google-검색-결과-캡처-2026-11-12)에 따른다.

### 1.2 시트 행 검증, 로컬 경로, 홍보 URL

1. 조회형과 직접 지정형 모두 Sheets 연결 도구/API로 문서 메타데이터, 탭의 `sheetId`, 헤더를 확인한다. `블로그 업로드 날짜`, `네이버 블로그 md 생성 여부`, `애드센스 포스팅 링크`, `메인 키워드`를 헤더명으로 찾고(현재 A·E·H·I열), 탭별로 대상 행의 필요한 열을 묶어 읽는다. 조회 목록의 탭·실제 행·키워드를 현재 시트와 대조한다. 행이 이동했거나 키워드가 바뀌면 다시 조회하고 불일치가 남은 행의 사유를 기록한다. 직접 지정형에서 행 번호가 생략되면 조사 메타데이터 또는 지정 탭의 키워드 검색으로 유일한 행을 확인한다.
2. 같은 행의 `블로그 업로드 날짜`를 `YY_MMDD`로 바꾸고 `YY_MMDD/{탭}_{메인 키워드}/`를 먼저 확인한다. A열이 비었거나 날짜를 해석할 수 없거나 예상 폴더가 없거나 조사 메타데이터가 다른 행을 가리키면, 프로젝트 날짜 폴더에서 같은 이름을 찾아 `웹조사/research.json` 또는 조사 manifest의 탭·실제 행·키워드·경로를 대조한다. 다른 PC의 절대경로가 기록되어 있으면 `utils.system_utils.resolve_meta_path`로 현재 프로젝트 경로에 맞춘다. 구형 폴더는 폴더명과 조사 문서의 주제로 대조한다. 날짜가 달라도 근거가 일치하는 유일한 폴더를 사용한다. 후보가 없거나 여러 후보의 대응을 확정할 수 없으면 해당 행의 사유와 재개 지점을 남긴다.
3. 시트 조회형의 `{promotion_url}`은 같은 행의 `애드센스 포스팅 링크`(H열)에서 실제 `http://` 또는 `https://` 주소를 가져온다. 직접 지정형에서 사용자가 해당 행의 URL을 명시했으면 그 URL을 우선한다. 셀이 비었거나 유효한 주소를 확정할 수 없으면 해당 행을 보류하고 링크 확인이 필요하다고 보고한다. 확인된 다른 행은 계속 처리한다.
4. 작업 식별자는 `spreadsheetId + sheetId + 탭 + 실제 행 번호 + 메인 키워드 + 키워드 폴더`다. 조회 시각, 팝업 순서·섹션, 실제 조사 폴더의 프로젝트 상대경로와 선택 근거, 보류 사유를 작업 목록에 남긴다. 재개 시 기존 대상과 실제 파일·시트 상태를 대조한다.

### 1.3 조사 자료와 출력물

- `웹조사/publish/{탭}_{키워드}_웹조사결과.md`를 우선 읽는다. 없으면 같은 키워드의 `웹조사/publish/*_웹조사결과.md`, `웹조사/*_웹조사결과.md`, `웹조사/웹조사결과.md` 순으로 찾는다. 핵심 안내를 뒷받침할 근거가 부족하면 보완할 항목과 재개 지점을 기록한다.
- `웹조사/publish/{탭}_{키워드}_제목메타디스크립션.txt`의 `[제목 후보]` 또는 추천 제목을 본문 제목, 검색용 제목 3개, 홈판형 제목 3개에 참고한다. 제목 자료가 없으면 누락을 기록하고 확인된 웹조사 내용을 바탕으로 제목을 작성한다.
- 이미지 링크는 선택한 Markdown 파일 기준 상대경로로 읽는다. 같은 키워드의 `publish/`, 상위 `웹조사/`와 조사 문서에 명시된 하위 경로에서 발행 후보를 확인한다. `publish/`에서 사용할 수 있는 이미지가 4장 이하이거나 필요한 장면이 빠졌으면 1.4절을 적용한다.
- 결과물은 `웹조사/publish/`의 `{탭}_{키워드}_네이버블로그.md`와 `{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt`다. `publish/`가 없으면 만들고, `{탭}_{키워드}`는 확정한 폴더명 전체를 사용해 두 파일을 UTF-8로 저장한다. 원본 조사 Markdown·이미지·수집 기록을 보존한다.

### 1.4 발행용 이미지가 부족할 때

1. 같은 키워드의 `웹조사/publish/`에서 본문에 사용할 수 있는 이미지를 센다. 같은 화면의 원본과 편집본은 한 장으로 센다. 4장 이하이거나 필요한 장면이 빠졌으면 같은 키워드의 `웹조사/raw/`에서 보완 후보를 찾는다. `research.json`, `publish/index.json`, `evidence/review.json`과 캡처·출처 기록을 대조하고, 후보를 직접 열어 실제 화면·버튼·표식·확인일·가독성·개인정보 노출을 확인한다. 직접 캡처한 화면과 기존 공식 예시의 가림·자르기·표식 편집본을 활용한다. 원본 경로·출처·확인일과 편집 내역을 기록한다.
2. `raw/`를 확인한 뒤에도 사용할 이미지가 4장 이하이거나 필요한 장면을 확보하지 못했으면 ego-browser에서 해당 메인 키워드를 Google로 검색한다. 광고를 제외하고 실제로 연 공식 페이지에서 빠진 단계의 화면을 `tools/research_browser.mjs`의 `capture()`로 수집한다. 검색 화면을 사용할 때는 실제로 연 공식 결과 제목에, 단계 화면은 설명 대상 버튼이나 메뉴에 빨간 테두리·화살표 등 필요한 표식을 붙인다. 원본과 URL·확인일·캡처 근거는 `raw/`와 `evidence/` 또는 키워드별 작업 기록 폴더에 보관하고, 캡처와 표식 검수는 [웹자료수집.md 6~7절](웹자료수집.md)을 따른다.
3. 채택한 `raw/` 이미지, 새 캡처와 그 밖의 하위 폴더 이미지는 원본 복사본 또는 가림·자르기·표식 편집본을 `웹조사/publish/` 바로 아래에 저장한다. `tools/naver_workflow.py prepare`가 이미지 배치 지시의 파일명을 `publish/`와 상위 `웹조사/`에서 찾기 때문이다. 수정이 없으면 원래 이름을 쓰고, 같은 이름의 다른 파일이 있으면 구분되는 파일명을 사용한다. 편집본은 다시 열어 검수한다. 원본·기존 발행 이미지·`index.json`과 검증 기록을 보존한다.
4. 보완 이미지와 기존 발행 이미지를 실제 절차 순서로 배치한다. 본문 지시에는 최종 파일명과 캡션을 쓰고, TXT에는 원본과 실제 사용할 파일의 상대경로, 해당 H2와 배치 위치, 화면 설명·캡션·출처·확인일, 보완 채택 사유와 편집 내역을 적는다. MD 배치 지시와 TXT의 이미지 순서·파일명·캡션을 1:1로 맞춘다.
   - 콘텐츠와 제목·이미지 배치 TXT에는 이미지 이용 제한에 관한 문구를 넣지 않는다. 화면의 시점과 실제 설명에 필요한 차이는 그대로 기재한다.
5. 채택하지 않은 후보의 경로와 사유는 TXT의 `[제외·보류 이미지]`에 기록한다. 추가 조사 후에도 적합한 이미지가 부족하면 시도한 경로, 최종 채택 수, 필요한 장면과 재개 지점도 그 항목에 남긴다. 공식 근거로 핵심 절차를 설명할 수 있으면 단계 안내와 표로 해당 부분을 완성한다. 핵심 안내를 검증할 근거가 부족하면 해당 행을 보류한다.

## 2. 구글시트 열 구조와 기록 원칙

네이버 블로그 원고와 제목·이미지 배치 가이드의 검수가 끝나면 **'네이버 블로그 md 생성 여부'(E열)**에 완료 표식(`ㅇ`)을 기록한다.

| 목적 | 실제 헤더명 | 참조 열 | 작업 시점과 동작 |
|---|---|---|---|
| 로컬 경로 탐색(날짜) | 블로그 업로드 날짜 | A | 해당 행의 날짜를 읽어 로컬 날짜 폴더(`YY_MMDD`, 예: `26_1106`) 및 키워드 폴더(`{탭}_{키워드}`) 탐색; 읽기만 수행 |
| 애드센스 HTML 작성여부 | 애드센스 블로그 작성여부 | D | Blogger HTML/TXT 생성 상태 (참고용, 네이버 블로그 작업 시 수정하지 않음) |
| **네이버 블로그 작성 완료** | **네이버 블로그 md 생성 여부** | **E** | **MD/TXT 파일 쌍의 검수 완료 후 한글 자음 `ㅇ` 기록** |
| **홍보 링크 참조** | **애드센스 포스팅 링크** | **H** | **시트 조회형의 본문 CTA URL 참조. 직접 지정형의 URL 우선순위는 1.2절 적용** |
| 행 식별 | 메인 키워드 | I | 대상 행 대조 및 키워드 일치 확인; 읽기만 수행 |

1. **셀 값 및 서식 원칙**:
   - 완료 표식은 한글 자음 `ㅇ`이다. 영문 `o`, 숫자 `0`, 불리언 등으로 변경하지 않는다.
   - 공백 문자, 수식 결과 공란, FALSE, 0은 빈 셀로 취급하지 않는다.
   - 쓰기 직전에 **같은 행의 메인 키워드(I열)와 대상 셀(E열)**을 다시 읽는다. 이미 완료값(`ㅇ`)이 적혀 있다면 보존하고, 다른 값이나 수식이 있으면 덮어쓰지 않는다.
   - 시트 작성 담당자 한 명이 검수된 행을 모아 Sheets 연결 도구/API로 해당 빈 셀(E열)에만 `ㅇ`를 쓰고 같은 범위를 재조회한다.
2. **구글시트 행 잠금 정책 (행 락 배제 원칙)**:
   - 네이버 블로그 콘텐츠 작성 단계 진행 시 구글시트 행에 대한 배타 잠금(`row:...`)을 생성하지 않으며, 작업 충돌 방지 및 중복 확인은 **오직 로컬 키워드 폴더 및 파일 존재 여부**로만 관리한다.
3. **오류 격리**:
   - 시트 업데이트 실패는 글 생성 실패와 구분한다. 로컬 파일과 작업 기록을 보존하고 **시트 반영만 재시도**한다.

## 3. 중복 검사 및 순차 작성 대응

### 3.1 생성 전 중복 판정

작성 전과 시작 직전에 확정한 키워드 폴더 하위에서 MD와 제목·이미지 배치 TXT의 정확한 파일명을 확인한다.

| 발견 상태 | 처리 방침 |
|---|---|
| 두 파일 모두 없음 | E열이 비어 있고 URL과 조사 근거가 확인되면 신규 생성 |
| 정상 파일 쌍이 같은 `웹조사/publish/`에 있음 | 기존 쌍을 검수하고 경로와 상태 보고 |
| 한쪽만 있음, 빈 파일 또는 손상된 파일 | 기존 파일을 보존하고 누락·손상 부분과 재개 지점 기록 |
| 여러 위치에 같은 이름이 있거나 파일 쌍의 위치가 서로 다름 | 후보 경로와 대응 근거를 대조하고 확정할 수 없으면 보류 |

- 기존 파일 쌍이 5절의 검수를 통과하고 E열이 비어 있으면 시트 기록만 복구한다.
- E열이 이미 `ㅇ`인데 로컬 파일 쌍이 없으면 유실 또는 경로 불일치 여부를 먼저 확인한다.

### 3.2 단일 세션 순차 작성 및 독립 채팅 대응

- 기본 작업은 팝업의 탭·섹션·행 순서에 따라 현재 세션에서 진행한다. 독립 채팅은 사용자가 명시적으로 요청한 경우에 배정한다.
- 각 행에 대응하는 키워드의 웹조사 자료와 이미지를 사용한다. 경로·링크·자료 문제로 보류한 행의 사유를 남기고 확인된 다른 행을 진행한다.

## 4. 네이버 블로그 콘텐츠 구성 및 작성 세부 지침

### 4.1 전반적인 톤앤매너 및 어조

1. **친근하고 부드러운 대화체**:
   - 독자에게 정보를 알기 쉽게 설명해주는 친근하게 대화하는 톤과 말투를 사용한다.
   - `~합니다`, `~입니다`와 같은 딱딱하고 기계적인 어조를 배제하고, `~해요`, `~어요`, `~했는데요`, `~더라구요` 등 부드럽게 공감하는 어투를 구사한다.
   - 독자의 고민, 불안, 귀찮음에 깊이 공감하며 쉽고 간결하게 작성한다.
2. **경험담 중심 서술**:
   - 조사 자료에서 확인할 수 있는 화면과 행동을 따라 독자가 겪을 상황을 자연스럽게 풀어낸다. 실제 수행이 확인된 경험은 확인된 범위에서 서술한다.
   - 전문적인 주제를 다룰 때는 신뢰도를 높이기 위해 구체적인 통계, 연구 결과, 공식 기관의 발표 자료(보도자료, 고시 등)를 인용하여 인간만의 맥락과 경험이 돋보이게 한다.
   - 정보의 구체적인 출처와 사회적 증거를 본문에 자연스럽게 녹여낸다.
   - 지나치게 장황한 서술은 지양하고, 핵심 인사이트 위주로 간결하게 작성하여 정보 밀도를 극대화한다.

### 4.2 인트로 (도입부) 작성 규칙

1. **인사말 및 안부 전면 배제**:
   - "안녕하세요, 반갑습니다", "오늘 날씨가 춥네요" 등 상투적인 인사말은 완전히 건너뛴다.
2. **직접적 답 제공 및 문제/이득/손실 후킹**:
   - 시작하자마자 사람들이 이 주제에서 가장 알고 싶어 하는 핵심 질문에 대해 직접적인 답을 제공한다.
   - 해결할 수 있는 문제, 얻을 수 있는 이득, 놓쳤을 때 발생하는 손실 상황, 핵심 요약 등을 선택적으로 후킹하여 스크롤을 유도한다.
   - 특히 홍보 링크를 통해 얻을 수 있는 결정적 이득과 해결 가능한 고민을 언급하여 클릭 욕구를 자극한다.
3. **분량 엄격 준수**:
   - **첫 번째 소주제(##) 전까지의 인트로는 반드시 2개 문단으로 작성한다.**
   - **공백 제외 (순수 텍스트) 160자 이내, 공백 포함 210자 이내**의 매우 간결하고 밀도 높은 분량으로 작성한다.

### 4.3 CTA 링크 배치 및 빌드업 카피라이팅 규칙 (총 2회)

포스팅 전체에서 홍보 URL(`{promotion_url}`)은 **정확히 2회** 배치한다. (홍보 URL 이외의 다른 외부 URL 링크는 일체 삽입 금지)

#### 1) 1차 CTA (인트로 직후, 첫 번째 소주제 시작 전)
- 인트로 직후 해당 링크와 직접적으로 관련된 이득 및 신청/확인하지 않았을 때의 손실을 언급하는 **짧은 빌드업 문구(1~2줄)**를 작성한다.
- CTA 문구는 **단일 셀(1개) 마크다운 테이블**로 감싸서 작성한다.
- 테이블 종료 후 **반드시 빈 줄(줄바꿈 1회)을 적용한 뒤 홍보 URL(`{promotion_url}`)**을 노출한다. 앞의 이모지는 주제에 어울리는 것으로 변경한다.

```markdown
| 🚌 인천교통연수원 신규교육 일정 및 빠른 예약 바로가기👇 |
 :---: 

{promotion_url}
```

#### 2) 2차 CTA (첫 번째 ## 소주제 이후, 두 번째 소주제 시작 전)
- 첫 번째 소주제 내용이 끝난 뒤, 독자의 상황에 맞는 직접적인 문제 해결책과 즉시 얻을 수 있는 혜택을 강조하는 **차별화된 짧은 빌드업 문구(1~2줄)**를 작성한다.
- 1차 CTA와 카피라이팅 및 이모지를 다르게 구성하여 동일한 단일 셀 테이블 형식으로 배치한다.

```markdown
| 📋 2026 운수종사자 교육 대상자 확인 및 신청 페이지 바로가기👇 |
 :---: 

{promotion_url}
```

### 4.4 소주제(H2) 및 유사 헤더(Pseudo-header) 작성 규칙

1. **소주제는 오직 `##`(H2)만 사용**:
   - 모든 공식 소주제는 반드시 `##`(H2 태그)로만 작성한다.
   - **`###`, `####` 등 H3 이하 태그의 사용을 엄격히 금지한다.**
   - 각 H2에는 번호를 붙여 직관적 순서를 안내한다 (예: `## 1. 인천교통연수원 신규교육 신청 자격 및 필수 조건`).
   - 소주제명에 `how to`, `step by step` 같은 불필요한 영문 표기를 금지한다.
2. **유사 헤더(Pseudo-header)의 단일 셀 테이블화 (필수 규칙)**:
   - `#` 태그가 없는 소제목(예: `**신청 진행 순서** 📱`, `**직접 겪으며 느낀 주의사항** ✍️` 등 본문 내 볼드 텍스트로 된 중간 소제목)은 **반드시 단일 셀(1행 1열) 마크다운 테이블**로 작성한다.

```markdown
| **신청 전 꼭 챙겨야 할 필수 서류** 📑 |
| :--- |
```

---

### 4.5 테이블 및 불릿(Bullet) 구성 규칙

1. **본문 내 테이블 3~4개 필수 포함**:
   - 전체 본문에 **3~4개의 마크다운 테이블**이 적절한 위치에 분산 삽입되었는지 점검한다. (CTA 테이블, FAQ 테이블과 별도로 데이터/정보 전달용 본문 테이블 3~4개 포함)
   - 테이블의 각 컬럼명과 주요 항목에는 내용과 어울리는 **직관적인 이모지**를 필수 포함한다.
   - 테이블 내부 문장은 누구나 한눈에 파악할 수 있도록 간결한 요약 문장으로 작성한다.
2. **불릿과 넘버링의 적극 활용**:
   - 핵심 절차나 정보를 나열할 때는 넘버링(1., 2., 3.)과 불릿(-), 이모지를 적극적으로 활용한다.
   - 독자의 예상 질문을 파악하여 한눈에 들어오는 정보성 불릿으로 추가 제공한다.
   - 각 불릿 문장은 모바일 가독성을 위해 간결하게 작성한다 (최대 150자 이내 권장).

### 4.6 네이버 공식 스팸 기준 준수 및 진정성 있는 콘텐츠 작성 지침

네이버의 Search AI 및 C-Rank/DIA 로직은 기계적인 단순 요약 글과 스팸성 패턴을 저품질로 분류하므로, 네이버 공식 스팸 안내 기준을 철저히 준수하고 진정성 있는 경험 위주로 작성해야 한다.

1. **네이버 공식 스팸 기준 준수 (스팸성 배제 및 신뢰성 확보)**:
   - **키워드 반복·남용(어뷰징) 절대 금지**: 검색 상위 노출만을 목적으로 동일 키워드를 의도적으로 반복하거나, 부자연스럽게 키워드를 끼워 넣는 행위를 엄격히 금지한다. 자연스러운 한국어 문맥과 문장 흐름을 최우선으로 작성한다.
   - **낚시성 제목 및 허위 정보 배제**: 제목과 본문 내용이 반드시 일치해야 하며, 실제 제공하지 않는 혜택이나 자극적인 문구로 독자를 기만하는 낚시성 작성을 배제한다.
   - **기계적 스크래핑 및 저품질 템플릿 탈피**: 타 사이트 콘텐츠를 기계적으로 변형·짜깁기하거나 천편일률적인 AI 템플릿 문체를 배제하고, 독자에게 실질적인 도움을 주는 고유한 정보와 진정성을 담는다.
   - **숨겨진 텍스트 및 과도한 링크 삽입 금지**: 글자색 은닉 등 비정상적 기법은 일체 금지하며, 본문 내 외부 링크는 지정된 공식 홍보 링크({promotion_url}) 정확히 2회 외에는 절대 삽입하지 않는다.
2. **근거가 있는 경험 또는 시행착오 팁 (본문 내 2회 이상)**:
   - 공식 누리집·앱에서 실제로 확인한 행동이나 조사 자료로 설명할 수 있는 실수 방지 팁을 본문에 자연스럽게 **2회 이상** 포함한다. 예문의 1인칭 서술은 해당 경험이 확인된 경우에 적용한다.
   - *예시*:
     - `"제가 직접 누리집에 접속해 신청 메뉴를 눌러보니, 본인인증 팝업이 차단되어 한참을 헤맸는데요. 미리 브라우저 팝업 허용 설정을 켜두시는 것이 훨씬 수월해요."`
     - `"공식 공고문과 고시 원문을 꼼꼼히 대조해보니 놓치기 쉬운 필수 서류가 하나 더 있더라구요."`
3. **미디어(이미지) 정보의 텍스트화**:
   - 채택한 이미지는 관련 `##` 소주제 직후에 배치 지시를 넣는다.
   - 첨부된 이미지에 담긴 중요한 핵심 정보(접수 일정, 지원 금액, 신청 대상 자격, 수수료, 마감일 등)는 이미지 위나 아래의 본문 텍스트 내에서 명확하게 다시 기재한다. (AI가 이미지 내용을 텍스트 형태로 쉽게 인용 및 색인할 수 있도록 구조화)
4. **독창적 맥락과 생생한 사례/시행착오**:
   - 구체적 사례와 문제 해결 과정은 조사에서 확인된 조건·행동·결과로 설명한다.
   - 누구나 아는 뻔한 상식 대신 창작자만의 관점, 감정, 실질적 팁을 담아 기계적 AI 생성 글로 오인되지 않도록 한다.
5. **공식 통계 및 사회적 증거 인용**:
   - 신뢰도를 높이기 위해 구체적인 통계 수치, 공식 기관의 발표 자료, 공신력 있는 연구 결과를 인용하여 인간 창작자만의 신뢰성을 부여한다.
6. **정보 밀도 유지**:
   - 장황하고 불필요한 사설은 지양하고 핵심 인사이트 위주로 간결하게 서술한다.

### 4.7 본문 내 이미지 배치 지시 작성 규칙

- 웹조사 자료(`YY_MMDD/{탭}_{키워드}/웹조사/publish/*_웹조사결과.md` 및 이미지 파일들)에서 확인된 실제 이미지들을 바탕으로 작성한다.
- 채택한 이미지는 해당 단계의 `##` 소주제 직후에 배치한다. 보완 이미지의 저장과 기록은 1.4절을 적용한다.
- 이미지 파일명만 적지 않고, **실제 화면 설명, 캡션, 그리고 이미지의 핵심 정보**를 본문 텍스트와 유기적으로 연결하여 지시한다.

```markdown
[이미지 배치 지시: `IMG_01_신규교육_접수화면.png` - 인천교통연수원 공식 접수 시스템 메인 화면 캡처 삽입. 캡션: "인천교통연수원 운수종사자 교육 신청 메뉴 화면"]
```

### 4.8 자주 묻는 질문(FAQ) 및 마무리(결론 생략) 규칙

1. **마무리(결론) 단락 전면 생략**:
   - 포스팅 본문은 **자주 묻는 질문(FAQ)까지만 작성하고 즉시 종료**한다.
   - "지금까지 ~에 대해 알아보았습니다", "도움이 되셨기를 바랍니다" 같은 상투적인 마무리/결론 문단은 절대 작성하지 않는다.
2. **FAQ 테이블 작성 규격 (단일 컬럼 테이블)**:
   - FAQ 섹션은 마지막 `##` 소주제로 구성하며, 독자가 본문 외에 추가로 가장 궁금해할 실질적인 질문 3개를 선정한다.
   - 각 질문-답변 세트는 **단일 컬럼(1열) 마크다운 테이블**로 분리하여 작성한다.
   - 질문은 첫 번째 행(볼드체), 답변은 두 번째 행에 배치하고, 세트 사이에 줄바꿈을 둔다.
3. **본문 최하단 해시태그 배치**:
   - FAQ 테이블 바로 아래에 줄바꿈 후, 본문의 최종 마무리 요소로 **해시태그(8~10개)**를 직접 기재한다.

```markdown
## 자주 묻는 질문 (FAQ) ❓

| **Q1. 교육 신청 후 일정 변경이나 취소가 당일에도 가능한가요?** |
| :--- |
| A1: 교육 당일에는 원칙적으로 변경이나 취소가 불가능해요. 일정 변경이 필요하시다면 교육 시작 최소 3일 전까지 홈페이지 마이페이지에서 취소 후 다시 원하시는 날짜로 재신청하셔야 불이익이 없어요. |

| **Q2. 모바일 스마트폰으로도 교육 신청과 수강이 가능한가요?** |
| :--- |
| A2: 네, 가능해요! 모바일 브라우저에서도 동일하게 접속하여 본인인증 후 신청하실 수 있어요. 다만 원활한 영상 시청을 위해 안정적인 Wi-Fi 환경에서 진행하시는 것을 추천해 드려요. |

| **Q3. 신규 교육 이수증은 교육 완료 즉시 바로 발급받을 수 있나요?** |
| :--- |
| A3: 교육 과정을 100% 수강하고 최종 평가를 완료하시면 즉시 시스템에서 이수증 PDF를 출력하거나 다운로드하실 수 있어요. 관할 구청이나 회사 제출용으로 바로 활용하시면 돼요. |
```

### 4.9 제목 및 이미지 배치 가이드(.txt) 작성 및 본문 최하단 해시태그 규칙

1. **제목 및 이미지 배치 텍스트 파일 생성 (필수)**:
   - 파일 경로: `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt` (UTF-8 인코딩)
   - **[절대 금지] 텍스트 파일 결과물 안에는 어떠한 볼드 표시(`**`) 특수문자도 사용하면 안 된다.**
   - **1) 제목 후보 3개**:
     - 검색 노출 및 클릭에 최적화된 자연스러운 제목 3개 (키워드 단순 나열형 스팸 절대 금지, `제목메타디스크립션.txt` 제목 후보 적극 참조).
   - **2) 홈판형 제목 후보 3개**:
     - 네이버 모바일 MY/홈판/피드형 노출에 최적화된 주목도 높은 제목 3개.
     - 독자의 호기심, 공감, 긴급성, 손실 회피 심리를 자극하는 매력적이고 직관적인 카피라이팅.
   - **3) 사용 이미지 정보 및 본문 내 추천 배치 위치**:
     - 채택 순서대로 이미지 파일명과 실제 파일 상대경로, 화면 설명, 권장 캡션, 해당 `##` 소주제와 배치 이유를 기록한다. 보완 이미지에는 1.4절의 원본 정보와 채택·편집 내역을 추가한다.
   - **저장 양식 예시**:
     ```text
     [네이버 블로그 제목 후보 3개]
     1. 자연스러운 검색 최적화 제목 1
     2. 자연스러운 검색 최적화 제목 2
     3. 자연스러운 검색 최적화 제목 3

     [네이버 모바일 홈판형 제목 후보 3개]
     1. 모바일 홈판 피드용 후킹형 제목 1
     2. 모바일 홈판 피드용 후킹형 제목 2
     3. 모바일 홈판 피드용 후킹형 제목 3

     [사용 이미지 정보 및 본문 내 추천 배치 위치]
     1. 이미지 파일명: IMG_01_신규교육_접수화면.png
        - 화면 설명: 인천교통연수원 접수 시스템 메인 화면 및 신규교육 예약 메뉴
        - 권장 캡션: 인천교통연수원 운수종사자 교육 신청 메뉴 화면
        - 본문 추천 배치 위치: ## 1. 소주제 직후 삽입
        - 배치 이유 및 설명: 사용자가 사이트 접속 후 가장 먼저 마주하는 화면으로, 예약 메뉴 위치를 시각적으로 확인시켜 진행 혼란을 방지함.

     2. 이미지 파일명: IMG_02_교육대상_확인화면.png

        - 권장 캡션: 2026 운수종사자 신규교육 대상자 확인 화면

     ```
2. **해시태그 본문 최하단 작성 (8~10개)**:
   - 해시태그는 `{탭}_{키워드}_네이버블로그.md` 파일의 **맨 마지막 줄(FAQ 섹션 테이블 바로 다음)**에 직접 작성한다.

## 5. 최종 산출물 및 작업 완료 체크리스트

1. **로컬 파일 2종 저장 (publish 폴더)**:
   - 네이버 블로그 원고(본문 및 최하단 해시태그 포함): `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_네이버블로그.md` (UTF-8 인코딩)
   - 제목 및 이미지 배치 가이드: `YY_MMDD/{탭}_{키워드}/웹조사/publish/{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt` (UTF-8 인코딩)
2. **검수와 구글시트 갱신**
   - 두 파일의 UTF-8과 본문 근거, 인트로 분량, CTA 위치와 URL 2회, H2·정보용 표·FAQ·해시태그, TXT 제목 후보 3개씩을 확인한다. MD 이미지 지시와 TXT의 순서·파일명·캡션이 맞는지, 파일이 실제로 열리는지 확인한다.
   - 2절에 따라 검수된 행의 키워드와 E열을 다시 확인하고 빈 E열에 `ㅇ`를 기록한 뒤 재조회한다. 시트 기록만 실패하면 로컬 파일을 사용해 시트 기록부터 재개한다.
3. **결과 보고**
   - 팝업 전체 행·탭 수와 섹션별 처리 건수를 요약한다. 행별로 탭·실제 행·키워드, 로컬 파일 2종 경로, 본문 줄 수·H2·표·채택 이미지 수, 검수·E열 재조회 결과를 표에 담는다. 보류·실패한 행에는 사유와 재개 지점을 적는다. 채팅에는 결과 요약표를 제공한다.
