# 키워드별 웹자료수집 가이드

구글 검색 의도 확인부터 출처·이미지 수집, 블로그용 결과물, 시트 완료 처리까지 적용한다. 브라우저 도구 일반 지침은 [크롬에이전트 활용법](크롬에이전트_활용법.md)을 참고한다.

2026-11-07 개정: 사용자 최신 요청을 우선한다. 본문·이미지·출처 수는 별도 절대 조건이 없는 한 권장값이며, **핵심 검색 의도를 근거와 활용 가능한 자료로 해결했는지**를 완료 기준으로 삼는다. 섹션별 독립 채팅 병렬 실행은 6.3절, 추가 조사와 완료 판단은 6.8절을 따른다. 이 문서의 정책과 현재 도구의 고정 검사는 구분하며, 구현 차이는 6.6절에 명시한다.

## 5. 키워드별 웹조사·안내 이미지 저장 표준 (2026-11-06 보완)

### 작업 대상과 저장 구조

- 프로젝트의 `guidelines/`에 가이드라인 Markdown이 존재하는지 먼저 확인한다. 없으면 작업을 중단하고 프로젝트 경로 문제를 알린다.
- 요청에 루트의 `AGENT_DESKTOP_GUIDE.md`가 적혀 있어도 이 프로젝트의 실제 파일은 `guidelines/AGENT_DESKTOP_GUIDE.md`다. 실제 경로를 확인해 읽는다. 다른 필수 가이드가 없으면 경로를 확인하고 누락을 알린다.
- 사용자가 탭·행·키워드를 지정했으면 전체 미작업 행 탐색은 생략한다. 지정 행과 헤더·수정 대상 셀만 확인한다.
- 사용자 한국 시간 기준 `YY_MMDD/{탭}_{키워드}/웹조사/` 아래에 저장한다. 신규 작업의 하위 폴더·분량·실행 기준은 **6절을 우선 적용**한다. 기존 결과물은 이동하거나 덮어쓰지 않는다.
- 원본·편집본을 구분하고 URL·뷰포트·스크롤 위치·표식 좌표를 기록한다.

### 검색·사실 확인

1. 각 메인 키워드를 Google에서 먼저 검색하고 광고를 제외한 상위 결과로 검색 의도를 파악한다.
2. AI 개요·블로그는 탐색 단서로 취급한다. 핵심 조건·연락처·기간은 공식 원문에서 확인한다.
3. 문서는 검색 의도 → 현재 확인된 방법 → 단계별 경로 → 예외·FAQ → 출처·확인 한계 순으로 정리한다.
4. 이벤트 게시일·참여 마감일·지급일·발표일을 구분한다. 과거 무료 보도자료가 있어도 현재 프로모션 URL을 직접 열어 확인한다.
5. 옛 검색 URL과 공식 페이지의 현재 연결 대상이 다르면 현재 공식 연결을 우선한다. 이번에는 코레일이 경찰민원24로 연결했고, 과거 `mini_open`은 오류 화면이었다. 이 사례를 영구 현황으로 고정하지 않는다.

### 캡처·편집·검수

- 모바일 웹이 있으면 실제 모바일 너비로 렌더링한다. PC 화면을 좁게 잘라 앱 화면으로 표시하지 않는다. 앱·모바일 웹·PC 웹을 구분한다.
- 로그인·인증·가입·설치가 필요하면 해당 화면이나 버튼까지만 수집한다. 기존 로그인 상태라도 조사 목적으로 실제 신청·결제·이벤트 참여를 완료하지 않는다.
- 빨간 테두리·화살표·번호와 단계 설명은 원본을 보존한 별도 편집본에 추가한다. 설명은 화면 밖 여백에 배치해 버튼·원문을 가리지 않는다.
- 표식은 실제 요소보다 넉넉한 여백과 굵은 선을 사용하되 옆의 문구나 다른 버튼을 가리지 않는다. 이미지 안에는 URL을 넣지 않는다. 화면에 원래 보이는 주소·검색 결과의 URL도 발행본에서 가리고, 실제 URL은 Markdown과 evidence에 보존한다.
- 모바일 사이트의 겹침·잘림은 기록하고, 전체 조건 설명은 실제 PC 렌더링을 보충한다. 사이트 UI를 임의로 고쳐 정상 화면처럼 촬영하지 않는다.
- 실제 이미지 MIME/포맷을 확인한다. WEBP 응답은 확장자를 맞추고 필요하면 원본과 변환 PNG를 함께 보존한다. 이미지 URL도 기록한다.
- 발행 이미지 전체를 직접 열고 원본과 대조해 팝업 잔존, 화면 밖 표식, 글자 겹침, 잘못된 단계·출처, URL·개인정보 노출을 검수한다. 팝업 닫힘·검색 결과 갱신을 기다리고 촬영한다.

### 시트 완료 처리

- 키워드별 조사 문서와 이미지 저장·검수 및 6.8절의 완료 판단을 마친 뒤에만 완료 셀을 갱신한다. 권장 분량·장수의 차이만으로 완료를 보류하거나 완료 처리하지 않는다.
- 수정 직전에 지정 행의 키워드, A·C열의 빈 값, 데이터 유효성 규칙을 다시 읽는다. 값이 생겼으면 덮어쓰지 않는다.
- 사용자 지시대로 A열에 실제 날짜값으로 완료일, C열에 한글 자음 **`ㅇ`**를 쓴다. 영문 `o`나 숫자 `0`으로 대체하지 않는다.
- Sheets API 날짜는 숫자 일련값과 `yyyy-mm-dd` 표시 형식을 사용한다. 기존 형식이 맞으면 유지하고 다른 열·서식을 변경하지 않는다.
- A열의 이름이 블로그 업로드 날짜여도 이 작업에서는 사용자가 요청한 조사 완료 표시다. 실제 블로그 발행 완료로 보고하지 않는다.
- 저장 후 날짜·기호·키워드를 재조회하고 가능하면 Google 렌더링 화면에서도 검수한다.
- A·C 중 하나만 이미 채워져 있으면 그 셀은 보존하고, 키워드와 완료 상태가 확인된 경우에만 나머지 빈 셀을 반영한다. 기존 값이 요청과 다르면 차이를 보고한다. 쓰기 결과가 불명확하면 재조회 후 누락된 셀만 재시도한다.

## 6. 키워드별 병렬 조사와 블로그 재사용 표준 v4 (2026-11-07)

사용자가 섹션별 독립 채팅 n개를 요청하면 해당 프로젝트에 실제 새 채팅 n개를 배정한다. 채팅 내부의 키워드별 Space 병렬 탐색과 구별한다. 본문·이미지·출처 수는 아래 권장값으로 계획하고, 콘텐츠의 충분성과 사용자 허용 범위에 따라 조정 사유를 기록한다.

### 6.1 적용 범위와 개선 배경

2026-11-06의 카카오톡 무료 이모티콘·코레일 분실물 센터 조사에서는 한 Space에서 순차 탐색했고, 코레일 안내 이미지가 14장까지 늘어났다. 다음 조사부터는 **키워드별 Space 분리, 3개씩 병렬 탐색(사용자 별도 요청시 그에 따름), 필요한 단계만 선별 촬영, 결정론적 후처리 코드**를 적용한다. 복합 검색어도 시트 행은 하나이며 그 Space 안에서 두 검색어를 순서대로 조사한다. 기존 조사 결과·이미지·시트 완료값은 보존한다. 병렬화는 대기 시간을 줄이는 방법이며, 토큰 절감은 출력 제한·중복 제거·코드 후처리에서 얻는다. 절감률은 측정 전 단정하지 않는다.

이 절은 사용자가 ego-browser 웹조사를 요청한 작업의 실행 기준이다. 다른 절의 고정 디버깅 포트·쿠키 복사·다른 브라우저 연결 예시는 이 작업에 적용하지 않는다. 실행 시 설치된 ego-browser 스킬을 읽고 지원 API를 사용한다. 캡차·추가 인증·사용자 제어 상태에서는 우회하거나 새 Space를 만들지 않고 해당 작업을 보류한다.

### 6.2 복합 검색어 분리, 결과물 분량과 이미지 예산

메인 키워드에 서로 다른 질문이 함께 있으면 에이전트가 검색 의도를 판별해 **35자 이하의 자연스러운 검색어 2개**로 나눈다. 예: `당근마켓 카드 결제 구매방법 수수료 및 정산` → `당근마켓 카드 결제 구매 방법` / `당근마켓 판매 수수료 정산`. 서로 같은 뜻의 문구만 바꿔 두 번 검색하지 않는다. `multiIntent: true`, `queries: [검색어1, 검색어2]`를 작업 설정에 넣는다. 단일 의도는 원래 키워드 하나를 검색한다. 검색어를 분리해도 폴더·본문·시트 완료 처리는 원래 메인 키워드와 행 하나에 묶인다.

Google 검색 결과에서는 광고를 제외하고 **실제로 열 공식 결과 링크의 화면 위치**를 캡처한다. 검색어당 검색 결과 안내 이미지 1장을 `role: search`로 기록하고 빨간 화살표·넉넉한 사각 테두리·번호를 붙인다. 상단 광고나 AI 요약을 공식 결과로 표시하지 않는다. 검색 결과 캡처 뒤 실제 링크를 열어 관련성과 최종 URL을 재확인한다. 원래 결과가 무관하거나 오래됐으면 서비스명·공식 도메인·기능명 등으로 추가 검색하며 같은 Space를 유지한다. 채택한 추가 검색어와 실제 연 링크도 기록하고, 추가 검색 화면을 사용하면 그 링크에 표식한다. URL은 이미지 캡션에 넣지 않고 Markdown에 검색 화면 URL과 연 공식 URL을 각각 적는다.

| 항목 | 단일 의도 권장값 | 복합 의도 권장값 |
|---|---|---|
| 본문 | 2,000~4,500자 내외 | 필요하면 최대 7,500자 내외, 두 질문을 모두 답함 |
| 출처 | 1~2개, 공식 1개 이상 | 1~2개, 두 질문을 뒷받침하고 공식 1개 이상 |
| 검색 결과 안내 | 검색어당 1장 | 검색어별 1장, 기본 총 2장 |
| 단계 안내 | 4~8장 | 4~8장, 필요한 경로를 선별 |
| 참고 이미지 | 0~3장 | 0~3장 |
| 발행용·원본 각각의 총수 | 기본 최대 12장씩 | 기본 최대 12장씩, 필수 경로 사유 기록 시 최대 14장씩 |

검색 결과도 이미지 예산에 포함한다. 위 수치는 사용자가 유동적 적용을 허용한 경우 절대적인 합격선·중단선이 아니다. 단순한 주제는 짧은 본문이나 적은 이미지로도 핵심 의도가 해결되면 완료할 수 있다. 복잡한 주제는 추가 출처·분량·이미지가 필요하면 사용자 허용 범위 안에서 조정하고 `evidence/review.json`에 실제 수, 조정 이유와 콘텐츠가 충분한 근거를 남긴다. 이 파일은 에이전트가 작성하는 검수 기록이며 현재 도구가 자동 생성·판정하는 필드는 아니다. 복합 의도의 기본 예외는 기존 `exceptionReason`에도 기록한다. 사용자가 절대 상한·하한을 별도로 지정했다면 그 지시를 따른다.

이미지 수를 채우기 위해 같은 화면이나 의미 없는 장면을 늘리지 않는다. 로그인 전 단계가 적다는 이유만으로 실패 처리하지 말고, 공식 설명·접근 가능한 안내 화면·유의미한 참고 이미지를 보강해 발행 가능성을 판단한다. 같은 이미지의 WEBP/PNG 변환본·가림 복사본은 서로 다른 자료로 세지 않는다. 최종 보고에는 실제 원본 파일 수와 발행 이미지 수를 적고, 복사본이 포함되면 별도로 설명한다.

본문 권장 구성:

1. **바로 답하기**: 대상, 가능한 방법, 확인일을 간결하게 정리한다.
2. **검색 의도와 준비물**: 사용자가 해결하려는 문제와 계정·앱·운행정보 등 사전 조건.
3. **단계별 방법**: 단계 번호, 실제 버튼 이름, 예상 결과, 해당 이미지 번호. 순위·정책 주제는 실제 자료의 확인·해석 과정으로 구성한다.
4. **조건·예외·실패 대처**: 이용기간·제외대상·모바일/PC 차이·로그인 중단 지점. 확인하지 못한 내용은 구분한다.
5. **FAQ**: 필요한 질문만 다루고 본문의 단순 반복을 피한다.
6. **작성자 메모**: 유효기간 재확인 항목, 이미지 삽입 위치, 재배포 조건 등 필요한 편집 메모.

각 사실 근처에 `[S1]` 같은 출처 ID를 넣는다. 광고 문구·상위 블로그 문장·공식 본문을 길게 복사하지 않고 직접 확인한 사실을 재서술한다. 저작권 있는 이미지의 출처 표기만으로 재사용 허가를 가정하지 않는다. 분량을 맞추려고 확인되지 않은 조건이나 불필요한 설명을 추가하지 않는다.

### 6.3 키워드별 독립 Space와 동시 실행

- **섹션별 채팅 배정**: 사용자가 독립 채팅 병렬 실행을 요청하면 먼저 현재 환경의 프로젝트·채팅 생성 도구를 확인한다. Codex에서는 제공되는 `list_projects`로 현재 프로젝트를 식별하고 `create_thread`로 섹션 수만큼 같은 프로젝트의 로컬 채팅을 만든다. 별도 요청이 없으면 worktree를 만들지 않는다. 다른 환경에서는 실제 독립 채팅을 만드는 동등 기능이 있을 때만 사용한다. Space·탭·하위 에이전트만 나누고 새 채팅을 만들었다고 보고하지 않는다.
- **실행 전 확인**: 조사 시작 전 모든 섹션의 채팅 생성·동시 실행 가능 여부를 확인한다. 각 채팅의 최초 프롬프트에 시작 전 확인 절차와 전체 작업 조건을 포함한다. 여러 섹션인데 독립 채팅 n개를 병렬로 실행할 수 없거나 일부 생성에 실패하면 조사·캡처·시트 수정을 시작하지 않고 사용자에게 알린다. 먼저 생성된 채팅도 사전 점검에서 멈춰야 하며 한 채팅의 순차 처리로 대체하지 않는다.
- **공유 시작 신호**: 채팅 생성은 즉시 실행을 시작할 수 있으므로 조정자는 먼저 `YY_MMDD/_research_runs/{dispatchId}/dispatch.json` 같은 배정 기록을 `pending`으로 만든다. 각 최초 프롬프트에 이 경로와 “전체 섹션이 준비되어 `ready`가 될 때까지 사전 점검만 수행” 조건을 넣는다. 모든 채팅 ID·배정이 확인되면 `ready`, 일부 실패하면 `blocked`와 이유를 기록한다. 각 채팅은 조사 전에 이 값을 확인한다. 이 파일은 에이전트 간 시작 조정용 기록이며 현재 `startBatch`가 자동 처리하는 기능은 아니다.
- **할당과 관찰**: 섹션별 `threadId`, 탭·행·키워드·저장 폴더를 대응시켜 기록한다. 각 채팅에는 배정 행만 읽고 쓰도록 하며, 원래 사용자 요청의 가이드·날짜·이미지·재개·완료 조건을 빠짐없이 전달한다. 조정자는 제공되는 `wait_threads` 등으로 실제 시작과 최종 결과를 확인한다. 생성 요청 성공만으로 조사 완료를 보고하지 않는다.
- **채팅 내부 병렬 탐색**: 요청한 동시 수를 적용한다. 예시 요청처럼 동시 3개라면 각 섹션 채팅에서 `concurrency: 3`으로 최대 세 키워드의 Space를 병렬 탐색한다. 현재 도구의 미지정 기본값은 2, 최대는 3이다. n개 채팅의 세 Space는 최대 3n개이므로 섹션별 독립 실행 수와 전체 실행 수를 구분한다. 채팅 내부의 탐색은 비동기 작업 풀로 처리할 수 있다.
- 각 키워드는 고유한 `spaceName`과 `spaceId`, 저장 폴더를 가진다. `탭/행/키워드 → Space → 폴더` 대응을 manifest와 `evidence/browser.json`에 저장한다. 다른 키워드의 탭을 공유하지 않는다.
- `startBatch`는 미완료 작업 중 최대 동시 수만큼 Google 검색을 병렬로 시작한다. 첫 묶음을 조사·검수·종료한 뒤 같은 starter를 실행하여 다음 묶음을 시작한다. 검색 시작만으로 조사가 완료되는 것은 아니다.
- 이미 `search_ready`인 작업은 초기 검색을 무조건 반복하지 않는다. 추가 검색이 필요하면 에이전트가 같은 Space에서 조사한다. 연결 오류·인증·제어권 전환의 `blocked` 기록을 무조건 재시도하지 않고 원인을 구분한다. 일반 연결·렌더링 오류는 상태를 확인해 복구하고, 인증·사용자 제어는 사용자 처리를 기다린다. 원인을 해결한 뒤 같은 ID로 재개하며 상태를 지워 새 Space를 만들지 않는다.
- 같은 페이지의 이동 → 대기 → 읽기 → 촬영은 순서대로 수행한다. 서로 다른 Space의 탐색·본문 추출은 병렬화한다. 캡처·뷰포트 변경은 공용 `capture()` 큐로 직렬화하며, 캡처 중 해당 페이지를 다른 코드가 이동시키지 않는다. 현재 큐는 **같은 Node 프로세스 안에서만** 공유된다. 다중 채팅은 공용 캡처 워커 또는 프로세스 간 잠금으로 캡처를 조정하고, 그 기능이 없으면 캡처 구간이 겹치지 않게 작업 시간을 분리한다. 탐색은 계속 병렬로 진행한다.
- 공유 도구·가이드는 채팅별로 동시에 수정하지 않는다. 필요한 개선은 한 담당자가 현재 파일을 다시 읽고 통합한다. 결과 폴더와 manifest는 섹션별로 분리한다.
- 키워드별 결과가 검수되면 6.6절의 일반 또는 에이전트 대안 검수 경로에 맞춰 해당 Space를 한 번만 종료한다. 실패·사용자 제어 대기 중에는 완료 종료하지 않는다. 시트 쓰기는 한 조정자에게 맡기거나 섹션별로 겹치지 않는 행의 담당자를 정해 정확한 셀만 처리한다. 두 방식에서 같은 행을 중복 수정하지 않는다.

### 6.4 저장 구조와 재사용 규칙

```text
YY_MMDD/
  _research_runs/{runId}/
    manifest.json                 # 대상·폴더·Space 이름·동시 수
    start.mjs                     # 재실행 가능한 시작점
  {탭}_{키워드}/웹조사/
    research.json                 # 본문·출처·이미지 선택·검수 상태
    validation.json               # 파일 해시·분량 검사·시트 반영 준비 상태
    raw/                          # 실제 화면/공식 참고 이미지 원본
    evidence/                     # 검색어별 후보·캡처 메타데이터·브라우저 상태
    publish/
      {탭}_{키워드}_웹조사결과.md
      01_search.png                # 광고 제외, 실제 열 링크 표시
      02_guide.png ... 09_guide.png
      10_reference.png            # 필요한 경우만; 실제 순서에 따라 번호 부여
      index.json                 # 도구가 생성한 파일 목록
```

신규 형식의 결과물은 `publish/`에 모은다. Markdown의 이미지 링크는 같은 폴더의 상대경로이고, 이미지 순서·설명·출처가 함께 제공된다. 기존 평면 폴더 결과는 상위 `웹조사/`의 Markdown·이미지도 함께 참조하며 자동 이관하지 않는다. 원본과 근거는 재검증용으로 보존한다. 후속 HTML 작성·Blogger 업로드 인계는 별도 [BLOGGER_CONTENT_WORKFLOW.md](BLOGGER_CONTENT_WORKFLOW.md)를 따른다.

`*_웹조사결과.md`에는 사용한 캡처·다운로드 이미지마다 **원본 파일명, 발행 파일명, 배치 순서·삽입 위치, 무엇을 설명하는지, 출처명, 화면의 실제 URL 또는 다운로드 원본 URL, 확인일**을 표나 목록으로 기록한다. 검색 이미지는 Google 검색 URL과 실제 연 공식 결과 URL을 함께 적는다. 출처별 대표 URL 외에도 정보를 확인한 관련 URL은 `sources[].relatedUrls` 또는 Markdown의 해당 출처 아래에 남긴다. 수집했으나 채택하지 않은 자료도 evidence에 파일명·URL·미사용 이유를 기록한다. 자동 Markdown이 이 정보를 모두 출력한다고 가정하지 않는다.

**표식 실패 시에도 로컬 결과를 남긴다.** 좌표·편집·검증 오류가 나면 먼저 `raw/`와 `evidence/`를 보존하고, `publish/{탭}_{키워드}_웹조사결과.md`에 현재까지의 본문·출처·이미지 활용 목록·실패 이유를 저장한다. `pack`이 실패해 Markdown을 만들지 못하면 에이전트가 이 파일을 직접 작성하고 사용할 수 있는 무표식 캡처·다운로드 이미지도 함께 제공한다. 기존 파일은 보존하고 재개 과정의 변경 내역을 기록한다. 표식 없는 자료의 완료 여부는 사용자가 허용한 대안과 6.8절의 콘텐츠 검수로 판단하며, 성공한 표식 이미지처럼 보고하지 않는다.

경로는 저장소 기준 상대경로로 기록한다. 프로젝트를 옮겨도 새 루트를 기준으로 해석한다. 현재 저장소에 `utils.system_utils.resolve_meta_path`가 없으므로 새 파이프라인은 과거 PC의 절대경로를 추측해 변환하지 않고 거부한다. 기존 절대경로 메타데이터를 이관할 때는 별도 변환 작업이 필요하다.

### 6.5 코드·API와 에이전트의 역할

| 처리 | 담당 | 토큰 사용을 줄이는 방식 |
|---|---|---|
| 지정 행 확인·A/C 업데이트 | 연결된 Google Sheets 도구/API | 헤더·대상 행만 조회, 정확한 필드만 일괄 변경 |
| 날짜·폴더·중복 검사·manifest | `tools/research_pipeline.py init` | KST 날짜 자동 적용, 기존 결과 덮어쓰기 차단 |
| 독립 Space 생성·Google 검색 시작 | `tools/research_browser.mjs startBatch` | 동시 수 제한, 상태 저장, 상위 후보 5개만 출력 |
| 검색 의도·광고 제외·공식 출처 선정 | 에이전트 | 후보 URL·제목 중심으로 판단, 필요한 페이지 2~5개 확인 |
| 버튼 선택·최신 조건 확인 | 에이전트 + ego-browser | 관찰한 UI만 조작; DOM 전체를 반복 출력하지 않음 |
| 원본·좌표·URL 기록 | `capture()` | 화면과 표식 좌표를 같이 저장, CSS 선택자 유일성·뷰포트 검사 |
| 사실 요약·단계 구성·FAQ | 에이전트 | `research.json`을 한 번 구조화하여 후속 재사용 |
| 빨간 표식·번호·캡션·Markdown | `pack` | Pillow로 원본에 별도 안내 편집, 복잡한 이미지 생성 모델 불필요 |
| 파일·상한·해시 검사 | `validate`, `pack`, `finishJob` | 중복 이미지·잘못된 좌표·검수 뒤 변경을 탐지 |
| 실제 이미지 가독성·출처 대응 | 에이전트의 시각 검수 | 자동 통과로 대체하지 않음 |

브라우저에는 페이지에서 보이는 정보와 DOM을 사용하는 공개 UI 경로를 적용한다. 숨은 내부 API·쿠키·토큰을 추출하지 않는다. Sheets 쓰기는 연결된 정식 도구/API를 사용한다. 공식 이미지 다운로드가 막히면 접근 가능한 화면 캡처를 사용하고 다운로드 실패를 기록한다.

스냅샷 전문은 로컬에 저장하고 모델에는 필요한 구간(보통 500~1,500자)만 읽힌다. 시작 도구의 검색어별 본문 저장은 5,000자, 후보 저장은 10개, 콘솔 출력은 검색어별 후보 5개로 제한된다. 결정에 필요한 내용이 잘렸으면 해당 절만 추가 추출한다. 완료 후 동일 페이지를 반복 조회하거나 전체 파일을 재출력하지 않는다.

### 6.6 실행 방법과 데이터 계약

Python 3.14와 Pillow, 설치된 ego-browser CLI가 필요하다. 아래 예제 JSON은 이미 완료한 행을 담은 **형식 예시**이므로 복사하여 새로운 대상에 맞춘다. 기존 결과가 있는 날짜·키워드로 `init`하면 의도적으로 중단된다. 재개할 때는 기존 manifest를 사용한다.

```powershell
# 프로젝트 루트에서 실행. research_jobs.json은 예제를 복사하여 새 대상 입력.
python3.14-64.exe tools/research_pipeline.py init research_jobs.json

# 출력된 manifest와 같은 폴더의 start.mjs 경로를 사용한다.
$researchEntry = (Resolve-Path 'YY_MMDD/_research_runs/RUN_ID/start.mjs').Path.Replace('\','/')
ego-browser nodejs -e "await import('file:///$researchEntry')"
```

복합 의도 작업에는 예제 작업 항목에 `"multiIntent": true, "queries": ["당근마켓 카드 결제 구매 방법", "당근마켓 판매 수수료 정산"]`를 추가한다. `tools/research_jobs.example.json`의 `date`를 생략하면 오늘 한국 날짜를 쓴다. 시작 파일에는 절대경로나 인증정보가 없다. `start.lock`이 남았다면 해당 실행이 종료되었는지 먼저 확인하고 그 실행 폴더의 잠금 파일만 해제한다. 실행 중인 작업의 잠금을 제거하지 않는다.

탐색을 진행하는 `.mjs`에서는 `taskSpace(spaceId)`로 기존 Space를 선택하고 `capture(page, folder, name, selectors, viewport)`를 호출한다. `folder`는 manifest의 프로젝트 상대경로, `selectors`는 현재 화면에서 확인한 유일한 CSS 선택자다. 기본 뷰포트는 390×844이며 PC 경로는 명시적으로 별도 크기를 지정한다. 결과 `{file, boxes, url}`을 다음 형식에 연결한다. `boxes`는 원본 PNG 좌표 `[x,y,width,height]`다. CDP 이후에는 이전 snapshot ref를 재사용하지 않는다. 캡처 도우미는 원본 12장에서 중단하며, 복합 의도와 `exceptionReason`이 기록되었으면 14장까지 허용한다.

```json
{
  "body": "출처 ID를 포함한 조사 본문: 권장 2000~4500자 내외, 주제와 사용자 허용 범위에 따라 조정",
  "sources": [
    {"id":"S1","title":"공식 이용 안내","url":"https://example.com/guide","official":true,"checkedAt":"2026-11-06"}
  ],
  "images": [
    {"role":"guide","file":"raw/01_entry.png","sourceId":"S1",
     "caption":"1단계. 확인된 메뉴를 선택합니다.","alt":"메뉴 위치를 표시한 첫 화면","boxes":[[20,70,120,50]]}
  ],
  "exceptionReason":"",
  "visualReviewed":false
}
```

위 JSON은 **필드 설명용 일부 예시**다. `init`이 만든 `keyword/row/tab/date`와 기존 메타데이터는 보존한다. 권장 출처·검색 결과·안내 이미지와 본문을 채우되 조정 사유를 기록한다. 참고 이미지는 `role: reference`로 기록하고 원본 UI 표식을 요구하지 않는다. 검색 결과 이미지는 `role: search`, `query: 해당 검색어`, `boxes: 실제 열 결과 링크의 좌표`로 기록한다. `official` 여부와 사실 정확성은 코드가 판정할 수 없으므로 에이전트가 확인한다.

**현재 구현과 정책의 차이**: `research_pipeline.py`는 여전히 본문 3,500~5,500자(복합 최대 7,500자), 출처 1~2개, 안내 4~8장 등 고정 검사를 하며 `limits` 임의 변경을 거부한다. `research_browser.mjs`의 캡처 상한도 기본 12장·복합 사유 14장이다. `exceptionReason`만으로 짧은 본문·적은 이미지·무표식 대안이 허용되지는 않는다. 독립 채팅 생성·프로세스 간 캡처 잠금·시트 쓰기도 이 두 파일이 자동 수행하지 않는다.

새 정책으로 실행할 때 이 차이를 사전 확인한다. 도구를 개선한다면 명시적인 조정 사유와 에이전트 검수 기록을 받아 수량 경고와 파일·출처·좌표·해시 오류를 구분하도록 최소 수정·검증한다. 본문을 반복해 늘리거나 같은 화면을 복제해 옛 검사에 맞추지 않는다. 검증 파일의 `errors`·해시·`ready_for_sheet`를 수동 조작해 통과시키지 않는다. 정책을 문서에 추가한 것만으로 도구 구현도 바뀌었다고 보고하지 않는다.

도구 지원이 아직 없으면 `validate`의 실제 오류를 보존하고 **에이전트 대안 검수**를 적용할 수 있다. 수량 기준 차이와 사용자 허용 무표식 대안만 남았는지 구분하고, 경로·파일 열림·이미지 해상도·출처와 실제 URL·중복·사용한 표식 좌표·개인정보 가림·최종 파일 해시를 별도로 검사한다. 실제 파일·근거 오류는 해결해야 하며 수량 예외로 덮지 않는다. `publish`를 별도 작성·편집한 뒤 모든 발행 파일을 검수하고 `evidence/review.json`에 검사 결과, 원래 도구 오류, 조정 사유, 파일별 해시, 콘텐츠 완료 판단을 기록한다. 이 검수를 마치면 6.8절에 따라 완료와 시트 반영을 판단할 수 있으며 **구 정책의 수량 검사만 실패했다는 이유로 보류하지 않는다**. 보고에는 “도구 자동 검증: 구 기준으로 미통과 / 에이전트 대안 검수: 완료”처럼 구분한다.

```powershell
python3.14-64.exe tools/research_pipeline.py validate 'YY_MMDD/탭_키워드/웹조사'
python3.14-64.exe tools/research_pipeline.py pack 'YY_MMDD/탭_키워드/웹조사'
```

기본 검사를 통과한 첫 `pack`은 `needs_visual_review` 상태다. 생성된 이미지 전체를 열어 표식·한글·팝업·민감정보·출처·단계 연결을 검수하고, 필요하면 좌표/설명을 수정한다. 에이전트가 검수를 완료한 뒤 `visualReviewed: true`로 바꾸고 다시 `pack`한다. 이는 사용자 승인 절차가 아니다. 이후 `ready_for_sheet`와 6.8절의 콘텐츠 완료 판단을 확인하고 `finishJob(folder)`로 Space를 정리한다. 검수 뒤 파일 변경은 다시 검사·검수해야 한다. 에이전트 대안 검수 경로에서는 `finishJob`가 성공한 것으로 기록하지 않는다. 그 경로에서 검수·결과 보존을 마쳤으면 설치된 ego 스킬의 지원 API로 해당 Space를 한 번 종료하고 실제 종료 결과를 기록한다.

`finishJob`는 시트를 수정하지 않는다. 지정된 쓰기 담당자가 대상 행의 키워드 셀(현재 시트는 I열, 다른 시트는 지정된 열)과 A/C 빈 값을 다시 읽고, 검수가 끝난 키워드의 빈 A열에 한국 날짜값·빈 C열에 `ㅇ`를 반영한 뒤 재조회한다. 이미 채워진 셀은 덮어쓰지 않고 차이를 기록한다. 오류·미완료 키워드는 완료 표시하지 않는다. 시트 쓰기 실패 시 로컬 결과와 재시도할 셀을 보고하며 재조사하지 않는다.

### 6.8 미완료 키워드 추가 조사와 완료 판단

1. **중단 원인을 구분한다.** 자료 무관·오래된 검색 결과·다운로드 실패·일시적 페이지 오류·이미지 부족·표식 실패·로그인 경계·미공개 자료를 구별하고 기존 근거와 Space를 확인한다. 한 번 수집에 실패했다는 이유만으로 최종 미완료 보고로 끝내지 않는다.
2. **가능한 대안을 직접 탐색한다.** 같은 Space에서 검색어를 바꾸고 다른 Google 결과, 공식 도움말·FAQ·정책·작품 페이지·공개 통계·접근 가능한 PC/모바일 웹을 확인한다. 다운로드 실패는 화면 캡처로, 앱 진입 제한은 공식 안내로 보완한다. 같은 오류를 반복하기보다 새 근거·화면을 얻는 경로를 선택하고 시도와 결과를 evidence에 남긴다. 로그인·가입·설치·추가 인증을 실제로 진행하거나 제한을 우회하지 않는다.
3. **의도에 맞는 결과로 구성한다.** 원래 표현과 정확히 같은 공식 표가 없어도 현재 제공 범위, 검증 가능한 최신 자료, 사용자가 확인하는 방법과 한계가 핵심 의도에 답하면 유의미한 결과가 될 수 있다. 월간 미공개 자료를 주간 순위로 확정하거나, 한국에서 본 영화 전체를 한국 제작 영화 순위로, 전체 차트를 오리지널 전용 차트로 바꾸어 쓰지 않는다. 대안과 요청 범위의 차이를 제목·본문·이미지 설명에 분명히 적는다.
4. **완료는 에이전트가 근거로 판단한다.** 핵심 질문에 답하고, 공식 근거·관련 URL과 활용 가능한 실제 이미지가 있으며, 본문·이미지별 활용 정보가 저장되고, 사실·표식 또는 허용 대안·가독성·개인정보·최종 파일을 검수했으면 완료할 수 있다. 권장 분량·장수와 다르거나 원래 명칭의 공식 자료가 없다는 이유만으로 보류하지 않는다. 수량 충족·`ready_for_sheet`만으로 핵심 답변이 없는 결과를 완료하지도 않는다. 조정 사유, 한계와 발행 가능한 이유를 `evidence/review.json`에 기록하고 6.6절의 검증 계약과 정합성을 확인한다.
5. **실제 차단만 남으면 보존하고 보고한다.** 유용한 대안을 조사해도 핵심 질문을 해결하지 못하거나 사용자 조작·아직 공개되지 않은 정보가 꼭 필요하면 가능한 Markdown·이미지·실패 근거를 모두 저장한다. 해당 행은 완료 표시하지 않고 구체적인 차단 원인, 이미 시도한 대안, 재개 지점을 보고한다. 사용자 조작이 해결되면 기존 Space에서 남은 단계만 재개한다. 존재하지 않는 자료를 만들거나 무한 재시도하지 않는다.

최종 보고는 키워드별 결과 경로, 실제 원본·발행 이미지 수, 조정·표식 실패·조사 한계, A/C 반영 값과 재조회 결과를 간단히 정리한다. 독립 채팅 생성 결과와 각 섹션의 완료·미완료도 함께 확인한다.

## 7. agent-desktop 보완과 본문 출력 예산 (2026-11-06)

### 캡처 배율 대응 (2026-11-06)

`tools/research_browser.mjs`의 `capture()`는 요청 뷰포트와 `innerWidth/innerHeight`가 다르다는 이유만으로 중단하지 않는다. Google 사이트 배율 110%, 모바일의 넓은 레이아웃, OS 배율 등에 대응해 실제 `visualViewport`와 스크롤바 크기를 읽고, 반환된 PNG의 IHDR 크기로 CSS 좌표를 PNG 픽셀 좌표로 변환한다. PNG와 표시 영역의 종횡비는 스크롤바 및 반올림 오차 범위에서 일치해야 한다.

반환값의 `boxes`를 그대로 `research.json`에 넣는다. `evidence/NAME.json`의 `targets`는 변환 전 DOM CSS 좌표이고 `boxes`는 편집용 PNG 좌표다. 새 메타데이터에는 `coordinateSpace: png-pixels`, `requestedViewport`, `visual`, `scrollbar`, `rasterViewport`, `pixelSize`, `pixelScale`이 함께 저장된다. 기존 원본·메타데이터는 자동 변환하거나 덮어쓰지 않는다.

로그인 QR이 포함된 원본은 로컬 근거로 보존하고, 발행 이미지 항목의 `redactions: [[x,y,width,height]]`에 PNG 좌표를 기록한다. `pack`은 해당 영역을 가리고 ‘로그인 QR 가림’이라고 표시한다. 가림 좌표도 이미지 경계 검사를 받으며, 최종 이미지를 열어 QR이 남지 않았는지 확인한다. 출처 항목의 `relatedUrls: [{title,url}]`는 탐색 중 확인한 추가 공식 근거 링크를 Markdown의 해당 출처 아래에 함께 출력한다.

Windows 이미지 뷰어가 검수한 파일을 사용 중일 수 있으므로 재포장은 기존 파일을 먼저 삭제하지 않는다. 동일한 PNG·Markdown은 그대로 보존하고, 변경 파일은 임시 파일로 저장한 뒤 교체한다. 새 출력 생성 후에만 이전 index의 미사용 관리 파일을 정리한다. 실제로 내용이 바뀐 파일의 교체가 잠겼다면 오류를 해결한 뒤 같은 결과를 재개한다.

캡처 전후 URL·스크롤·뷰포트·배율·요소 위치가 바뀌면 저장 전에 중단한다. 선택자 중복·화면 밖 요소·최소화·사용자 제어권 전환도 계속 오류로 처리한다. 이 변경은 인증이나 화면 접근 제한을 해제하지 않는다. 검증: `node tools/test_research_browser.mjs`와 기존 두 Google 검색 Space에서 실제 캡처 및 표식 시각 검수.

### 병렬 작업 시작과 이미지 검수 보완 (2026-11-07)

- 병렬 검색을 시작하기 전에 ego 창의 최소화 여부와 캡처 가능 상태를 확인한다. 최소화 오류가 나면 기존 Space와 원본·초안을 보존하고 창을 복원한 뒤 같은 Space에서 실제 캡처를 다시 확인한다. 창 활성화만으로 캡처 가능하다고 단정하지 않는다. 해결되지 않으면 미완료로 기록하고 시트에 완료 표시를 하지 않는다.
- 검색 결과의 공식 링크를 실제로 열어 확인하고 검색 시점과 자료의 집계 기간·지역·분류를 본문과 이미지 설명에서 구분한다. 월간 순위를 요청받았더라도 주간 차트를 월간 확정치로 표현하지 않는다.
- 발행 이미지마다 빨간 테두리·번호·화살표가 대상과 핵심 문구를 가리지 않는지 실제 크기로 확인한다. 겉보기만 다른 동일 화면으로 필수 단계 수를 채우지 않는다. 계정 정보 등은 발행본에서 가리고, 가림 내용과 표시 문구가 일치하는지 확인한다. 현재 기본 `pack`의 가림 문구는 QR 전용이므로 다른 대상을 가릴 때 해당 문구를 그대로 사용하지 않는다. 별도 편집이 필요하면 원본을 보존하고 최종 파일의 검증 및 시각 검수를 다시 수행한다.
- 본문 분량은 이미지 목록·출처 목록을 제외하고 별도로 확인한다. 현재 자동 검사는 `body`의 문자 수를 사용하므로 `body` 안에 목록까지 넣으면 포함될 수 있다. 자동 통과만으로 본문 분량을 확정하지 않는다. 이미지별 기록에는 화면의 실제 URL을 기재하며 검색 결과 화면에는 실제 검색 URL을 기록한다.

이 절은 6절의 폴더·본문·이미지·검수·시트 완료 기준을 유지하면서 탐색 중 출력만 줄인다. [agent-desktop 통합 가이드](AGENT_DESKTOP_GUIDE.md)에 설치·API 예제·검증 근거를 정리했다.

1. **웹은 ego SDK로 진행**한다. 공개 기사만 필요한 별도 작업은 ca-rust `read/extract`를 선택할 수 있다. `agent-desktop`은 Windows 앱·네이티브 창을 읽어야 할 때만 추가한다. 파일 업로드는 ego의 `setInputFiles/waitForFileChooser`를 우선한다.
2. **선택한 영역만 출력**한다. `observePage(page, folder, name, {selector, maxChars:1500, linksLimit:5})`를 호출하면 렌더링된 선택 영역 본문을 `evidence/NAME.page.json`에 보존하고 지정 구간·출처만 반환한다. selector는 관찰한 유일한 DOM 영역이어야 한다.
3. **반복 출력과 재방문을 줄인다.** 동일 URL·제목·영역·본문·저장 링크이면 `unchanged:true`로 본문 출력 0자를 반환한다. 더 필요한 절은 `readPageEvidence(folder,name,{offset:1500,maxChars:1000})`로 로컬에서 읽는다. 후자는 과거 자료임을 표시하며 최신 UI 확인·조작을 대신하지 않는다.
4. **본문 예산과 최종 결과물을 구분**한다. 탐색 중 1,500자 제한과 발행용 본문 권장 2,000~4,500자 내외는 별개다. 최종 분량은 6.2절과 콘텐츠 충분성 기준을 따른다. 잘린 조건을 누락하지 않도록 `hasMore`와 추가 구간을 확인한다. 일반 텍스트 자료에 snapshot·screenshot을 매번 함께 요청하지 않는다.
5. **네이티브 조작 범위를 명시**한다. agent-desktop의 앱/창 선택은 ego TaskSpace 선택과 별개다. skeleton도 큰 JSON이 될 수 있으므로 로컬에 저장하고 필요한 노드만 읽는다. 여러 창이면 실제 `window-id`를 지정하고 새 ref로 조작한다. OS 전체 트리를 키워드마다 반복 수집하지 않는다.
6. **측정 범위를 명시**한다. 실제 ego GitHub README 7,256자에서 본문 1,500자만 반환하고 동일 재관찰 본문 0자, 추가 500자 로컬 읽기를 확인했다. 첫 envelope는 2,289자였다. 토큰 과금·전체 조사 시간·사이트별 절감률은 측정하지 않았다.
7. **인증·제어 상태를 유지**한다. 네이티브 도구를 사용해 캡차·2FA·브라우저 권한 프롬프트·사용자 제어 전환을 우회하지 않는다. 기존 Space 재개·실패 기록·완료 검수 규칙을 그대로 따른다.

검증: `node tools/test_research_observe.mjs`. 경로 이탈, 출력 상한, 내용 중복, URL 변경, 로컬 구간 읽기, 숨은 링크·모호한 선택자 처리를 검사한다. 기존 `test_research_browser.mjs` 및 Python 6개 검사도 통과했다.
