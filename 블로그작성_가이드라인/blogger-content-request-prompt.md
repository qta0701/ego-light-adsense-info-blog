# 웹조사·캡처 기반 Blogger 콘텐츠 요청 프롬프트

2026-11-07 갱신. A는 키워드별 독립 채팅에서 콘텐츠 작성 후 시트 작성 완료 기록, B는 ego-browser Space 최대 3개 병렬로 업로드·저장/발행 후 시트 기록을 수행한다. 운영 기준은 [분리된 Blogger 가이드](../guidelines/BLOGGER_CONTENT_WORKFLOW.md)다. 입력칸을 실제 값으로 바꾸어 복사한다. A를 실행했다는 이유로 B까지 실행하지 않는다.

## A. HTML 콘텐츠와 제목·메타 TXT 작성

```text
.antigravity/rules.md를 참고해줘. 먼저 현재 프로젝트의 guidelines/에 .md 파일들이 있는지 확인하고, 없다면 잘못된 프로젝트 경로이므로 작업을 진행하지 말고 알려줘.
guidelines/CHROME_AGENTS_USAGE_GUIDE.md, guidelines/크롬에이전트_활용법.md, guidelines/AGENT_DESKTOP_GUIDE.md를 먼저 읽고, guidelines/BLOGGER_CONTENT_WORKFLOW.md, guidelines/웹자료수집.md, 블로그작성_가이드라인/html-content-guide.md, 블로그작성_가이드라인/html-style-guide.md를 참고해줘.
실행·중복 검사·독립 채팅·시트 기록은 BLOGGER_CONTENT_WORKFLOW.md를, 콘텐츠는 html-content-guide.md 0절을 기존 범용 템플릿보다 우선 적용해줘.

[대상 목록: 키워드별 YY_MMDD/{탭}_{키워드}/ 로컬 경로 + 시트 탭 + 실제 행 번호. 여러 개면 한 줄에 하나씩]
[선택 입력: 독자층, 강조할 내용, 사용할 서브키워드, 지정된 블로그/광고 설정]

대상 구글시트는 https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit 이야. URL의 gid를 모든 작업의 탭으로 고정하지 말고 대상 목록의 탭을 사용해줘.
각 폴더의 자료를 바탕으로 Blogger용 가이드 콘텐츠를 작성하고, 검수 완료 후 시트의 애드센스 블로그 작성여부 열에 ㅇ를 기록해줘. 실제 Blogger 업로드는 이번 A의 범위에 포함하지 않아.

0. 중복 방지와 독립 채팅 배정
- 시작 전에 각 YY_MMDD/{탭}_{키워드}/ 전체 하위 경로를 검색해서 정확한 {탭}_{키워드}_html콘텐츠.html과 {탭}_{키워드}_제목메타디스크립션.txt가 이미 있는지 확인해줘. 루트·웹조사·publish·구형 outputs도 포함해줘. tools/blogger_workflow.py의 scan을 활용해줘.
- 정상 파일 쌍이 있으면 새로 생성하지 말고 건너뛰어줘. 한 파일만 있거나 빈 파일·서로 다른 위치의 쌍·중복 사본이면 검토 대상으로 분리하고 자동 덮어쓰기·재생성을 하지 마. 두 파일 모두 없는 대상만 신규 생성 후보야.
- 시트 metadata·헤더·실제 행 키워드를 확인해줘. D열이라고 고정하지 말고 '애드센스 블로그 작성여부' 헤더로 찾아줘. D가 이미 ㅇ인데 파일이 없으면 먼저 유실·다른 경로 여부를 확인해줘. 행이 생략되면 research.json/manifest나 지정 탭의 키워드 검색으로 유일한 행을 확인하고, 모호하면 임의 쓰기하지 마.
- 신규 생성할 키워드 n개마다 같은 프로젝트에 실제 독립 채팅 n개를 만들어 병렬로 진행해줘. 하위 에이전트나 Space만 나누는 것으로 대체하지 마. 각 채팅은 배정된 한 키워드만 작성해줘.
- BLOGGER_CONTENT_WORKFLOW.md 3.2절에 따라 dispatch.json을 pending으로 만들고, 모든 채팅이 준비되어 ready가 되기 전에는 파일 생성을 시작하지 마. 채팅 생성 실패나 독립 채팅 병렬 실행이 불가능하면 blocked를 기록하고 알려줘. 일부만 시작하거나 한 채팅의 순차 작성으로 대체하지 마.
- 조정자는 tools/blogger_workflow.py claim으로 각 키워드 폴더·시트 행을 예약하고, 작업자에게 실제 채팅 ID와 범위·원래 요구사항·가이드·dispatch 경로를 전달해줘. 시작 직전 파일 부재를 재확인해줘. 시트와 공유 문서의 수정은 조정자 한 명이 담당해줘.

1. 입력 확인
- publish/{탭}_{키워드}_웹조사결과.md를 우선 읽어줘. 없으면 같은 키워드의 publish/*_웹조사결과.md, 상위 웹조사/*_웹조사결과.md 또는 웹조사/웹조사결과.md를 확인해줘.
- Markdown의 이미지 링크를 문서 위치 기준으로 해석하고, 이미지가 없으면 같은 키워드의 publish/와 상위 웹조사/를 확인해줘. 명시된 하위 경로도 확인하되 다른 날짜·키워드의 동명 이미지로 대체하지 마.
- research.json, publish/index.json, evidence/review.json, 이미지 출처 기록이 있으면 보조 근거로 참고해줘. 없어도 기존 자료로 진행할 수 있는지 판단해줘.
- 대상이 여러 개라 어느 폴더인지 확정할 수 없으면 임의로 고르지 말고 대상을 확인해줘. 여러 키워드를 명시적으로 요청했다면 각각 별도의 결과물을 작성해줘.

2. 이미지와 본문 흐름 설계
- 사용할 후보 이미지를 직접 열어 실제 화면, 버튼명, 표식, 캡션, 확인일, 가독성, 개인정보 가림과 재사용 조건을 확인해줘. 파일명만 보고 설명을 만들지 마.
- 이미지의 실제 화면 전환과 조사문의 권장 순서를 바탕으로 개요와 이미지 배치안을 먼저 만들어줘. 질문에 대한 답 → 준비 조건 → 단계별 행동과 확인 결과 → 예외/FAQ 순서로 독자가 따라갈 수 있게 써줘.
- 기본적으로 단계 제목 → 행동을 설명하는 문단 → 관련 이미지와 캡션 → 결과/주의점 → 다음 단계 순서로 구성해줘. 광고나 CTA는 설명과 해당 이미지 사이에 끼우지 마.
- 이미지의 파일번호·화면 내부 표식 번호·본문 절차 번호를 구분해줘. 원래 파일명은 유지하고 별도 삽입 ID IMG_01, IMG_02 등을 부여해줘. 첫 작성에서는 본문 순서대로 ID를 부여하고 수정 시 기존 ID와 업로드 URL 대응을 보존해줘.
- 모든 이미지를 억지로 쓰지 말고 중복·불필요한 검색 화면·모음 미리보기는 제외해줘. 검색 화면은 공식 경로를 찾는 설명에 필요할 때만 써줘. 이미지를 재배치하거나 제외했다면 이유를 TXT에 기록해줘.
- 사용 가능한 이미지가 없으면 존재하지 않는 파일이나 슬롯을 만들지 말고, 작성 가능한 본문과 필요한 이미지 보완 목록을 남겨줘.

3. 내용과 HTML
- 근거에 없는 수치·후기·개인적 실사용 경험·로그인 이후 완료 단계를 만들지 마. 앱/모바일 웹/PC 웹, 조사일/작성일, 주간/월간, 지역·분류와 확인 한계를 구분해줘.
- 변동 가능한 사실을 현재형으로 쓸 때는 공식 자료를 재확인해줘. 재확인할 수 없으면 조사일 기준과 미확인 항목을 표시해줘.
- H2·표·CTA·FAQ 개수는 캡처의 흐름과 주제에 맞춰 조정하고, 분량이나 개수를 채우기 위한 반복은 하지 마. 실제 출처 링크와 확인일을 제공해줘.
- 기존 스타일 가이드의 블루 계열, 이미지·FAQ·표 컴포넌트를 활용하고, Blogger 본문용 HTML 조각만 작성해줘. html/head/body/h1/title/meta 태그와 Markdown 코드펜스는 넣지 마.
- 채택 이미지마다 고유한 id="img-01", data-image-id="IMG_01", IMAGE_SLOT:IMG_01 START/END 주석을 사용해줘. 관련 소제목과 이미지 직전·직후 문단에도 고유 id를 부여해줘.
- 업로드 전 src는 {{BLOGGER_IMAGE_URL_IMG_01}} 형식의 해당 이미지 토큰으로 넣어줘. 실제 alt, 캡션, 이미지 크기와 비율 유지 스타일을 작성해줘. 로컬 경로나 임의 원격 URL을 src로 사용하지 마.
- 광고·제휴는 지정되거나 확인된 대상 블로그 설정에만 맞추고, 모르는 경우 예시 광고 ID를 임의로 넣지 말고 TXT의 확인 항목에 기록해줘.

4. 결과물
같은 키워드의 웹조사/publish/에 다음 두 파일을 UTF-8로 저장해줘. publish가 없으면 생성하고 {탭}_{키워드}는 실제 폴더명 전체를 그대로 사용해줘.
- {탭}_{키워드}_html콘텐츠.html
- {탭}_{키워드}_제목메타디스크립션.txt

TXT는 html-content-guide.md 0.6절의 구조대로 다음 정보를 빠짐없이 작성해줘.
- 입력 자료와 경로, 조사일·작성일, 콘텐츠 개요
- 제목 후보 7개와 최종 추천 1개, 후킹 문구 7개
- 메타디스크립션 후보 3개와 최종 추천 1개 및 공백 포함 문자 수
- 영문 퍼머링크 후보 3개와 최종 추천 1개, 한글 참고 문구, 라벨 제안
- 별도 섹션 [Blogger 이미지 업로드 추천 순서와 삽입 위치]
- 이미지마다 삽입 ID, 추천 업로드 순서·본문 순서, 원래 파일번호와 정확한 파일명, 프로젝트 상대경로, 역할, 내부 표식 번호와 본문 절차 번호, 실제 화면 설명
- 완성한 HTML의 실제 H2/H3 문구와 id, 직전 문단 id·마지막 문장, 직후 문단 id·첫 문장, 슬롯 id·주석·치환 토큰
- 권장 alt·캡션, 실제 픽셀 크기, 출처명·ID·실제 화면/원본 URL·확인일, 검색 화면이면 실제 연 공식 결과 URL
- 대표 이미지 추천과 이유, 순서 변경·제외·보류 이유, 가림·가독성·재사용 검수 결과
- 이미지 업로드 상태와 Blogger 이미지 URL은 실제 업로드 전에는 미업로드로 표기
- 업로드 담당 에이전트 전달사항, 남은 확인 항목, 검수 결과

5. 검수·시트 기록·보고
- 이미지 슬롯과 TXT 상세 블록이 1:1로 대응하는지, 파일이 실제 존재하는지, ID·토큰이 중복되지 않는지, 앞뒤 문장과 순서가 일치하는지 확인해줘.
- 가능한 로컬 시각 검수는 수행하고, 실제 Blogger 미리보기는 하지 않았다면 미실행으로 구분해줘. 미업로드 토큰을 실제 이미지 로딩 성공으로 보고하지 마.
- 기존 조사 Markdown·이미지·수집 도구 index/검증 기록은 보존해줘. 기존 두 파일이 발견되면 신규 생성은 건너뛰고, 기존 파일 수정·복구를 별도로 요청받았을 때만 사용자 수정과 URL 매핑을 보존하며 처리해줘.
- 조정자는 각 독립 채팅의 실제 완료를 기다리고 HTML/TXT 두 파일과 검수 결과를 확인해줘. 쓰기 직전에 해당 행의 메인 키워드와 작성여부 셀·수식·유효성 검사를 다시 확인하고, '애드센스 블로그 작성여부'(현재 참고 D열)의 빈 셀에 한글 ㅇ를 넣은 뒤 재조회해줘. 같은 ㅇ는 보존하고 다른 값은 덮어쓰지 마.
- tools/blogger_workflow.py sheet-plan의 content 이벤트로 요청을 만들 수 있지만 계획 생성은 시트 쓰기 완료가 아니야. 실제 연결 도구로 적용하고 재조회해줘. 기존 파일 쌍의 D만 누락된 경우에는 재생성 없이 내용을 검수한 뒤 기록만 복구해줘.
- 시트 쓰기에 실패하면 파일은 보존하고 시트 기록만 재시도해줘. TXT에 시트 ID·탭·sheetId·실제 행·threadId·D 반영 상태를 기록해줘.
- 최종 답변에는 채팅별 키워드·두 파일 링크·채택 이미지 수·건너뛴/보류 대상·D 반영 및 재조회 결과를 간단히 알려줘. 파일 작성 완료 / 시트 반영 완료 / 이미지 미업로드 / 미발행을 구분해줘.
- 조정자는 재사용할 절차 개선을 guidelines/BLOGGER_CONTENT_WORKFLOW.md와 관련 가이드에 통합 반영하고, 개별 키워드의 편집 기록은 TXT에 남겨줘. 작업자들이 공유 가이드를 동시에 수정하지 마.
```

## B. 작성된 결과물의 Blogger 업로드 인계

사용자가 대상 시트의 탭과 실제 행 번호를 지정해서 요청한다. 아래 실행 범위는 `공개 발행`이며, 초안까지만 원하면 `초안 저장`으로 바꾸어 사용한다. A의 독립 채팅과 달리 B는 한 조정자 아래 키워드별 ego-browser Space를 최대 3개 병렬로 진행한다.

```text
.antigravity/rules.md와 guidelines/의 프로젝트 확인 규칙을 적용하고, guidelines/CHROME_AGENTS_USAGE_GUIDE.md, guidelines/크롬에이전트_활용법.md, guidelines/AGENT_DESKTOP_GUIDE.md를 먼저 참고해줘.
guidelines/BLOGGER_CONTENT_WORKFLOW.md의 운영·중복 방지·시트 상태 규칙과 블로그작성_가이드라인/html-content-guide.md 0절, html-style-guide.md의 이미지 슬롯 규칙을 따라 아래 대상을 Blogger에 반영해줘.
```
