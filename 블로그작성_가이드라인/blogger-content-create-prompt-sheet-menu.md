# Google Sheets HTML 미작성 조회부터 Blogger 원고 작성까지

현재 프로젝트의 `guidelines/`에 `.md` 파일이 있는지 먼저 확인해줘. 없으면 프로젝트 경로를 확인해달라고 알려줘. `.antigravity/rules.md`, `guidelines/AGENT_DESKTOP_GUIDE.md`, `guidelines/BLOGGER_CONTENT_WORKFLOW.md`를 읽어줘. 팝업 조회와 복사 복구에는 `guidelines/웹자료수집.md` 8절과 `블로그작성_가이드라인/web-search-request-prompt-sheet-menu.md`의 조회 방식을 참고해줘.

아래 팝업에서 대상 행을 직접 가져와 각 행에 대응하는 로컬 웹조사 자료로 Blogger 본문 HTML과 제목·메타디스크립션 TXT를 만들어줘. 작성과 검수가 끝난 행은 시트의 `애드센스 블로그 작성여부`에 `ㅇ`를 기록하고 재조회해줘. Blogger 이미지 업로드·초안 저장·발행은 후속 B 프로세스에서 진행해.

## 1. 시트 팝업에서 대상 가져오기

1. 설치된 `ego-browser skill`의 안내를 끝까지 읽고 공개 SDK를 사용해 조회용 TaskSpace에서 [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)를 열어줘. 시트 제목이 바뀌어도 문서 ID로 확인하고 작업 탭은 팝업의 탭 이름을 사용해줘.
2. 상단 `🔍 키워드 조회` → `3️⃣ html 글 미작성 전체 시트 조회 (팝업)`를 실행해줘. 스크립트 실행이 끝나고 `전체 시트 html 글 미작성 목록`이 열릴 때까지 기다려줘. 결과 없음, 스크립트 오류, 로그인·권한 요구를 구분해줘. 사용자 조작이 필요하면 같은 TaskSpace에서 제어를 넘기고 확인 후 재개해줘.
3. 전체 목록은 `📋 전체 기본 복사`를 사용해줘. 섹션을 나눠 가져올 때는 대상 탭마다 분할 크기(예: `3개씩`)를 정한 뒤 그 탭의 `📑 연달아 분리된 섹션 전체 복사`를 사용해줘. 중첩 iframe에서 버튼을 찾지 못하면 현재 화면에서 위치를 확인하고 클릭해줘. 실제 복사 텍스트를 확인할 수 없으면 팝업 snapshot 또는 iframe subtree에서 요약과 해당 섹션의 텍스트박스를 읽어줘. 복사 결과 확인을 위해 시트에 붙여넣지 마.
4. 탭 이름·실제 시트 행 번호·메인 키워드를 `{tab, row, keyword}`로 정리해줘. `No.` 열의 번호를 사용하지 말고 팝업의 탭·행 순서와 섹션 경계를 유지해줘. 전체 행 수·탭 수와 섹션별 건수를 대조하고, 탭 누락·같은 탭과 행의 중복·키워드 충돌·건수 불일치는 다시 확인해줘. 조회 결과가 0개이면 결과만 알려줘.

ego-browser에서 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용해줘. 이 함수가 최소화된 같은 창을 자동으로 복원한 뒤 캡처해. 검증용 캡처는 프로젝트 내 작업 기록 폴더에 저장하고, 캡처 폴더에 `research.json`이 없으면 `{}`로 초기화해줘.

## 2. 시트 행과 로컬 조사 자료 확인

- Sheets 연결 도구/API로 문서 메타데이터와 탭의 `sheetId`, 헤더를 확인해줘. 헤더 `블로그 업로드 날짜`, `애드센스 블로그 작성여부`, `메인 키워드`(현재 참고 A·D·I열)를 찾아 탭별로 필요한 열과 대상 행 범위를 묶어서 읽어줘. 팝업의 탭·실제 행·키워드를 현재 값과 대조하고, 행 또는 키워드가 바뀌었으면 다시 조회해줘. 불일치가 남으면 해당 행의 사유를 기록해줘.
- 같은 행의 `블로그 업로드 날짜`를 `YY_MMDD`로 변환해 `YY_MMDD/{탭}_{메인 키워드}/`를 먼저 확인해줘. 날짜를 확인할 수 없거나 해당 폴더가 없거나 조사 메타데이터가 다른 행을 가리키면 프로젝트의 날짜 폴더에서 같은 이름을 찾아줘. `웹조사/research.json`이나 조사 manifest의 탭·행·키워드·경로를 대조하고, 구형 폴더는 폴더명과 조사 문서의 주제로 대응을 확인해줘. 날짜가 달라도 근거가 일치하는 기존 폴더를 사용하고 그 경로와 근거를 배정 기록에 남겨줘. 경로를 확정할 수 없으면 해당 행의 사유를 남긴 뒤 확인된 행을 계속 처리해줘.
- `웹조사/publish/{탭}_{키워드}_웹조사결과.md`를 먼저 읽어줘. 없으면 같은 키워드의 `웹조사/publish/*_웹조사결과.md`, `웹조사/*_웹조사결과.md`, `웹조사/웹조사결과.md` 순으로 확인해줘. 이미지 링크는 선택한 Markdown 기준 상대경로로 읽고, 같은 키워드의 `publish/`, 상위 `웹조사/`와 문서에 명시된 하위 경로에서 발행 후보를 확인해줘.
- `웹조사/publish/`에서 본문에 쓸 수 있는 이미지가 4장 이하이거나 필요한 장면이 빠졌다면 `BLOGGER_CONTENT_WORKFLOW.md` 1.4절에 따라 같은 키워드의 `웹조사/raw/`를 먼저 확인해줘. 같은 화면의 원본과 편집본은 한 장으로 세고, `research.json`, `publish/index.json`, `evidence/review.json`과 출처 기록에서 원본을 대조해줘. 직접 캡처한 화면과 가림·자르기·표식 편집본을 활용해줘.
- `raw/` 보강 후에도 쓸 수 있는 이미지가 4장 이하이거나 필요한 장면이 없으면 ego-browser에서 해당 메인 키워드를 Google로 검색해줘. 광고를 제외하고 실제로 연 공식 페이지에서 빠진 화면을 `tools/research_browser.mjs`의 `capture()`로 캡처해줘. 검색 결과를 쓰면 실제로 연 공식 링크에, 안내 화면을 쓰면 설명할 버튼·메뉴에 빨간 표식을 넣어줘. [웹자료수집.md 6~7절](../guidelines/웹자료수집.md)에 따라 원본과 URL·확인일을 남기고 표식·가독성·개인정보를 검수해줘.
- 채택한 `raw/` 원본과 새 캡처의 복사본이나 편집본은 `웹조사/publish/blogger-images/`에 저장해줘. 편집이 없으면 원래 이름을 유지하고, 가림·자르기·표식은 작업 사본에서 처리한 뒤 다시 열어 검수해줘. 기존 발행 이미지와 보완 이미지를 실제 절차 순서에 배치하고, 수집 도구의 `index.json` 및 검증 기록을 보존해줘.
- 콘텐츠와 이미지 배치 TXT에는 이미지 이용 제한에 관한 문구를 넣지 말아줘. 화면의 시점과 실제 화면을 이해하는 데 필요한 차이는 기록해줘.
- 채택하지 않은 후보의 경로와 사유는 TXT의 `[제외·보류 이미지]`에 적어줘. 추가 조사 후에도 이미지가 부족하면 시도한 경로, 최종 채택 수, 필요한 장면과 재개 지점도 그 항목에 남겨줘. 공식 근거로 핵심 내용을 설명할 수 있으면 단계 안내·표·공식 링크로 작성해줘. 핵심 답변에 필요한 근거까지 부족하면 해당 행을 검토 대상으로 기록해줘.

## 3. 중복 검사와 독립 채팅 배정

- 작성 전 `tools/blogger_workflow.py scan`으로 해당 키워드 폴더 전체를 검색해 정확한 HTML/TXT 파일명을 확인해줘. 같은 폴더에 정상 파일 두 개가 있으면 기존 쌍을 검수하고, D가 비어 있으면 기록만 복구해줘. 부분 결과·빈 파일·서로 다른 위치의 쌍·중복 사본은 검토 대상으로 남겨줘. D가 이미 `ㅇ`인데 파일이 없으면 유실이나 다른 경로를 먼저 확인해줘.
- 작성여부 셀이 비어 있고 두 파일이 모두 없으며 사용할 조사 근거를 확보한 행을 신규 생성 대상으로 확정해줘. 조회 시각, 팝업 순서·섹션, `spreadsheetId`·`sheetId`·탭·실제 행·키워드, 확인한 시트 값, 로컬 상대경로와 보류 사유를 배정 기록에 남겨줘. 재개 요청은 기존 배정의 결과물과 기록을 대조해 이어가줘.
- `BLOGGER_CONTENT_WORKFLOW.md` 3.2절에 따라 `dispatch.json`을 `pending`으로 만든 뒤 같은 프로젝트에서 신규 키워드마다 실제 독립 채팅 1개를 배정해줘. 한 채팅에는 해당 키워드의 행·폴더·요구사항·가이드·dispatch 경로를 전달해줘. 섹션별 채팅 ID가 모두 기록되면 그 섹션과 소속 행을 `ready`로 바꿔 시작하고, 섹션 구분이 없으면 전체 배정에 적용해줘. `ready` 전에는 사전 점검만 해줘. 실패한 섹션은 사유와 함께 `blocked`로 기록하고 준비된 섹션은 진행해줘. 동시 작업 수를 지정했다면 그 범위를 적용하고, 독립 채팅 자동 생성 기능이 없는 Antigravity 환경은 해당 절의 순차 작성 절차를 적용해줘.
- 시작 직전 파일 상태를 다시 확인해줘. 중복 작업 방지는 `scan`과 필요 시 로컬 폴더 잠금을 사용해줘. 구글시트 행 배타 잠금은 사용하지 말고 시트 쓰기는 조정자 한 명이 담당해줘.

## 4. Blogger 본문과 제목·메타 TXT 작성

`블로그작성_가이드라인/html-content-guide.md` 0절을 범용 템플릿보다 우선 적용하고 `블로그작성_가이드라인/html-style-guide.md`를 따라줘.

- 후보 이미지를 직접 열고 실제 화면·버튼·표식·캡션·확인일·가독성·개인정보 가림을 확인해줘. 실제 화면 전환을 기준으로 개요와 이미지 배치를 먼저 정해줘. 답변 → 준비 조건 → 단계별 행동과 결과 → 예외/FAQ 순서로 구성하고, 행동 설명과 해당 이미지·캡션은 붙여 배치해줘. 파일번호·화면 표식 번호·본문 단계 번호를 구분하고, 이미지 재배치나 제외 사유는 TXT에 적어줘.
- 근거에 없는 수치·후기·실사용 경험·로그인 이후 완료 단계를 만들지 마. 앱/모바일 웹/PC 웹, 조사일/작성일, 기간·지역·분류와 확인 한계를 구분해줘. 변동 가능한 사실을 현재형으로 안내할 때는 공식 자료를 재확인하고, 확인할 수 없으면 조사일 기준과 미확인 범위를 적어줘.
- 블루 계열 스타일과 이미지·FAQ·표 컴포넌트를 활용해 Blogger 본문용 HTML 조각으로 작성해줘. `html/head/body/h1/title/meta` 태그와 Markdown 코드펜스는 넣지 마. H2·표·CTA·FAQ 개수는 주제와 실제 흐름에 맞춰 정해줘.
- 채택 이미지마다 원본 파일명을 기록하고 첫 작성에서는 본문 순서대로 `IMG_01`, `IMG_02` 등을 부여해줘. `id="img-01"`, `data-image-id="IMG_01"`, `IMAGE_SLOT:IMG_01 START/END` 주석, 실제 alt·캡션·크기·비율 스타일을 넣어줘. `src`는 `{{BLOGGER_IMAGE_URL_IMG_01}}` 형식의 대응 토큰을 사용하고, 연결 소제목과 이미지 직전·직후 문단에도 고유 ID를 부여해줘. 후속 수정 시 기존 ID와 업로드 URL의 대응을 보존해줘.
- 조사 결과의 실제 URL을 관련 이미지와 설명 순서에 맞춰 연결하고 출처명과 확인일을 제공해줘. 각 H2 제목 전체에는 해당 소주제의 검증된 URL을 연결해줘. 소주제·표·이미지 주변에는 사이트명이나 행동 문구를 앵커로 사용하고, 기존 요청과 같이 볼드 및 `#1b1bf8` 색을 적용해줘. 모든 링크와 버튼은 현재 탭에서 열리도록 작성해줘.
- 콘텐츠 가이드의 광고 코드·링크·디자인·버튼·인트로 직후 및 버튼 직전 CTA 규칙을 적용해줘. 광고와 CTA는 설명·이미지 사이를 피해서 배치해줘. 확인된 블로그 설정에 맞춰 광고·제휴를 적용하고, 설정을 모르면 확인 항목을 TXT에 적어줘.

같은 키워드의 `웹조사/publish/`에 아래 두 파일을 UTF-8로 저장해줘. `publish/`가 없으면 만들고 `{탭}_{키워드}`는 실제 폴더명 전체를 사용해줘.

- `{탭}_{키워드}_html콘텐츠.html`
- `{탭}_{키워드}_제목메타디스크립션.txt`

TXT는 `html-content-guide.md` 0.6절에 따라 작성해줘.

- 입력 자료·상대경로·조사일·작성일·콘텐츠 개요, 제목 후보 7개와 추천 1개, 후킹 문구 7개, 메타디스크립션 후보 3개와 추천 1개 및 공백 포함 문자 수, 영문 퍼머링크 후보 3개와 추천 1개, 한글 참고 문구와 라벨을 포함해줘.
- `[Blogger 이미지 업로드 추천 순서와 삽입 위치]`에 보완 이미지를 포함해 채택 이미지마다 상세 블록을 작성해줘. 삽입 ID, 업로드·본문 순서, 원래 파일번호·파일명·상대경로, 실제 업로드 파일의 상대경로, 역할, 화면 표식과 본문 단계, 실제 화면 설명을 적어줘. 완성한 HTML의 실제 H2/H3와 ID, 직전 문단 ID와 마지막 문장, 직후 문단 ID와 첫 문장, 슬롯 ID·주석·치환 토큰을 대응시켜줘. 보완 이미지의 채택 사유와 편집 내역을 적고 화면에 표식이 없으면 `해당 없음`으로 기록해줘.
- 이미지마다 권장 alt·캡션, 실제 픽셀 크기, 출처명·ID·실제 화면/원본 URL·확인일, 검색 화면이면 실제로 연 공식 결과 URL을 기록해줘. 대표 이미지 추천, 재배치·제외·보류 사유, 가림·가독성 검수, 이미지 미업로드 상태, 업로드 담당자 전달사항과 남은 확인 항목을 포함해줘.

## 5. 검수·시트 기록·보고

- 파일 쌍·UTF-8, H2 전체 링크와 인트로 CTA, 근거 링크, HTML 이미지 슬롯과 TXT 블록의 1:1 대응, 실제 업로드 파일·픽셀, ID·토큰 유일성, 문장·순서 일치를 한 번에 검수해줘. 보완 이미지도 TXT에 기록한 업로드 파일과 HTML의 슬롯·alt·캡션이 일치하는지 확인해줘. 임시 로컬 미리보기에서 토큰에 실제 파일을 연결해 모바일·PC의 이미지 표시·비율과 가로 넘침을 확인해줘. 작업 채팅에서 브라우저가 실행되지 않으면 조정자가 해당 원고를 모아 미리보기를 확인해줘. 로컬 미리보기 범위, 실제 Blogger 미리보기 여부와 이미지 미업로드 상태를 기록해줘.
- 조정자는 실제 작업 완료와 두 파일을 확인한 행부터 묶어서 처리해줘. 쓰기 직전에 해당 행의 메인 키워드와 `애드센스 블로그 작성여부` 셀의 값·수식·유효성을 다시 확인해줘. 검수한 행의 빈 작성여부 셀에만 한글 `ㅇ`를 연결 도구로 쓰고 같은 범위를 재조회해줘. 기존 `ㅇ`, 다른 값이나 수식은 보존해줘. A·C 등 다른 열은 그대로 둬.
- `tools/blogger_workflow.py sheet-plan`의 `content` 이벤트는 요청 생성에 사용할 수 있어. 완료는 실제 적용과 재조회로 확인해줘. 시트 기록만 실패하면 해당 기록만 재시도해줘. TXT 작업 정보에 `spreadsheetId`, `sheetId`, 탭, 실제 행, 메인 키워드, `runId`/`threadId`와 `D열 반영 상태` 한 줄을 두고, 조정자가 재조회 결과로 갱신해줘. 인계 메모에서 D열 상태가 필요하면 이 줄을 참조해줘. 전체 처리 후 대상 행을 묶어서 마지막으로 대조해줘.
- 팝업의 전체 행 수·탭 수와 섹션별 배정 결과를 알려줘. 행별로 탭·행·키워드, HTML/TXT 경로, HTML 줄 수·H2 개수·채택 이미지 수, 검수와 D열 반영·재조회 결과를 표로 보고해줘. 보류 이미지와 필요한 장면, 건너뛴 행·실패 사유와 재개 지점, 실패 건수도 알려줘.
