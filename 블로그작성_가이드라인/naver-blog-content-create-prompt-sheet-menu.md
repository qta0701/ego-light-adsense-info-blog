# Google Sheets 네이버 블로그 MD 미작성 조회부터 원고 작성까지

현재 프로젝트의 `guidelines/`에 `.md` 파일이 있는지 먼저 확인해줘. 없으면 프로젝트 경로를 확인해달라고 알려줘. `.antigravity/rules.md`, `guidelines/AGENT_DESKTOP_GUIDE.md`, `guidelines/NAVER_BLOG_MD_WORKFLOW.md`, `블로그작성_가이드라인/naver-blog-promo-guide.md`를 읽어줘. 실행·경로·검수·시트 기록에는 `NAVER_BLOG_MD_WORKFLOW.md`와 이 요청을 적용하고, 제목과 카피 작성에 `naver-blog-promo-guide.md`를 참고해줘. 팝업 조회와 복사 복구에는 `guidelines/웹자료수집.md` 8절의 조작 방식을 참고해줘.

시트 팝업에서 대상 탭·실제 행 번호·메인 키워드를 직접 가져와 각 행의 로컬 조사 자료로 네이버 블로그 본문 Markdown과 제목·이미지 배치 TXT를 작성해줘. 두 파일을 검수한 행은 시트의 `네이버 블로그 md 생성 여부`에 `ㅇ`를 기록하고 재조회해줘. 이번 작업 범위는 원고 작성과 E열 기록까지야.

## 1. ego-browser에서 대상 목록 가져오기

1. 설치된 `ego-browser skill`을 끝까지 읽고 공개 SDK로 조회용 TaskSpace에서 [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)를 열어줘. 문서 ID로 시트를 확인하고 작업 탭은 팝업에 표시된 이름을 사용해줘.
2. 메뉴가 좁은 창에 가려지지 않도록 `tools/research_browser.mjs`의 `ensureSheetsMenuWidth(page)`로 2,150px 폭을 요청하고 실제 적용 방식과 메뉴 상태를 확인해줘. 에뮬레이션으로 적용된 경우 새 SDK 라운드마다 다시 호출해줘. 상단 `🔍 키워드 조회` → `9️⃣ 네이버 블로그 md 미작성 전체 시트 조회 (팝업)`을 실행해줘. 스크립트가 끝나고 `전체 시트 네이버 블로그 md 미작성 목록`이 열릴 때까지 기다려줘. 결과 없음, 실행 오류, 로그인·권한 요구를 구분해줘. 사용자 조작이 필요하면 같은 TaskSpace에서 제어를 넘기고 확인 후 재개해줘.
3. 전체 목록은 `📋 전체 기본 복사`를 사용해줘. 섹션을 나눠 가져올 때는 대상 탭마다 분할 크기(예: `3개씩`)를 정한 뒤 그 탭의 `📑 연달아 분리된 섹션 전체 복사`를 사용해줘. 중첩 iframe에서 버튼을 찾기 어려우면 화면에서 실제 위치를 확인해 클릭해줘. 복사 텍스트를 확인할 수 없으면 팝업 snapshot 또는 iframe subtree에 표시되는 요약과 섹션 텍스트박스를 읽어줘. 복사 검증에 시트 셀 붙여넣기를 사용하지 마.
4. `{tab, row, keyword}`를 팝업의 탭·행 순서와 섹션 경계대로 정리해줘. `row`는 `No.` 열의 번호와 별개인 실제 시트 행 번호야. 전체 행·탭 수와 섹션별 건수를 대조하고, 탭 누락·동일 탭/행 중복·키워드 충돌·건수 불일치가 있으면 다시 확인해줘. 결과가 0개면 결과만 알려줘.

ego-browser에서 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용해줘. 이 함수가 최소화된 같은 창을 자동으로 복원한 뒤 캡처해. 검증용 캡처는 프로젝트 내 작업 기록 폴더에 저장하고, 캡처 폴더에 `research.json`이 없으면 `{}`로 초기화해줘.

## 2. 시트 행과 로컬 조사 자료 확인

- Sheets 연결 도구/API로 문서 메타데이터와 각 탭의 `sheetId`를 확인해줘. 헤더 `블로그 업로드 날짜`, `네이버 블로그 md 생성 여부`, `애드센스 포스팅 링크`, `메인 키워드`(현재 A·E·H·I열)로 열을 찾아 탭별로 대상 행을 묶어 읽어줘. 탭·실제 행·키워드를 팝업과 대조하고 달라졌으면 다시 조회해줘. 불일치가 남으면 해당 행과 사유를 기록해줘.
- 같은 행의 `블로그 업로드 날짜`를 `YY_MMDD`로 변환해 `YY_MMDD/{탭}_{메인 키워드}/`를 먼저 확인해줘. 날짜가 비었거나 해석할 수 없거나 예상 폴더가 없거나 조사 메타데이터가 다른 행을 가리키면 다른 날짜 폴더에서 같은 이름을 찾아줘. `웹조사/research.json`이나 조사 manifest의 탭·실제 행·키워드·경로를 대조해줘. 구형 폴더는 폴더명과 조사 문서의 주제로 대조하고, 다른 PC의 절대경로는 `.antigravity/rules.md`의 경로 해석 규칙을 적용해줘. 근거가 일치하는 유일한 폴더를 사용하고, 대응을 확정할 수 없으면 해당 행의 사유와 재개 지점을 기록해줘.
- 같은 행의 `애드센스 포스팅 링크`(H열)의 실제 `http://` 또는 `https://` 주소를 `{promotion_url}`로 사용해줘. 비어 있거나 주소를 확정할 수 없는 행은 보류하고 확인된 다른 행을 진행해줘.
- `웹조사/publish/{탭}_{키워드}_웹조사결과.md`를 먼저 읽어줘. 없으면 같은 키워드의 `웹조사/publish/*_웹조사결과.md`, `웹조사/*_웹조사결과.md`, `웹조사/웹조사결과.md` 순으로 찾아줘. `웹조사/publish/{탭}_{키워드}_제목메타디스크립션.txt`의 `[제목 후보]` 또는 추천 제목을 참고해줘. 제목 자료가 없으면 누락을 기록하고 조사 근거로 제목을 작성해줘. 핵심 안내의 근거가 부족하면 보완할 항목을 남겨줘.
- 작성 전과 시작 직전에 키워드 폴더 전체에서 두 결과 파일의 정확한 이름을 확인해줘. 두 파일 모두 없고 E열이 비어 있는 행은 URL과 조사 근거가 확인되면 작성해줘. 정상 파일 쌍이 있으면 검수해서 재사용하고, E열이 비어 있으면 시트 기록을 복구해줘. 부분 파일·빈 파일·중복본은 경로와 상태를 기록해 검토해줘. E열이 이미 `ㅇ`인데 파일이 없으면 유실이나 경로 불일치를 먼저 확인해줘. 현재 세션에서 팝업 순서대로 진행하고 구글시트 행에 배타 잠금을 걸지 마.
- 작업 목록에 조회 시각, 팝업 순서·섹션, `spreadsheetId`·`sheetId`·탭·실제 행·키워드, 확정한 로컬 상대경로와 선택 근거를 남겨줘. 재개 시 기존 대상과 실제 파일·시트 상태를 대조해줘.

## 3. 이미지 선택과 보완

- 조사 Markdown의 이미지 링크는 해당 파일 기준 상대경로로 읽어줘. 같은 키워드의 `웹조사/publish/`, 상위 `웹조사/`와 조사 문서에 명시된 하위 경로에서 후보를 찾아 직접 열어줘. 화면·버튼·표식·확인일·가독성·개인정보를 확인해줘.
- `웹조사/publish/`에서 본문에 쓸 수 있는 이미지가 4장 이하이거나 필요한 장면이 빠지면 `NAVER_BLOG_MD_WORKFLOW.md` 1.4절에 따라 같은 키워드의 `웹조사/raw/`를 먼저 확인해줘. 같은 화면의 원본과 편집본은 한 장으로 세고, `research.json`, `publish/index.json`, `evidence/review.json`과 출처 기록을 대조해줘. 캡처와 공식 예시의 가림·자르기·표식 편집본을 활용하고 출처와 확인일을 기록해줘.
- `raw/` 보강 후에도 쓸 수 있는 이미지가 4장 이하이거나 필요한 장면이 없으면 ego-browser에서 해당 메인 키워드를 Google로 검색해줘. 광고를 제외하고 실제로 연 공식 페이지에서 빠진 화면을 `tools/research_browser.mjs`의 `capture()`로 캡처해줘. 검색 결과를 쓰면 실제로 연 공식 링크에, 안내 화면을 쓰면 설명할 버튼·메뉴에 빨간 표식을 넣어줘. [웹자료수집.md 6~7절](../guidelines/웹자료수집.md)에 따라 원본과 URL·확인일을 남기고 표식·가독성·개인정보를 검수해줘.
- 채택한 `raw/` 이미지와 새 캡처 등의 원본 복사본 또는 편집본을 `웹조사/publish/` 바로 아래에 저장해줘. 수정이 없으면 원래 이름을 쓰고 동명의 다른 파일이 있으면 구분되는 이름을 붙여줘. 가림·자르기·표식은 작업 사본에서 수행하고 편집본을 다시 열어 검수해줘. 원본과 수집·검증 기록을 보존하고, 보완 이미지와 기존 발행 이미지를 실제 절차 순서로 배치해줘.
- 콘텐츠와 제목·이미지 배치 TXT에는 이미지 이용 제한에 관한 문구를 넣지 말아줘. 화면의 시점과 실제 화면을 이해하는 데 필요한 차이는 기록해줘.
- 채택하지 않은 후보의 경로와 사유는 TXT의 `[제외·보류 이미지]`에 적어줘. 추가 조사 후에도 이미지가 부족하면 시도한 경로, 최종 채택 수, 필요한 장면과 재개 지점도 그 항목에 남겨줘. 공식 근거로 핵심 절차를 설명할 수 있으면 단계 안내와 표로 해당 내용을 채워줘. 핵심 안내를 검증할 근거가 부족한 행은 보류해줘.

## 4. 네이버 블로그 MD와 제목·이미지 배치 TXT 작성

같은 키워드의 `웹조사/publish/`에 두 파일을 UTF-8로 저장해줘. `publish/`가 없으면 만들고 `{탭}_{키워드}`는 확정한 폴더명 전체를 사용해줘.

- `{탭}_{키워드}_네이버블로그.md`
- `{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt`

### 본문 Markdown

- 제목 자료와 조사 근거로 대표 제목을 정해줘. 도입 첫 문장부터 친근한 한국어 대화체로 핵심 답을 제시해줘. 확인한 화면과 공식 근거를 바탕으로 실제 행동이나 실수 방지 팁을 2회 이상 넣어줘. 1인칭 경험은 실제로 확인된 경우에 사용하고, 이미지에 담긴 핵심 정보는 인접 본문에도 적어줘. 날짜·조건이 바뀔 수 있는 정보는 공식 자료에서 재확인하고, 조사 시점의 근거만 있으면 그 기준일을 밝혀줘.
- 인트로는 2개 문단, 공백 제외 160자 이내와 공백 포함 210자 이내로 작성해줘. CTA는 인트로 직후와 첫 번째 H2 내용이 끝난 뒤에 배치해줘. 각 CTA는 서로 다른 문구·이모지의 단일 셀 테이블과 빈 줄, 실제 `{promotion_url}` 단독 행으로 구성해줘. 본문 외부 URL은 이 홍보 URL 2회로 제한해줘.
- 소주제는 번호를 붙인 `##`만 쓰고, 중간 강조형 소제목은 단일 셀 표로 작성해줘. CTA·FAQ와 별도로 정보용 표 3~4개를 넣고 표에 직관적인 이모지를 활용해줘. 불릿은 항목당 150자 이내로 작성해줘.
- 채택한 이미지의 배치 지시를 해당 `##` 소주제 직후에 넣어줘. 아래 형식에서 백틱 안에는 실제 사용할 파일명만 넣고, 화면 설명과 캡션은 직접 확인한 내용으로 작성해줘.

  ```markdown
  [이미지 배치 지시: `IMG_01_신규교육_접수화면.png` - 인천교통연수원 접수 화면 삽입. 캡션: "인천교통연수원 교육 신청 화면"]
  ```

- FAQ를 마지막 `##` 소주제로 두고 질문 3개를 각각 1열 표로 작성해줘. 질문은 볼드, 답변은 다음 행에 넣어줘. FAQ 다음에는 빈 줄과 해시태그 8~10개로 끝내줘.

### 제목 및 이미지 배치 TXT

- `[네이버 블로그 제목 후보 3개]`와 `[네이버 모바일 홈판형 제목 후보 3개]`를 작성해줘. 제목 자료의 후보와 조사 근거를 활용하고, TXT는 평문으로 작성해줘.
- `[사용 이미지 정보 및 본문 내 추천 배치 위치]`에 MD 순서대로 최종 파일명·실제 파일 상대경로, 해당 H2, 화면 설명, 배치 이유, 권장 캡션, 출처·확인일을 적어줘. 보완 이미지는 원본 상대경로, 채택 사유와 편집 내역도 적어줘. MD 배치 지시의 파일명·순서·캡션을 TXT와 맞춰줘.

## 5. 검수·시트 기록·결과 보고

- 두 파일의 UTF-8, 본문 근거와 인트로 분량, CTA 위치와 홍보 URL 2회, H2·정보용 표·FAQ·해시태그, TXT 제목 후보 3개씩을 확인해줘. 보완 이미지를 포함해 MD와 TXT의 배치 지시를 대조하고 실제 파일을 열어 확인해줘.
- 검수를 마친 행은 쓰기 직전에 메인 키워드와 `네이버 블로그 md 생성 여부` 셀의 값·수식을 다시 확인해줘. 해당 빈 셀(E열)에만 한글 자음 `ㅇ`를 쓰고 같은 범위를 재조회해줘. 기존 값이나 수식은 보존해줘. 시트 반영만 실패하면 로컬 파일을 보존하고 시트 기록을 재시도해줘.
