- 로컬 작업 경로를 찾을 때, 지정된 구글시트 탭의 행 번호에서 A열('블로그 업로드 날짜' 헤더) 값을 확인하고(예: 2026-11-06), 해당 날짜를 YY_MMDD 형식(예: 26_1106)으로 변환하여 프로젝트 루트의 날짜 폴더(26_1106\) 및 그 하위의 {탭}_{메인 키워드} 폴더(예: 26_1106\앱사용_당근마켓 채팅 걸기\웹조사\publish\) 경로에서 .md/.html/.txt 및 이미지를 찾아 인계받아줘.
- ego-browser 설치 스킬을 끝까지 읽고 순분(name=순분, profileId=Profile 2)을 사용해줘. 워크플로 4.2절에 따라 키워드별 새 독립 작업 채팅을 실제로 생성하고 각 채팅에서 해당 키워드의 TaskSpace 1개를 열어줘. 준비된 행이 3개 이상이면 처음 3개의 채팅과 Space를 함께 시작하고, 슬롯이 비면 다음 행을 시작해줘. 인증·시트 확인 대기를 포함해 동시 활성 채팅과 Space는 각각 최대 3개야. 재개할 때는 기존 배정·Space·글을 대조해줘. 환경에서 채팅 생성이 지원되지 않으면 조정자 채팅에서 사용 가능한 독립 Space로 계속 진행하고 실제 제한과 동시 실행 수를 남겨줘.
- 조정자만 연결된 Sheets 도구로 읽고 써줘. metadata·헤더로 열을 찾고 실제 행·키워드·정확한 HTML/TXT 쌍을 확인해줘. 조정자가 stage B claim을 확보해 각 작업 채팅에 전달하고, 각 작업 채팅은 글 생성 전에 로컬 상태 및 Blogger 중복 검사를 적용해줘. 완료된 글·이미지를 다시 생성하거나 업로드하지 마.
- **G/H/L이 모두 실제 공란이면 신규 업로드 후보(`eligible_new`)로 배정해줘.** 생성 직전·발행 직전·쓰기 직전 live 확인과 쓰기 후 재조회는 유지해줘. 수식 결과 공란·공백·FALSE·0은 값으로 취급해줘. 기존 초안은 명시된 같은 글로만 재개하고 이미 공개된 글은 재발행하지 마.
- 원래 채택된 모든 이미지 슬롯을 업로드하도록 워크플로 1.2절을 적용해줘. 파일·IMG ID와 출처·편집 내역을 확인하고, 파일이 없거나 화면이 맞지 않으면 같은 키워드의 관련 이미지나 적합한 자체 제작 설명 이미지로 보완해줘. 원고에 채택 이미지가 없으면 관련 있는 이미지 1개 이상을 준비해줘. 슬롯을 일괄 삭제하지 말아줘. 확보가 끝내 불가능한 행은 원본·시도·사유·재개 지점을 기록해 보류하고, 내가 해당 제외를 명시적으로 허용하지 않았다면 미완성 행의 G 완료 처리나 발행은 하지 말아줘. 다른 행은 계속 진행해줘.
- 확정한 TXT의 채택 이미지·파일명·IMG ID를 대조해 같은 글에 순차 업로드하고 실제 URL로 본문을 치환해줘. 새 postId는 이미지 업로드 전에, 각 업로드 URL은 다음 이미지 전에 로컬 상태에 저장해줘.
- 제목·검색 설명·사용 가능한 맞춤 퍼머링크·라벨은 TXT의 최종 추천값을 적용해줘. 해당 항목이 없거나 비어 있으면 본문과 키워드를 근거로 직접 작성해 입력해줘. 참고로 퍼머링크 탭에서는, '맞춤 퍼머링크' 라디오 메뉴를 선택하면 입력창이 활성화 되어서 퍼머링크를 입력할 수 있어.  별도 확인 질문이나 여러 후보 작성은 필요 없어. 입력 제한에 맞춰 조정하고 채택값을 TXT/state에 남겨줘.
- 맞춤 주소가 지원되지 않거나 한 번의 저장 확인에서 유지되지 않으면 자동 주소로 진행하고 실제 URL을 기록해줘. 이미 발행된 주소를 바꾸려고 초안으로 되돌리거나 재발행하지 마. 별도 요구에서 주소를 필수로 지정한 경우에는 그 조건을 우선해줘.
- 기본 PC·모바일 미리보기, iframe 검수 탭, 이미지별 캡처, 필드별 저장·재로드, 이미 검수된 원고의 재조사는 생략해줘. 새 레이아웃·이미지 편집, 관찰된 오류, 별도 요청이 있을 때만 해당 부분을 시각 검수해줘.
- ego-browser에서 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용해줘. 이 함수가 최소화된 같은 창을 자동으로 복원한 뒤 캡처해. 업로드 검증용 캡처는 B 실행 디렉터리의 별도 폴더에 저장하고, 캡처 폴더에 `research.json`이 없으면 `{}`로 초기화해줘. 복원이나 캡처에 실패하면 해당 Space와 기존 작업 상태를 보존하고 오류와 재개 지점을 기록해줘.
- 본문·메타를 함께 저장하고 같은 편집기에 한 번 재진입하여 저장값과 이미지·alt·캡션·토큰을 묶어서 확인해줘. 실제 초안 저장→로컬 상태→G=ㅇ→재조회 순서로 진행해줘. 초안만 요청한 경우 여기서 종료하고 H/L은 쓰지 마.
- 공개 발행은 같은 글에서 진행해줘. 같은 blogId의 게시 요청과 실제 URL 검증은 채팅·Space 전체에서 직렬화하고, 한 글의 목록 보기 URL·공개 제목·canonical을 확인한 뒤 다음 글을 게시해줘. 주소가 다른 글을 열거나 중복되면 H/L을 쓰지 않고 같은 postId와 증거를 보존해 워크플로 4.3절에 따라 복구해줘. 이미지 업로드와 초안 준비는 병렬로 진행해줘. 공개 페이지에서 이미지 전체의 로딩·메타·원래 발행 시각도 확인하고 공개 URL·시각을 먼저 로컬에 저장한 뒤 H/L을 같은 batchUpdate로 쓰고 재조회해줘. L은 KST 숫자형 DATE_TIME, 시트 시간대는 유지해줘.
- 파일 검사·잠금·열 판정·시트 계획·시간 변환은 tools/blogger_workflow.py를 재사용해줘. 같은 로직의 임시 프로그램이나 이미지별 스크립트를 새로 만들지 말고, ego 라운드별 최소 실행 코드에 검증된 연속 조작·조건 대기·순차 업로드 루프를 묶어줘. 실패한 과거 mutation 스크립트는 재실행하지 마.
- 전체 HTML·snapshot·URL을 반복 출력하지 말고 상태·개수·불일치만 반환해줘. 시트 실패 시 기존 글·원래 시각을 보존하고 시트만 복구해줘. HTML/TXT/state를 마무리하고 claim 해제·Space 종료는 각각 한 번만 수행해줘.
- 실제 채팅·Space ID와 시작·종료 시각을 B 실행 기록에 남겨줘. 결과에는 각각의 최대 동시 실행 수, 탭·행·키워드·초안/발행 상태·실제 URL·G/H/L 재조회, 업로드·제외·대체 이미지 수, 행별 실패·보류와 재개 지점을 포함해줘. 새로운 성공 방식이나 오류가 발견됐을 때만 운영 가이드에 추가해줘.

기존 글 수리나 재개를 요청할 때는 해당 항목의 실제 ID를 기입한다. 사용자가 탭 이름, 행 번호, 메인 키워드만 지정한 경우 에이전트는 시트 A열('블로그 업로드 날짜')을 확인하여 `YY_MMDD\{탭}_{키워드}\` 경로를 자동으로 탐색하여 원고를 인계받는다. 만약 시트 A열이 공란이거나 날짜 형식이 아니어서 폴더를 특정할 수 없는 경우, 프로젝트 내의 날짜 폴더들을 탐색하되 불명확하거나 여러 개가 존재하면 임의 선택하지 않고 사용자에게 확인을 요청한다. 메타데이터 자율 작성은 누락된 입력 항목을 보완하는 범위이며, HTML/TXT 파일 자체가 없거나 대상 폴더가 여러 개인 문제를 임의로 해결하는 지시는 아니다.
