# Blogger 업로드 및 발행 요청 프롬프트 (B)

2026-11-08 최적화. 아래 요청문 **하나만** 복사하고 대상 입력을 바꾼다. 상세 규칙은 [운영 가이드](../guidelines/BLOGGER_UPLOAD_WORKFLOW.md)에 모아 중복 프롬프트를 없앴다.

기본값은 검증된 성공 경로, 미리보기 생략, 저장·공개·시트 통합 확인이다. 시각 검수가 필요한 경우에만 조건부로 수행한다. 제목·검색 설명·사용 가능한 맞춤 주소·라벨이 TXT에 없으면 에이전트가 자율 작성한다. 로컬 작업 경로는 구글시트 A열('블로그 업로드 날짜')을 조회하여 `YY_MMDD\{탭}_{키워드}\` 경로를 자동으로 탐색한다.

```text
.antigravity/rules.md와 프로젝트 확인 규칙을 적용하고 guidelines/CHROME_AGENTS_USAGE_GUIDE.md, guidelines/크롬에이전트_활용법.md, guidelines/AGENT_DESKTOP_GUIDE.md의 관련 지침을 참고해줘.
guidelines/BLOGGER_UPLOAD_WORKFLOW.md의 현재 운영 규칙(0~5절·7~9절), 블로그작성_가이드라인/html-content-guide.md 0절과 html-style-guide.md의 이미지 슬롯 규칙으로 B 단계 작업을 완료해줘. 과거 실측 기록은 해당 오류가 있을 때만 필요한 부분을 읽어줘.

(또는 요약 형식: - [탭 / 실제 행 번호 / 메인 키워드 / 정확한 키워드 폴더(알면 기입)])

대상 블로그: [Blogger 관리 URL·blogId 또는 탭 매핑]

별도 요구: [없음 / 반드시 필요한 맞춤 주소·시각 검수 등]

- 로컬 작업 경로를 찾을 때, 지정된 구글시트 탭의 행 번호에서 A열('블로그 업로드 날짜' 헤더) 값을 확인하고(예: 2026-11-06), 해당 날짜를 YY_MMDD 형식(예: 26_1106)으로 변환하여 프로젝트 루트의 날짜 폴더(26_1106\) 및 그 하위의 {탭}_{메인 키워드} 폴더(예: 26_1106\앱사용_당근마켓 채팅 걸기\웹조사\publish\) 경로에서 .md/.html/.txt 및 이미지를 찾아 인계받아줘.
- ego-browser 설치 스킬을 끝까지 읽고 순분(name=순분, profileId=Profile 2)을 사용해줘. 기존 작업은 같은 Space·글에서 재개하고 키워드당 1 Space, 대기 포함 최대 3개로 진행해줘.
- 조정자만 연결된 Sheets 도구로 읽고 써줘. metadata·헤더로 열을 찾고 실제 행·키워드·정확한 HTML/TXT 쌍을 확인해줘. stage B claim, 로컬 상태 및 Blogger 중복 검사를 적용하고 완료된 글·이미지를 다시 생성하거나 업로드하지 마.
- G/H/L 공란·불일치 판정, 생성 직전·발행 직전·쓰기 직전 live 확인과 쓰기 후 재조회는 유지해줘. 수식 공란·공백·FALSE·0은 빈 셀이 아니야. 기존 초안은 명시된 같은 글로만 재개하고 이미 공개된 글은 재발행하지 마.
- TXT의 채택 이미지·파일명·IMG ID를 대조해 순차 업로드하고 실제 URL로 본문을 치환해줘. 새 postId는 이미지 업로드 전에, 각 업로드 URL은 다음 이미지 전에 로컬 상태에 저장해줘.
- 제목·검색 설명·사용 가능한 맞춤 퍼머링크·라벨은 TXT의 최종 추천값을 적용해줘. 해당 항목이 없거나 비어 있으면 본문과 키워드를 근거로 직접 작성해 입력해줘. 별도 확인 질문이나 여러 후보 작성은 필요 없어. 입력 제한에 맞춰 조정하고 채택값을 TXT/state에 남겨줘.
- 맞춤 주소가 지원되지 않거나 한 번의 저장 확인에서 유지되지 않으면 자동 주소로 진행하고 실제 URL을 기록해줘. 이미 발행된 주소를 바꾸려고 초안으로 되돌리거나 재발행하지 마. 별도 요구에서 주소를 필수로 지정한 경우에는 그 조건을 우선해줘.
- 기본 PC·모바일 미리보기, iframe 검수 탭, 이미지별 캡처, 필드별 저장·재로드, 이미 검수된 원고의 재조사는 생략해줘. 새 레이아웃·이미지 편집, 관찰된 오류, 별도 요청이 있을 때만 해당 부분을 시각 검수해줘.
- 본문·메타를 함께 저장하고 같은 편집기에 한 번 재진입하여 저장값과 이미지·alt·캡션·토큰을 묶어서 확인해줘. 실제 초안 저장→로컬 상태→G=ㅇ→재조회 순서로 진행해줘. 초안만 요청한 경우 여기서 종료하고 H/L은 쓰지 마.
- 공개 발행은 같은 글에서 진행해줘. 목록의 보기 링크로 실제 공개 페이지를 한 번 열어 제목·canonical·이미지 로딩·메타·원래 발행 시각을 묶어서 확인해줘. 공개 URL·시각을 먼저 로컬에 저장한 뒤 H/L을 같은 batchUpdate로 쓰고 재조회해줘. L은 KST 숫자형 DATE_TIME, 시트 시간대는 유지해줘.
- 파일 검사·잠금·열 판정·시트 계획·시간 변환은 tools/blogger_workflow.py를 재사용해줘. 같은 로직의 임시 프로그램이나 이미지별 스크립트를 새로 만들지 말고, ego 라운드별 최소 실행 코드에 검증된 연속 조작·조건 대기·순차 업로드 루프를 묶어줘. 실패한 과거 mutation 스크립트는 재실행하지 마.
- 전체 HTML·snapshot·URL을 반복 출력하지 말고 상태·개수·불일치만 반환해줘. 시트 실패 시 기존 글·원래 시각을 보존하고 시트만 복구해줘. HTML/TXT/state를 마무리하고 claim 해제·Space 종료는 각각 한 번만 수행해줘.
- 결과는 탭·행·키워드·초안/발행 상태·실제 URL·G/H/L 재조회 결과 표, 이미지 수, 실패/보류와 사유(없으면 0건)로 간략히 보고해줘. 새로운 성공 방식이나 오류가 발견됐을 때만 운영 가이드에 추가해줘.
```

기존 글 수리나 재개를 요청할 때는 해당 항목의 실제 ID를 기입한다. 사용자가 탭 이름, 행 번호, 메인 키워드만 지정한 경우 에이전트는 시트 A열('블로그 업로드 날짜')을 확인하여 `YY_MMDD\{탭}_{키워드}\` 경로를 자동으로 탐색하여 원고를 인계받는다. 만약 시트 A열이 공란이거나 날짜 형식이 아니어서 폴더를 특정할 수 없는 경우, 프로젝트 내의 날짜 폴더들을 탐색하되 불명확하거나 여러 개가 존재하면 임의 선택하지 않고 사용자에게 확인을 요청한다. 메타데이터 자율 작성은 누락된 입력 항목을 보완하는 범위이며, HTML/TXT 파일 자체가 없거나 대상 폴더가 여러 개인 문제를 임의로 해결하는 지시는 아니다.
