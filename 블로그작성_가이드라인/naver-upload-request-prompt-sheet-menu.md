# 구글시트 네이버 포스팅 미진행 조회부터 발행까지

`.antigravity/rules.md`, `guidelines/CHROME_AGENTS_USAGE_GUIDE.md`, `guidelines/크롬에이전트_활용법.md`, `guidelines/AGENT_DESKTOP_GUIDE.md`를 먼저 읽고 [네이버 업로드 운영 가이드](../guidelines/NAVER_UPLOAD_WORKFLOW.md)를 적용해줘. 조회 메뉴와 복사 오류 복구는 `guidelines/웹자료수집.md` 8.1절의 조작 방식을 따르고, 과거 발행 기록은 관련 오류가 생겼을 때 필요한 부분을 참고해줘.

구글시트 팝업에서 모든 대상의 탭·실제 행 번호·메인 키워드를 직접 가져와줘. 시트와 로컬 파일을 대조한 뒤 이미 작성된 네이버 Markdown을 ego-browser의 스마트에디터에 올리고, 각 행의 공개 발행 또는 예약발행과 두 시트의 결과 재조회까지 완료해줘. 처리 범위를 따로 지정하면 팝업 순서대로 그 범위를 적용해줘.

## 1. ego-browser에서 대상 목록 가져오기

1. 설치된 `ego-browser skill`을 끝까지 읽고 공개 SDK로 조회용 TaskSpace에서 [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)를 열어줘. 문서 ID로 대상을 확인해줘. 메뉴가 가려지면 `tools/research_browser.mjs`의 `ensureSheetsMenuWidth(page)`를 사용하고, 에뮬레이션이면 메뉴를 조작할 SDK 라운드마다 다시 호출해 새 snapshot을 확인해줘.
2. 상단 `🔍 키워드 조회` → `1️⃣1️⃣ 네이버 포스팅 미진행 전체 시트 조회 (팝업)`을 실행해줘. 스크립트 동작이 완료되고 `전체 시트 네이버 포스팅 미진행 목록` HTML 팝업이 열릴 때까지 기다려줘. 0건과 스크립트 오류, 로그인·권한 요구를 구분해줘. 사용자 조작이 필요하면 같은 Space에서 제어를 넘기고 확인 후 재개해줘.
3. `📋 전체 기본 복사`로 전체 목록을 가져와줘. 연속 목록이 필요하면 `📑 연달아 모두 복사`, 분할 목록이 필요하면 대상 탭별로 분할 크기를 정한 뒤 `📑 연달아 분리된 섹션 전체 복사`를 사용해줘. 버튼이 탭마다 있으면 대상 탭별로 복사해서 탭 이름도 확보해줘. 복사 텍스트를 직접 확인하고, 중첩 iframe의 버튼 조작이 실패하거나 복사 결과를 읽을 수 없으면 팝업 snapshot 또는 iframe subtree의 요약과 섹션 텍스트박스를 읽어줘. 확인은 팝업과 복사 결과에서만 해줘.
4. `{tab, row, keyword}`를 팝업 순서대로 정리해줘. `row`에는 `No.`와 구별되는 실제 시트 행 번호를 넣어줘. 팝업에 표시된 전체 행·탭 수와 분할 시 섹션별 건수를 대조해줘. 분할 경계가 있으면 유지하고, 경계가 없으면 탭마다 한 섹션으로 삼아줘. 탭 누락, 동일 탭·행 중복, 키워드 충돌, 건수 불일치는 원래 목록을 다시 확인해줘. 팝업에 0건이면 조회용 Space를 정리하고 조회 결과만 알려줘.

## 2. 현재 시트 행과 로컬 인계 파일 확인

- 조정자 한 명이 연결된 Sheets 도구로 문서 메타데이터, 각 탭의 `sheetId`·헤더·후보 행만 읽어줘. `블로그 업로드 날짜`, `네이버 포스팅 여부`, `애드센스 포스팅 링크`, `메인 키워드`를 헤더로 찾아줘(현재 A·F·H·I). 팝업의 탭·실제 행·키워드를 현재 시트와 대조하고, 재조회해도 대응이 불확실한 행은 사유와 재개 지점을 남겨줘.
- A의 날짜를 `YY_MMDD`로 변환하고 `YY_MMDD/{탭}_{키워드}/웹조사/publish/`를 먼저 확인해줘. 폴더명에는 기존 이름 정규화 규칙을 적용하고 시트에서는 원래 키워드를 사용해줘. 날짜가 비었거나 해석할 수 없거나 예상 경로가 없거나 조사 기록이 다른 행을 가리키면 프로젝트의 날짜 폴더를 제한 탐색해줘. `웹조사/research.json`, 조사 manifest, 기존 배정 기록이나 `웹조사/evidence/naver-state.json`에서 탭·행·키워드를 대조하고, 구형 폴더는 폴더명과 조사 문서의 주제를 확인해줘. 근거가 일치하는 유일한 폴더를 사용하고 확정할 수 없는 행은 보류해줘.
- `publish/`에서 `{탭}_{키워드}_네이버블로그.md`와 선택 파일 `{탭}_{키워드}_네이버블로그_제목 및 이미지 배치.txt`를 확인해줘. 실제 파일명 접두어에는 확정한 키워드 폴더명을 사용해줘. 제목·배치 TXT가 없으면 `_네이버블로그_제목해시태그.txt`를 참고하고, 둘 다 없으면 키워드를 포함한 제목과 원고에 맞는 배치를 정해줘. MD와 TXT의 채택 이미지 순서·캡션을 확인하고 `publish/`에 없는 이미지는 같은 키워드의 상위 `웹조사/`에서 정확한 파일명으로 찾아줘. 원본 MD·TXT·이미지를 보존하고 원고나 채택 이미지를 확보하지 못한 행은 필요한 파일과 재개 지점을 남겨줘.
- 직접 캡처한 화면과 가림·자르기·표식 편집본을 채택된 순서와 캡션대로 업로드해줘. 재사용 또는 편집 허용 근거가 확인되지 않았다는 이유만으로 이미지를 자동 제외하거나 슬롯을 삭제하지 말아줘. 실제 파일·화면 내용·개인정보 가림·가독성과 원고의 일치는 확인해줘.
- 게시할 본문과 캡션, 제목·이미지 배치 TXT와 새로 가공하는 이미지에는 이미지 이용 제한에 관한 문구를 추가하지 말아줘. 출처와 확인일, 이전 버전 화면이라는 사실 등 내용을 이해하는 데 필요한 정보는 유지해줘.
- 같은 행 H의 실제 애드센스 링크를 읽어 원고의 CTA 바로 다음 URL과 대조해줘. H가 비어 있으면 대응이 확인된 MD의 CTA에서 하나로 일치하는 HTTP(S) URL을 사용하고 근거를 남겨줘. H와 CTA가 다르면 시트 행과 원고를 다시 확인해줘. 차이가 남거나 URL을 확정할 수 없는 행은 보류하고 확인된 행을 계속 처리해줘. 확정 URL을 `promotionUrl`과 현황 시트 F에 사용해줘.
- F가 실제 공란인 행은 현황 E/H/계정 열과 `naver-state.json`을 대조해 신규 발행 후보를 추려줘. F=`ㅇ`이거나 동일 글의 공개·예약 근거가 있으면 실제 결과를 확인해 필요한 시트 기록만 복구해줘. F에 다른 값이나 수식이 있거나 기존 글의 결과를 확정할 수 없으면 값을 보존하고 해당 행의 사유를 남겨줘. 이미 소유한 동일 글의 체크포인트가 있으면 그 글에서 이어가줘.
- 조회 시각, 문서·탭 ID, 팝업 순서와 섹션, 탭·행·키워드, 확인한 셀, 원고 상대경로, 삽입 URL의 출처와 배정·복구·보류 사유를 실행 기록에 남겨줘. 조회와 대조는 읽기 작업으로 하고 목록을 보존한 뒤 조회용 Space를 정리해줘. 기존 실행 재개는 저장된 배정·Space ID·글의 체크포인트 또는 공개 URL을 대조해 남은 단계부터 진행해줘.

## 3. 계정 배정과 병렬 진행

| ego 프로필 이름 | 네이버 ID |
|---|---|
| 박상민 | chocolateelf |
| 상민-서브계정2 | almawade1 |
| 상민-투넘버 | qta14 |
| 순분 | supportimes001 |

- 조정자는 섹션 전체의 신규 발행 대상을 모아 네 프로필 순서를 한 번 무작위로 섞고 라운드로빈으로 균등 배정해줘. 4개 이하는 모두 다른 계정, 그 이상이면 계정 간 건수 차이가 최대 1이 되게 해줘. 같은 키워드는 하나의 작업으로 확정하고, 전체 배정표와 계정별 `indexOnProfile`·예정 시각을 저장해 재시도에 재사용해줘. 각 행의 신규 편집 전에 워크플로의 로컬 claim을 확보해줘.
- 섹션이 여러 개면 섹션 수만큼 실제 Codex 새 채팅을 같은 프로젝트에 만들어 한 섹션씩 배정해줘. 키워드마다 별도 ego-browser TaskSpace를 만들고 각 채팅에서 최대 3개 Space를 동시에 진행해줘. 전체 목표는 활성 채팅별 Space 수의 합이며, 예를 들어 4개 채팅에 각 3개 키워드가 준비되면 총 12개 Space를 목표로 해줘. 전체 채팅을 합쳐 3개로 제한하지 말고 실제 브라우저·계정 슬롯과 시스템 자원을 확인해줘. 인증·시트 확인 대기 Space도 실제 슬롯에 포함하고, 한도에 도달하면 가능한 행부터 진행해 슬롯이 비는 즉시 다음 행을 시작해줘. 새 채팅 생성이 지원되지 않으면 조정자 채팅에서 지원되는 범위의 독립 Space로 이어가고 실제 제약을 알려줘. 이 요청으로 필요한 복수 TaskSpace 생성을 허용해.
- 작업자는 `profiles()`의 실제 이름과 ID를 확인해 배정 프로필로 Space를 만들고 네이버 화면의 로그인 ID와 블로그 주소를 대조해줘. 신규 편집 전에 해당 블로그의 공개 글을 대조해 중복을 확인해줘. 다른 페이지에 있으면 미저장 내용을 보존한 뒤 같은 Space에서 `https://www.naver.com/` 또는 `https://blog.naver.com/{배정된_네이버ID}`로 이동해줘. 로그인·추가 인증·사용자 제어는 같은 Space에서 처리해줘. 진행과 재개 안내에는 탭·실제 행 번호와 Space 번호를 함께 적어줘.
- 예약 시각은 네이버 ID마다(ego 프로필별로) 모든 섹션의 배정 행을 모아 각각 독립적으로 계산해줘. 각 계정의 최신 공개 일반 글을 한 번 확인해 그 계정 첫 글의 즉시 발행 또는 예약을 정하고, 다음 행은 **같은 계정**의 앞 행 예상·예정 시각+2시간으로 미리 배정해줘. 다른 계정의 글과 시각은 기준이나 대기 조건에 넣지 말고, 계정이 다르면 같은 시각에 예약해도 돼. 공지글은 제외하고 상대 날짜는 관찰 KST 시각과 함께 기록해줘. 기본은 해당 계정 최신 공개 일반 글+2시간이 지났으면 즉시, 남았으면 예약이야. 따로 발행 간격을 지정하면 그 지시를 우선해줘. 예약은 UI 분 간격으로 올림하고, 기존 예약 목록 조회 없이 진행해줘. 제출 전 계정별 예정 시각표를 저장·공유하고 지연으로 시각이 지난 슬롯은 해당 계정의 미제출분만 조정해줘.
- 같은 계정에 배정된 행도 각자 작성·검수·제출·결과 확인을 독립적으로 진행해줘. 계정 내 순번은 예정 시각 배정에만 사용해줘. 공용 클립보드·파일 선택·캡처는 모든 참여 채팅이 같은 프로젝트의 `tools/naver_editor.mjs` `withEditorLease`로 해당 짧은 편집 배치만 직렬화해줘. 다른 도구나 프로젝트가 같은 잠금을 쓰지 않으면 별도 공용 조정 또는 시간 분리를 적용해줘. 다른 행의 장애가 생겨도 독립적으로 진행 가능한 행을 이어가줘.

## 4. 스마트에디터 입력과 발행

- `tools/naver_workflow.py`의 파일·해시·이미지 매핑, 균등 배정, 시각 계산, 시트 계획과 `tools/naver_editor.mjs`의 검증된 편집 helper를 재사용해줘. `https://blog-editor.supportimes.com/`에서 원고를 변환하고 HTML 복사·저장 결과로 리치 텍스트를 준비해줘. 변환용 복사본에서 이미지 위치만 표식으로 바꾸고 CTA 다음의 실제 URL은 변환 완료까지 유지해줘. 변환 결과에서 URL 위치를 분리하고 CTA `#fff8b2` 배경, `#1b1bf8` 글자, 19px, 700과 일반 문장 굵기 400을 확인해줘.
- 빈 스마트에디터의 굵기 버튼을 직접 해제하고 실제 해제 상태를 확인한 뒤 본문 전체를 한 번에 리치 붙여넣어줘. 유일한 표식 문단을 찾아 이미지와 링크로 교체해줘. 사진 버튼 클릭 전에 chooser 대기를 등록하고 한 장씩 업로드 완료·로드·순서를 확인해줘. 이미지 설명(캡션)은 글에서 실제 삽입된 순서대로 `1.원래 설명`, `2.원래 설명` 형식으로 앞에 번호를 넣고, 기존 순번은 중복하지 말아줘. 원본 파일을 보존하며 실행용 이미지 계획과 chunk의 캡션을 번호 포함 문구로 맞추고, 이미지를 선택한 뒤 캡션 p의 번호·내용을 대조해줘. CTA 표 직후 문단에 plain URL을 붙여넣고 Enter로 카드를 생성해줘. 썸네일과 링크가 확인되면 raw URL 문장과 빈 문단만 지워 표에 카드를 바로 붙여줘.
- 삽입한 이미지 중 글 주제에 적합하고 작은 썸네일에서도 잘 보이는 사진 한 장을 골라 스마트에디터에서 클릭한 뒤 이미지 왼쪽 상단의 대표 이미지 지정 컨트롤과 현재 상태를 확인해줘. 이미 그 사진이 대표이면 그대로 두고 아니면 지정해줘. 실제 지정 상태와 선택한 파일·순번을 확인·기록하고, 제출 전과 저장된 예약 글 또는 공개 글에서 확인 가능한 범위까지 다시 검수해줘. 컨트롤이나 지정 상태를 확인할 수 없으면 성공으로 간주하지 말고 같은 글과 재개 지점을 보존해줘.
- 적절한 카테고리와 TXT 태그를 적용하고, 맞는 카테고리가 없으면 첫 ‘유용정보’를 선택해줘. 제출 직전 해당 행과 계정을 다시 확인하고 제목·본문·표·번호·이미지·캡션·CTA·카드, 보통체 문장과 잔여 표식을 워크플로 6절 기준으로 검수해줘. 해당 행에 배정한 즉시/예약 설정으로 제출하고 공개 페이지 또는 저장된 예약 글에서 실제 결과와 서식을 검증해줘. 예약은 제목·계정·확정 KST 시각을 확인하고 공개 검수 상태와 구분해줘.
- 같은 Space가 블로그 상단메뉴 설정 등 다른 화면이면 기존 내용을 보존한 뒤 해당 계정의 `https://blog.naver.com/{네이버ID}/`로 돌아가 글쓰기를 열어줘. `작성 중인 글이 있습니다`가 나타나면 확인을 선택하고 복구된 제목·내용을 확인해줘. 진행 글과 다르면 기존 내용을 보존한 뒤 임시저장 또는 예약 목록에서 해당 제목을 선택하고, 현재 글 임시저장 후 불러오기 확인창은 확인을 선택해줘. 대상 제목이 없는 신규 작업은 기존 글을 저장하고 `더보기 → 새 글쓰기`의 빈 편집기에서 작성해줘. 이미 제출한 글은 목록에 제목이 없더라도 공개·예약 결과를 먼저 확인하고 결과가 불확실하면 재제출하지 말아줘. 다른 초안을 덮어쓰거나 삭제하지 말아줘.
- 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 사용해줘. 작업 기록 폴더에 저장하고 캡처 폴더의 `research.json`이 없으면 `{}`로 초기화해줘. 캡처나 편집이 실패하면 같은 Space와 기존 작업을 보존하고 마지막 성공 단계부터 필요한 동작만 복구해줘. 검증을 위해 전체 원고·HTML·시트 snapshot을 반복 출력하지 말아줘.

## 5. 두 시트 반영과 결과 보고

- 공개 URL 또는 확정 예약 시각과 계정을 `웹조사/evidence/naver-state.json`에 먼저 기록해줘. 조정자 한 명이 쓰기 직전에 실제 키워드·F와 현황 시트의 E열 마지막 데이터·대상 셀을 다시 확인해줘.
- [네이버블로그 현황](https://docs.google.com/spreadsheets/d/1YVfd6VIEEZCbAjNw-n3Cre6UrcrIIo28XQlZd1Sv3yI/edit)의 `네이버블로그 현황` 탭에서 E열 마지막 데이터 다음 행에 A=KST 발행일 또는 예정일, D=콘텐츠표 탭, E=키워드, F=삽입 URL, H=실제 네이버 공개 URL 또는 `YYYY년 MM월 DD일 HH시 MM분 예약발행`을 적어줘. I=almawade1, J=qta14, K=supportimes001, L=chocolateelf 중 해당 열에만 `홍보성`을 써줘. 이어 콘텐츠표의 해당 행 F에 한글 `ㅇ`를 쓰고 두 시트를 재조회해줘. 기존 값·수식·다른 계정 열과 서식을 보존해줘. 시트 반영만 실패하면 같은 글과 원래 발행 시각의 근거로 해당 시트만 복구해줘.
- 팝업 전체 행·탭 수, 섹션별 배정·보류 수, 실제 채팅과 Space 수·최대 동시 실행 수를 알려줘. 행별 탭·실제 행·키워드, 원고 경로, 계정, 공개/예약 상태와 KST 시각, 확인된 공개 링크, 두 시트의 재조회 결과를 표로 정리해줘. 보류·실패 행에는 사유와 재개 지점을 적어줘.
- 확인을 마친 글의 claim과 Space를 각각 한 번 정리하고, 오류·인증·사용자 제어 대기 중인 Space는 보존해줘. 최종 완료 또는 중단 시 워크플로 9절의 Windows 알림을 실행해줘. 새로 확인한 실행 방식이나 오류가 있으면 가이드와 필요한 프롬프트에 반영하고 세부 기록은 `guidelines/archive/`에 남겨줘.
