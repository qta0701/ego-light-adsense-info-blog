전달한 키워드가 있는 지정한 행만 처리하고 전체 행 탐색은 생략해줘.
ego-lite에서 키워드마다 개별 Space를 만들고 동시 3개씩 병렬 탐색해줘.
한 메인 키워드에 예를들어 카카오톡 예약메세지 확인 보내는법 상대방 표시 처럼, 여러개의 서브키워드 같은 질문이 섞였으면 검색어를 2개로 나눠서 같은 Space에서 각각 검색해줘. 이때 폴더를 나누지 말고, 기존 경로에 같이 조사한 파일을 저장해줘.(.md나 이미지 등)
Google 검색으로 의도를 확인한 뒤 광고를 제외하고 공식 출처 중심으로 조사해줘. 만약 탐색한 페이지가 키워드와 관련 없을 경우, 다른 검색결과 혹은 키워드로 추가로 조사해줘. (공식 가이드 문서, 가이드 페이지 등을 추가로 탐색해도 좋음) 키워드에 구애 받지 말고 해당 의도에 대한 답을 찾는 느낌으로 자율적으로 조사해줘.
검색어별로 실제 열 공식 결과 링크를 Google 결과 화면에서 빨간 표식으로 표시해줘.
준비·캡처·편집·검증은 tools/research_pipeline.py와 tools/research_browser.mjs를 활용하고,
검색 의도·사실 판단·본문 작성·이미지 시각 검수는 에이전트가 담당해줘.
ego-browser에서 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용해줘. 이 함수가 최소화된 같은 창을 자동으로 복원한 뒤 캡처해. 복원이나 캡처에 실패하면 해당 Space와 기존 작업 상태를 보존하고 오류와 재개 지점을 기록해줘.

-추천 분량 및 수집 갯수: 키워드당 웹조사결과 분량 2,000~4,500자 내외(복합 의도는 최대 7,500자), 출처 1~2개(공식 포함. 각 출처별 url, 탐색 과정에서 정보가 있던 url링크들도 포함),
검색 결과 이미지 검색어당 1장, 단계 안내 4~8장, 참고 이미지 0~3장으로 만들어줘.
발행용·원본은 기본 최대 12장, 복합 의도로 필수 경로가 더 필요하면
사유를 기록하고 각각 최대 14장까지 허용해줘. 
-제시한 분량이나 갯수는 절대적인 건 아니고, 키워드 주제에 부합하는 유의미한 콘텐츠 발행이 가능할 정도의 분량과 이미지 갯수가 되었다면 완료처리 되게 해줘.(제한 갯수나 분량은 상황에 따라 유동적으로 조정)

빨간 화살표·네모 테두리·번호는 캡쳐한 이미지에 있는 실제 요소보다 좀 더 큰 넉넉한 사이즈(네모 테두리 등)로 굵게 표시해줘.
로그인·가입·설치가 필요하면 해당 화면까지만 조사해줘.

오늘 한국 날짜의 YY_MMDD/{탭}_{키워드}/웹조사/에 raw/evidence/publish로 저장하고,
publish에 블로그 작성용 Markdown과 번호·빨간 표식·설명이 있는 이미지를 함께 저장해줘.(이미지에 url은 포함하지 않음)
기존 결과가 있으면 덮어쓰지 말고 상태를 확인해 재개해줘.

키워드별 파일·이미지 검수 후에만 지정 행 A열을 오늘 날짜값(yyyy-mm-dd 표시),
C열을 한글 ㅇ로 업데이트해줘. 쓰기 직전 빈 셀 여부와 키워드를 확인하고
이미 채워진 셀은 덮어쓰지 말아줘. 반영 후 재조회해줘.
완료 경로, 실제 이미지 수, 조사 한계와 시트 반영 결과를 간단히 테이블 등으로 알려줘. 완료처리에 실패한 키워드가 있다면 미완료 사유와 함께 알려줘.

그리고 만약 Google의 배율과 캡처 도구의 좌표 기준이 맞지 않아 빨간 표식을 정확히 검증하지 못할 경우, Google의 배율에 대응하여, 캡쳐 도구가 유동적으로 대응하도록 처리해줘. 예를들어 캡처 도구가 실제 화면 크기와 배율을 읽고, PNG 크기에 맞춰 표식 좌표를 변환하도록 수정하겠습니다. 배율 차이와 실제 창 크기 변경도 구분해서 검사하는 식으로 말이야.

- 빨간표식을 넣지 못할 경우에도, *_웹조사결과.md와 캡쳐 이미지, 다운로드 이미지 등은 로컬에 저장되게 해줘.

참고로 *_웹조사결과.md에 각 캡쳐한 이미지나 다운로드한 이미지마다 대한 파일명과 배치 순서, 이미지에서 설명하고자 하는 것(무엇에 대한 이미지인지. 즉 이 이미지가 뭔지 설명), 출처, 해당 url 등 콘텐츠에 활용할 정보가 포함되게 해줘.

-만약 사용자가 첨부한 키워드 리스트에서 섹션이 여러개로 구분되어 있는데, 병렬 스레드로 진행이 안된다면(즉 해당 프로젝트에서 섹션별 독립 채팅 n개 실행하는 식), 작업을 진행하지 말고 사용자에게 알려줘.

- 요청이 미완료된 키워드에 대해서, 미완료 사유를 고려하여 너가 능동적으로 사고하고 탐색해서 가능한 자료와 이미지를 모아서 작업을 완료해줘. 다른 검색어로 시도한다던지, 다른 검색엔진(네이버 등)으로 찾아본다던지, 키워드를 바꿔본다던지 등으로,

메인키워드와 관련하여 큰 주제는 같되(예를들어 키워드가 넷플릭스 한국영화 추천이었는데 이전에 미완료 되었다면, 넷플릭스에 있는 작품 추천이라는 큰 주제는 유지하고 꼭 한국영화가 아니라 다른 카테고리나 방식으로 변경하거나, 혹은 한국영화 카테고리를 확인하는 방법으로 pivoting 하는 식), 너가 완료할 수 있을 법한 세부키워드로 변경해서 조사를 진행해주고, 구글시트의 키워드가 있는 해당 탭의 아마도 I열(메인 키워드 이름의 헤더열이 있는 열)에 해당 키워드가 있는 행에 입력된 키워드도 너가 찾은 키워드로 변경해서 작업이 완료되면 완료 처리 해줘.

즉 너가 탐색하다가 얻게된 정보들로 할 수 있을법한 키워드로 조정해줘.

만약 키워드가 추가 된다면, 구글시트에도 반영해줘. I열(메인 키워드)에 데이터가 있는 가장 마지막 행 이후에 신규 키워드 추가. 조사 및 자료 수집 완료후에는 A열(블로그 업로드 날짜)과 c열(상위노출 블로그 수집여부) 업데이트 되게끔 말이야.
