# Google Sheets Blogger 미작성 조회부터 공개 발행까지

현재 프로젝트의 `guidelines/`에 `.md` 파일이 있는지 확인해줘. 없으면 프로젝트 경로 확인이 필요하다고 알려줘. `.antigravity/rules.md`, `guidelines/BLOGGER_UPLOAD_WORKFLOW.md`의 0~5절·7~9절, `guidelines/CHROME_AGENTS_USAGE_GUIDE.md`, `guidelines/크롬에이전트_활용법.md`, `guidelines/AGENT_DESKTOP_GUIDE.md`의 관련 지침을 적용해줘. 이미지 인계는 `블로그작성_가이드라인/html-content-guide.md` 0절과 `블로그작성_가이드라인/html-style-guide.md`의 슬롯 규칙을 따라줘.

`전체 시트 blogger 미작성 목록` 팝업에서 `📋 전체 기본 복사`로 확보한 **모든 탭·실제 행 번호·메인 키워드**를 Blogger 작업 목록으로 삼아줘. 별도 최대 건수를 지정하면 팝업 순서대로 그 범위만 진행해줘. 시트와 로컬 원고를 대조하고 채택 이미지의 실제 업로드를 완료한 행은 초안으로 저장한 뒤 같은 글을 공개 발행해줘. 초안 저장만 요청한 경우에는 이미지와 저장값 확인 후 G열 재조회까지 진행해줘.

## 1. 시트 팝업에서 대상 가져오기

1. 설치된 `ego-browser skill`을 끝까지 읽고 공개 SDK를 사용해줘. `순분`(`name=순분`, `profileId=Profile 2`) 프로필의 조회용 TaskSpace에서 [1.애드센스 키워드표](https://docs.google.com/spreadsheets/d/1KAnq9pvZ7VYFJOAQ_25cM8EjaDFUX5Z6x9jfCCtTf7s/edit?usp=sharing)를 열고 URL의 문서 ID를 확인해줘.
2. 상단 `🔍 키워드 조회` → `5️⃣ blogger 미작성 전체 시트 조회 (팝업)`을 실행하고 `전체 시트 blogger 미작성 목록`이 열릴 때까지 기다려줘. 결과 없음, 실행 오류, 로그인·권한 요구를 구분해줘. 사용자 조작이 필요하면 같은 Space에서 제어를 넘기고 확인 후 재개해줘.
3. `📋 전체 기본 복사`를 눌러 전체 목록을 가져와줘. 분할 복사를 별도로 요청한 경우에는 해당 탭의 분할 수를 정한 뒤 `📑 연달아 분리된 섹션 전체 복사`를 사용해줘. 복사 결과를 직접 확인해줘. 중첩 iframe에서 버튼 조작이 실패하거나 클립보드를 확인할 수 없으면 `guidelines/웹자료수집.md` 8절의 방식대로 팝업 snapshot 또는 iframe subtree의 요약과 섹션 텍스트박스를 읽어줘. 복사를 확인하기 위해 시트에 붙여넣지 마.
4. 탭 이름·실제 시트 행 번호·메인 키워드를 `{tab, row, keyword}`로 정리해줘. `No.` 열은 실제 행 번호로 쓰지 마. 팝업 순서와 섹션 경계를 유지하고 전체 행 수·탭 수와 섹션별 건수를 대조해줘. 같은 탭·행의 중복, 키워드 충돌, 탭 누락 또는 건수 불일치가 있으면 해당 목록을 다시 확인해줘. 팝업에 0건이 표시되면 조회 결과만 알려줘.

## 2. 실제 행과 로컬 인계 파일 확인

- 조정자 한 명이 연결된 Sheets 도구로 문서 메타데이터, 해당 탭의 `sheetId`, 헤더와 후보 행만 읽어줘. `블로그 업로드 날짜`, `메인 키워드`, `애드센스 임시저장 여부`, `애드센스 포스팅 링크`, `애드센스 포스팅 작성일`을 헤더명으로 찾아줘(현재 참고 A·I·G·H·L). 팝업의 탭·행·키워드를 현재 시트와 대조하고, 다시 조회해도 일치하지 않는 행은 사유를 남겨줘.
- `블로그 업로드 날짜`를 `YY_MMDD`로 변환해 프로젝트의 `YY_MMDD/{탭}_{메인 키워드}/`를 먼저 확인해줘. 예를 들어 `2026-11-06`의 `앱사용` 탭 `당근마켓 채팅 걸기`는 `26_1106/앱사용_당근마켓 채팅 걸기/`야. 경로에는 기존 폴더명 정규화 규칙을 적용하고 시트 대조에는 원래 키워드를 사용해줘. 날짜가 비었거나 해석할 수 없거나, 예상 폴더가 없거나 조사 기록이 다른 행을 가리키면 프로젝트의 날짜 폴더에서 같은 이름을 찾아줘. `웹조사/research.json`, 기존 배정 기록·manifest, `blogger-state.json` 또는 조사 문서로 대응을 확인해줘. 경로를 확정할 수 없는 행은 보류하고 확인된 행은 계속 처리해줘.
- `웹조사/publish/`의 HTML/TXT와 관련 조사 문서를 확인해줘. `tools/blogger_workflow.py scan`으로 유일한 정상 HTML/TXT 쌍을 확인하고 TXT의 원래 채택 이미지 수·순서·경로·IMG ID를 HTML 슬롯 및 실제 파일과 대조해 기록해줘. 각 이미지의 파일과 준비 상태는 워크플로 1.2절에 따라 확인하고 파일 누락·중복·미해결 슬롯의 자료와 재개 지점을 남겨줘.
- `preflight`로 최신 G/H/L을 확인해줘. **G/H/L이 모두 실제 공란이면 신규 업로드 후보(`eligible_new`)로 배정해줘.** 워크플로 4.1절에 따라 Blogger에 기존 글이 없는 행의 새 글을 생성해줘. 수식 결과 공란·공백·FALSE·0은 값으로 취급해줘. 기존 초안은 명시적 재개 요청에 따라 같은 글에서 이어가고, 이미 공개된 같은 글을 발견하면 URL과 원래 발행 시각을 확인해 누락된 시트 기록만 복구해줘.
- B 실행 기록에 조회 시각, 팝업 순서·섹션, `spreadsheetId`·`sheetId`·탭·실제 행·키워드, 시트 값, 로컬 상대경로와 배정·보류 사유를 남겨줘. 목록 확보 후 조회용 Space를 정리해줘.
- 워크플로 4.2절에 따라 기본은 키워드별 독립 채팅을 생성하되, 별도로 채팅당 키워드 수를 지정하면 그 묶음을 우선해줘. 어떤 묶음이든 키워드마다 TaskSpace 1개를 배정하고, 준비된 행이 3개 이상이면 허용된 최대 3개 Space를 함께 시작해줘. 인증·시트 확인 대기를 포함해 동시 활성 채팅과 Space는 각각 최대 3개야. 슬롯이 비면 남은 활성 Space를 확인해 다음 행을 시작하고, 한 행이 보류돼도 독립적으로 처리 가능한 행은 계속해줘. 재개 요청은 기존 배정·Space·글 ID를 대조해줘. 환경에서 채팅 생성이 지원되지 않으면 조정자 채팅에서 사용 가능한 독립 Space로 계속 진행하고 실제 제한과 동시 실행 수를 남겨줘.

## 3. Blogger 업로드·저장·공개 발행

- 원래 채택된 **모든 이미지 슬롯을 업로드하는 것을 목표**로 해줘. 글 생성 전에 워크플로 1.2절에 따라 이미지마다 파일·출처·가림과 편집 내역을 확인해줘. 파일이 없거나 화면이 맞지 않으면 같은 키워드의 관련 이미지 또는 적합한 자체 제작 설명 이미지로 원래 슬롯의 의미와 위치를 유지해줘. 실제 화면이 아닌 도식·생성 이미지는 그렇게 밝혀줘. 원고의 채택 수가 0이면 관련 있는 발행용 이미지 1개 이상을 준비해줘.
- 원본 또는 적합한 대체 이미지를 끝내 확보하지 못한 행은 IMG ID별 시도·사유·재개 지점을 기록해 보류하고 다른 행은 진행해줘. 내가 이미지 일부 또는 전체가 없는 발행을 명시적으로 허용하지 않는 한 슬롯을 삭제하거나 이미지 0개로 완료하지 말아줘. 이미 초안이 만들어졌다면 같은 postId와 기존 업로드 URL을 보존하되 미완성 상태에서 G 완료 표시나 공개 발행은 하지 말아줘. 원본 HTML/TXT와 이미지는 B 실행 디렉터리에 보존하고 대체 파일·출처·순서·매핑을 발행본에 갱신해줘.
- 조정자가 stage B claim을 확보한 뒤 작업 채팅에 넘겨줘. 작업 채팅은 워크플로 2절의 탭별 Blogger URL에 접속하고, 새 글 생성과 발행 직전에는 조정자의 시트 재확인을 받아줘. 새 `postId`는 이미지 업로드 전에, 각 실제 이미지 URL은 다음 이미지 업로드 전에 `blogger-state.json`에 저장해줘. 확정한 TXT의 채택 이미지를 같은 글에 순서대로 업로드해 실제 URL로 HTML 토큰을 치환하고, 확인된 기존 업로드 URL은 재사용해줘.
- 신규 원고의 제목·검색 설명·사용 가능한 맞춤 퍼머링크·라벨에는 TXT의 최종 추천값을 적용해줘. 비어 있는 항목은 본문과 키워드에 근거해 입력 제한에 맞게 채우고 채택값을 TXT와 상태에 남겨줘. `맞춤 퍼머링크` 라디오를 선택해 활성 입력란에 값을 넣고 통합 저장 확인에서 유지 여부를 확인해줘. 기능이 없거나 값이 유지되지 않으면 자동 주소로 발행해줘. 사용자가 주소를 필수 조건으로 지정한 경우에는 발행 전에 그 조건을 확인해줘.
- 신규 초안은 본문과 메타를 함께 저장하고 같은 편집기에 한 번 재진입해 저장값·모든 대상 이미지의 URL·개수·순서·alt·캡션·잔여 토큰을 확인해줘. 원래 채택 수와 원본 사용·대체·명시적 제외 수를 대조하고, 내가 해당 제외나 이미지 없는 발행을 명시적으로 허용하지 않았다면 대상 이미지가 빠졌거나 업로드 0개인 행은 G 완료 처리하지 말아줘. 검증된 초안 저장을 로컬에 기록한 뒤 G에 한글 `ㅇ`를 쓰고 재조회해줘. PC·모바일 미리보기와 화면 캡처는 별도 요청, 새 레이아웃·이미지 편집 또는 관찰된 오류가 있을 때 해당 부분만 확인해줘.
- 화면 캡처가 필요하면 현재 TaskSpace의 Page에서 `tools/research_browser.mjs`의 `capture()`를 우선 사용해줘. 이 함수가 캡처 전에 창 상태를 확인하고 최소화된 같은 창을 자동으로 복원해. 업로드 검증용 캡처는 B 실행 디렉터리의 별도 폴더에 저장하고, 해당 폴더에 `research.json`이 없으면 `{}`로 초기화해줘. 복원이나 캡처에 실패하면 해당 Space와 기존 업로드 상태를 보존하고 오류와 재개 지점을 기록해줘.
- 같은 `blogId`의 게시 요청은 여러 채팅과 Space에 걸쳐 직렬화하고, 앞선 글의 실제 보기 URL과 공개 페이지 제목·canonical·발행 시각을 확인한 뒤 다음 글을 게시해줘. 이미지 업로드와 초안 준비는 병렬로 진행해줘. 같은 글을 공개 발행하고 Blogger 목록의 `보기` 링크로 실제 공개 페이지를 열어 제목·canonical·대상 이미지 전체의 순서와 로딩·메타·발행 시각을 확인해줘. 다른 글과 URL이 같거나 제목이 다르면 H/L에 기록하지 말고 같은 postId와 증거를 보존해 충돌을 처리해줘. 공개 글을 초안으로 되돌려 재발행해야 할 경우에는 영향과 시각 변경 가능성을 알려 내 승인을 받아줘. URL과 발행 시각을 로컬에 먼저 저장해줘. 쓰기 직전에 대상 행과 셀을 다시 확인하고 H에 실제 공개 URL, L에 실제 발행 시각의 KST 날짜·시간 일련값과 DATE_TIME 형식을 같은 `batchUpdate`로 반영해줘. 기존 시트 시간대를 유지하고 적용된 셀을 재조회해줘. 시트 반영만 실패하면 같은 글 ID·URL·원래 발행 시각으로 시트만 복구해줘.
- 파일 검사·잠금·열 판정·시트 계획·시간 변환은 `tools/blogger_workflow.py`를 재사용해줘. 새 원고나 별도 업로드 스크립트 작성은 생략하되, 1.2절의 이미지 확인·적절한 대체 제작과 슬롯 보완은 수행해줘. 조정자 한 명이 시트 쓰기 직전에 행·키워드·대상 셀을 확인하고 G/H/L의 빈 셀에만 반영해줘. 기존 완료값·다른 값·수식은 보존해줘. 완료된 HTML/TXT와 상태를 정리하고 claim 해제와 Space 종료는 각각 한 번만 수행해줘.

## 4. 완료 보고

실제 채팅·Space ID와 시작·종료 시각을 B 실행 기록에 남겨줘. 팝업 전체 행 수·탭 수, 섹션별 배정 건수와 채팅·Space 각각의 최대 동시 실행 수를 알려줘. 행별로 탭·행·키워드, 초안/공개 상태, 실제 공개 URL, **원래 채택 수와 실제 업로드·제외·대체 이미지 수**, G/H/L 재조회 결과를 표로 정리해줘. IMG ID별 근거·대체·실패, 행의 제외·보류는 사유와 재개 지점을 포함해줘. 최종 표의 URL과 시각은 시트 및 공개 페이지 확인값과 대조해줘.
